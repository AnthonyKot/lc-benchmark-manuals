Problem Statement

You are given an integer array nums with distinct elements.

A subarray nums[l...r] is a bowl if it has length at least 3 and the smaller of the two endpoint values is strictly greater than every value between them:

r - l + 1 >= 3
min(nums[l], nums[r]) > max(nums[l + 1], ..., nums[r - 1])

Return the number of bowl subarrays. Constraints: 3 <= nums.length <= 100000, 1 <= nums[i] <= 1000000000, and all elements are distinct.

Problem Essence

The middle of a valid bowl must be entirely lower than both endpoints. Because all values are distinct, the lower endpoint is the limiting endpoint. If the right endpoint is higher than the left endpoint, then the left endpoint must have its first greater element to the right exactly at that right endpoint. If a greater element appeared earlier inside the subarray, it would break the bowl condition. The symmetric statement holds when the left endpoint is higher.

So the problem reduces to counting nearest-greater pairs whose indices are at least two apart: previous greater pairs and next greater pairs.

Worked Example

For nums = [2,5,3,1,4], the answer is 2.

CandidateReasonCounted by
[3,1,4]min(3,4)=3 and the only middle value is 1.4 is the next greater element to the right of 3, distance 2.
[5,3,1,4]min(5,4)=4, and max(3,1)=3.5 is the previous greater element to the left of 4, distance 3.

No other endpoint pair has all interior values below the lower endpoint while also having length at least 3.

Decision Rule / Algorithm

  1. Use a decreasing monotonic stack to compute pge[i], the nearest index left of i with nums[pge[i]] > nums[i], or -1 if none exists.
  2. Use a decreasing monotonic stack to compute nge[i], the nearest index right of i with nums[nge[i]] > nums[i], or n if none exists.
  3. For every index i, count (pge[i], i) if pge[i] != -1 and i - pge[i] >= 2.
  4. For every index i, count (i, nge[i]) if nge[i] != n and nge[i] - i >= 2.

Why this is exact: if nums[l] < nums[r], the bowl condition says every element between l and r is less than nums[l], so r is the first greater element to the right of l. If nums[l] > nums[r], then l is the first greater element to the left of r. Distinct values prevent equality cases.

Time complexity is O(n). Space complexity is O(n) for explicit previous/next arrays, or O(n) with a smaller constant for the one-pass stack variant.

Implementation Skeleton

long bowlSubarrays(int[] nums) {
    int n = nums.length;
    int[] pge = new int[n];
    int[] nge = new int[n];
    fill(pge, -1);
    fill(nge, n);

    stack = empty decreasing stack of indices;
    for i in 0..n-1:
        while stack not empty and nums[stack.top] < nums[i]:
            stack.pop()
        if stack not empty:
            pge[i] = stack.top
        stack.push(i)

    clear stack
    for i in 0..n-1:
        while stack not empty and nums[stack.top] < nums[i]:
            nge[stack.pop()] = i
        stack.push(i)

    ans = 0
    for i in 0..n-1:
        if pge[i] != -1 and i - pge[i] >= 2:
            ans += 1
        if nge[i] != n and nge[i] - i >= 2:
            ans += 1
    return ans
}

A compact one-pass form is also accepted: scan left to right with a decreasing stack of values or indices; whenever a smaller stack top is popped by the current value, count it if a greater left boundary remains. Also count the current top as the previous greater boundary when the distance condition is satisfied. The explicit two-array version is easier to audit.

Reimplementation Checklist

  • Use strict < in stack popping because the input values are distinct.
  • Count only distances of at least 2 between endpoints, since length must be at least 3.
  • Return a 64-bit integer type where the language distinguishes integer widths. The answer is at most linear here, but LeetCode signatures use long/int64 for several languages.
  • Do not compute interior maxima for each pair; that becomes too slow.
  • Do not count arbitrary greater elements. Only the nearest greater relation is valid.
  • Initialize missing previous greater as -1 and missing next greater as n.

Wrong But Tempting

  • Checking all subarrays with a running maximum: still O(n^2) in the worst case and fails the 100000 length constraint.
  • Counting every pair of endpoints taller than the middle minimum: the condition is about the maximum interior value, not local neighbors.
  • Using any greater element instead of nearest greater: if a greater element appears before the endpoint, it lies inside the proposed subarray and invalidates it.
  • Forgetting the length test: adjacent greater pairs are not bowls because there is no interior element and the required length is at least 3.
  • Adding equality handling from generic monotonic-stack templates: equality cannot occur under the constraints, and loose comparisons can accidentally change which endpoint is considered nearest.
