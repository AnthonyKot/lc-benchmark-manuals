Problem Statement

You are given an integer array nums of length n and an integer k. Choose a subsequence with indices 0 <= i1 < i2 < ... < im < n such that consecutive chosen indices are at least k apart: i(t+1) - i(t) >= k.

The chosen values must be strictly alternating: either nums[i1] < nums[i2] > nums[i3] < ... or nums[i1] > nums[i2] < nums[i3] > .... A subsequence of length 1 is valid. Return the maximum possible sum of selected values.

Constraints: 1 <= n <= 100000, 1 <= nums[i] <= 100000, and 1 <= k <= n.

Problem Essence

For every index i, the last comparison into i is either upward, meaning the previous selected value is smaller than nums[i], or downward, meaning the previous selected value is larger. The distance rule means index i may only extend subsequences ending at indices j <= i-k.

The core task is therefore repeated range maximum queries by value: among eligible previous indices, find the best downward-ending score with value less than the current value, and the best upward-ending score with value greater than the current value.

Worked Example

For nums = [5,4,2] and k = 2, the answer is 7.

  1. At index 0, value 5 can stand alone, so both state interpretations can contribute score 5.
  2. At index 1, no earlier index is at distance at least 2, so value 4 can only stand alone.
  3. At index 2, index 0 becomes eligible because 2 - 0 = 2. Since 5 > 2, the subsequence [5, 2] is a valid downward step and has score 5 + 2 = 7.

The best score is 7, using indices [0, 2].

Decision Rule / Algorithm

Maintain two DP values for each index:

  • up[i]: best sum of a valid subsequence ending at i whose last move is upward, so the previous value is < nums[i].
  • down[i]: best sum ending at i whose last move is downward, so the previous value is > nums[i].

Before computing states for index i, insert index i-k into query structures. This single delayed insertion makes every stored state distance-valid for the current and future indices.

up[i]   = nums[i] + max(0, best down[j] where j <= i-k and nums[j] < nums[i])
down[i] = nums[i] + max(0, best up[j]   where j <= i-k and nums[j] > nums[i])
answer = max(answer, up[i], down[i])

Use two Fenwick trees or segment trees that store maximum DP score by value. One tree queries values smaller than the current value directly. The other handles values greater than the current value either with a reversed coordinate or with a suffix-query segment tree.

Implementation Skeleton

function maxAlternatingSum(nums, k):
    n = len(nums)
    values = coordinate_compress(nums)  // or use max(nums) because nums[i] <= 100000
    lessTree = FenwickMax(size(values))       // stores down[j] by nums[j]
    greaterTree = FenwickMax(size(values))    // stores up[j] by reversed nums[j]
    up = array of length n
    down = array of length n
    ans = 0

    for i in 0 .. n-1:
        if i >= k:
            j = i - k
            p = rank(nums[j])
            lessTree.update(p, down[j])
            greaterTree.update(reverse(p), up[j])

        p = rank(nums[i])
        bestSmallerDown = lessTree.query(p - 1)
        up[i] = nums[i] + max(0, bestSmallerDown)

        bestLargerUp = greaterTree.query(reverse(p) - 1)
        down[i] = nums[i] + max(0, bestLargerUp)

        ans = max(ans, up[i], down[i])

    return ans

If the tree uses -infinity for empty ranges, convert an empty result to 0 so a single element remains valid.

Reimplementation Checklist

  • Use 64-bit integer return storage: maximum score can exceed 32-bit signed range.
  • Insert only index i-k before processing i; after that, the tree contains exactly all indices <= i-k.
  • Use strict value inequalities: smaller query is < current, larger query is > current. Equal values cannot extend the alternating sequence.
  • Allow length-1 subsequences by initializing each state from the current value or by adding max(0, query).
  • For greater-than queries with a Fenwick prefix tree, reverse the compressed index.
  • Return the maximum over both states at every index, not just the final index.

Wrong But Tempting

  • Using ordinary alternating-subsequence DP without the distance delay. It will illegally chain adjacent elements when k > 1.
  • Using non-strict comparisons. Equal neighboring selected values are not alternating.
  • Keeping only one best previous score. The direction of the last move matters because the next move must reverse direction.
  • Trying O(nk) or scanning all earlier eligible positions for each index. With n = 100000, that is too slow.
  • Using 32-bit int for scores in Java/C++/Go/Rust. The selected sum can be around 1e10.

Fenwick max tree over raw value range Several Python, Java, C++, and JavaScript solutions use value indices up to max(nums), maintaining one tree for smaller values and one reversed tree for larger values. O(n log V) time, O(n + V) memory, where V <= 100000.
Fenwick max tree with coordinate compression Go, JavaScript, TypeScript, Rust, and some Python-style solutions compress the distinct values first, then use prefix maxima on compressed ranks. O(n log m) time, O(n + m) memory, where m is the number of distinct values.
Segment tree range maximum The official hints name segment tree; it is equivalent here to Fenwick max because all queries are value prefixes or suffixes. O(n log V) or O(n log m) time.
