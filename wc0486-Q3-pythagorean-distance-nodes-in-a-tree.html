Problem Statement

You are given an undirected tree with n nodes numbered from 0 to n - 1, represented by edges. You are also given three distinct target nodes x, y, and z.

For every node u, compute its distances to the three targets: dx = dist(u, x), dy = dist(u, y), and dz = dist(u, z). A node is special when these three distances, sorted in ascending order as a, b, c, satisfy a*a + b*b == c*c.

Return the number of special nodes. The tree has 4 <= n <= 100000, edges.length == n - 1, and the input is guaranteed to be a valid tree.

Problem Essence

The tree property guarantees exactly one simple path between any two nodes, so unweighted BFS from a target gives the distance from that target to every node in linear time. The problem is therefore not about path search per node; it is about reusing three global distance arrays.

The key observation is that only three sources matter. Run BFS from x, from y, and from z. Then each node can be checked independently in constant time.

Worked Example

For n = 4, edges = [[0,1],[0,2],[0,3]], x = 1, y = 2, z = 3, the tree is a star centered at node 0.

NodeDistances to x,y,zSortedSpecial?
01, 1, 11, 1, 1No: 1 + 1 != 1
10, 2, 20, 2, 2Yes: 0*0 + 2*2 == 2*2
22, 0, 20, 2, 2Yes
32, 2, 00, 2, 2Yes

The answer is 3.

Decision Rule / Algorithm

  1. Build an adjacency list for the undirected tree.
  2. Run BFS from x to get dx, from y to get dy, and from z to get dz.
  3. For each node i, sort the three values [dx[i], dy[i], dz[i]].
  4. Increment the answer if a*a + b*b == c*c.

Complexity: building the graph is O(n), the three BFS traversals are O(n), and the final scan is O(n). Memory is O(n) for adjacency and three distance arrays.

Implementation Skeleton

from collections import deque

class Solution:
    def specialNodes(self, n, edges, x, y, z):
        graph = [[] for _ in range(n)]
        for a, b in edges:
            graph[a].append(b)
            graph[b].append(a)

        def bfs(src):
            dist = [-1] * n
            dist[src] = 0
            q = deque([src])
            while q:
                u = q.popleft()
                for v in graph[u]:
                    if dist[v] == -1:
                        dist[v] = dist[u] + 1
                        q.append(v)
            return dist

        dx = bfs(x)
        dy = bfs(y)
        dz = bfs(z)

        ans = 0
        for i in range(n):
            a, b, c = sorted((dx[i], dy[i], dz[i]))
            if a * a + b * b == c * c:
                ans += 1
        return ans

Reimplementation Checklist

  • Use zero-based node ids exactly as given by the constraints.
  • Add each edge in both directions.
  • Initialize the source distance to 0, not 1.
  • Run three traversals, not one traversal and not a BFS per candidate node.
  • Sort the three distances or check all three possible hypotenuse choices.
  • Use integer arithmetic. The largest distance is below 100000, so squares fit in 32-bit signed int, but wider integers are harmless in C++/Java.
  • Return the count of nodes, not the list of nodes.

Wrong But Tempting

  • Running shortest paths from every node: this becomes O(n^2) and is unnecessary.
  • Checking only dx*dx + dy*dy == dz*dz: the largest distance may be any of the three values, so sort first or test all permutations.
  • Rejecting zeros: the official examples count triples such as 0, 2, 2 and 0, 1, 1 as valid because 0^2 + a^2 = a^2.
  • Using DFS recursion in Python on a path-shaped tree: recursion depth can exceed the default limit for n = 100000. BFS with a deque avoids that risk.
  • Assuming weighted or one-based input: the stated problem is an unweighted zero-based tree.

Accepted Algorithm Families

All accepted files follow the same core family: linear graph construction, three complete tree traversals from the target nodes, and a final linear Pythagorean count. Most submissions use BFS queues; some Java variants use iterative DFS-style stack traversal, which is equivalent on an unweighted tree because each node is reached once along the unique tree path.
