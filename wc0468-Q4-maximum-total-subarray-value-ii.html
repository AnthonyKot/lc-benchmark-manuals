Problem Statement

You are given an integer array nums of length n and an integer k. Select exactly k distinct non-empty subarrays nums[l..r]. Subarrays may overlap, but the same pair (l, r) cannot be selected twice.

The value of a subarray is max(nums[l..r]) - min(nums[l..r]). Return the maximum possible sum of values over the selected k subarrays.

  • 1 <= n == nums.length <= 5 * 10^4
  • 0 <= nums[i] <= 10^9
  • 1 <= k <= min(10^5, n * (n + 1) / 2)

Problem Essence

Every subarray has a score equal to its internal range. The task is to find the top k scores among all O(n^2) subarrays without enumerating them all.

For a fixed left endpoint l, extending the right endpoint can only keep or increase max - min. Therefore the candidates for one fixed l form a sorted stream when scanned from r = n - 1 down to l: v(l,n-1), v(l,n-2), ... is non-increasing. The official solution merges these n sorted streams with a max-heap.

Decision Rule / Algorithm

Primary official heap/RMQ rule

  1. Build sparse tables for range maximum and range minimum. Then value(l,r) is answered in O(1).
  2. For every left index l, push the largest stream item (value(l,n-1), l, n-1) into a max-heap.
  3. Repeat k times: pop the current largest item, add its value, and if r > l, push (value(l,r-1), l, r-1).
  4. The monotonicity for fixed l makes this a correct k-way merge of the best remaining candidates.

Complexity: sparse table build O(n log n) memory and time, then O((n + k) log n) heap work with O(1) range queries.

Implementation Skeleton

function maxTotalValue(nums, k):
    n = len(nums)
    build log table
    build sparseMax[level][i] and sparseMin[level][i]

    value(l, r):
        len = r - l + 1
        j = log[len]
        mx = max(sparseMax[j][l], sparseMax[j][r - 2^j + 1])
        mn = min(sparseMin[j][l], sparseMin[j][r - 2^j + 1])
        return mx - mn

    heap = max-heap
    for l in 0..n-1:
        push (value(l, n-1), l, n-1)

    ans = 0
    repeat k times:
        val, l, r = pop max
        ans += val
        if r > l:
            push (value(l, r-1), l, r-1)

    return ans

Reimplementation Checklist

  • Use 64-bit arithmetic for the answer: k can be 10^5 and each value can approach 10^9.
  • Use two sparse tables or an equivalent RMQ structure for max and min.
  • Initialize one heap entry per left endpoint, not one entry per subarray.
  • After popping (l,r), only push (l,r-1) for the same l in the official stream-merge solution.
  • Implement the heap as a max-heap directly or negate values in languages with min-heaps.
  • Verify the sparse-table query uses the two overlapping intervals ending at r: [l, l+2^j-1] and [r-2^j+1, r].

Wrong But Tempting

  • Enumerating all subarrays and sorting them is O(n^2 log n), which is impossible for n = 5 * 10^4.
  • Choosing only globally longest subarrays is not valid; a shorter subarray may expose a larger local max-min gap.
  • Using a visited set with both shrink-left and shrink-right transitions can work for top-k state search, but it is more complex and easier to over-generate than the official one-stream-per-left merge.
  • Using 32-bit integers for the accumulated answer can overflow even though each individual subarray value fits in 32 bits.
  • Assuming distinct values are required is wrong. The subarrays must be distinct; equal scores from different subarrays all count.

Failure Patterns From Stats

  • Keep preprocessing near O(n log n).
  • Keep candidate extraction near O(k log n).
  • Do not scan all right endpoints for every left endpoint during extraction.
