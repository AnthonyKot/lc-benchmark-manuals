Problem Statement

You are given a positive integer k. Find the smallest positive integer n divisible by k whose decimal representation contains only digit 1, such as 1, 11, 111, and so on.

Return the number of digits in that smallest valid n. If no such number exists, return -1.

Constraint: 2 <= k <= 100000.

Problem Essence

The actual number can be enormous, so never build it as an integer or string and then divide it. Track only the remainder of the growing all-ones number modulo k.

Appending one digit 1 to the right changes the remainder by:

new_remainder = (old_remainder * 10 + 1) % k

If this remainder becomes 0, the current length is the answer. If k is divisible by 2 or 5, no all-ones decimal can be divisible by k, because every all-ones number is odd and ends in 1.

Worked Example

For k = 7, update the remainder one appended digit at a time:

LengthNumber shapeRemainder modulo 7
111
211(1 * 10 + 1) % 7 = 4
3111(4 * 10 + 1) % 7 = 6
41111(6 * 10 + 1) % 7 = 5
511111(5 * 10 + 1) % 7 = 2
6111111(2 * 10 + 1) % 7 = 0

The first zero remainder occurs at length 6, so return 6.

Other Official Examples

Decision Rule / Algorithm

  1. If k % 2 == 0 or k % 5 == 0, return -1.
  2. Set remainder = 0.
  3. For length from 1 through k, update remainder = (remainder * 10 + 1) % k.
  4. If remainder == 0, return length.
  5. If the loop finishes, return -1.
Why k iterations are enough: there are only k possible remainders. If no zero remainder appears after checking k generated remainders, the process has entered a cycle without reaching divisibility.

Implementation Skeleton

class Solution:
    def minAllOneMultiple(self, k: int) -> int:
        if k % 2 == 0 or k % 5 == 0:
            return -1

        remainder = 0
        for length in range(1, k + 1):
            remainder = (remainder * 10 + 1) % k
            if remainder == 0:
                return length

        return -1

The same structure ports directly to Java, C++, Go, Rust, JavaScript, and TypeScript because all arithmetic stays within small integer bounds. With k <= 100000, remainder * 10 + 1 is below about 1000001 before the modulo.

Reimplementation Checklist

  • Reject multiples of 2 or 5 before the loop.
  • Start with remainder = 0 and append one virtual digit per iteration.
  • Loop at most k times, or use a visited set to detect repeated remainders.
  • Return the length immediately when the remainder becomes 0.
  • Do not construct the full all-ones number.
  • Do not use floating point, logarithms, or decimal conversion.

Wrong But Tempting

  • Building 1, 11, 111 as real integers. This grows exponentially in digit count and can overflow or become very slow.
  • Returning -1 only after an arbitrary large limit. The rigorous bound is k remainders, or an explicit repeated-remainder check.
  • Checking only k % 2 == 0. Multiples of 5 are also impossible because all candidates end in 1.
  • Starting the count at zero but updating from remainder = 1 % k without adjusting the returned length. This creates an off-by-one risk.
  • Using 9 * k as the loop limit. It can still pass, as one accepted C++ submission does, but it is looser than necessary and obscures the pigeonhole argument.

Accepted Algorithm Families

FamilyPattern in accepted filesNotes
Bounded remainder loop Most Java, JavaScript, Rust, Go, C++, TypeScript, and Python submissions use for length in 1..=k with remainder = (remainder * 10 + 1) % k. This is the cleanest approach: O(k) time and O(1) extra memory.
Visited remainder cycle check Several Python and JavaScript submissions keep a set of seen remainders and stop if one repeats. Also correct, but uses O(k) memory. It mirrors the official hint exactly.
Early impossibility by factors Accepted submissions consistently short-circuit when k is divisible by 2 or 5. This is not only an optimization; it is a simple mathematical decision rule.
