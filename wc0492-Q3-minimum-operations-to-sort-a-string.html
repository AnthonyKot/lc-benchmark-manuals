Problem Statement

You are given a string s consisting of lowercase English letters.

In one operation, you may select any non-empty substring of s that is not the entire string and sort that substring in non-descending alphabetical order.

Return the minimum number of operations needed to make the whole string sorted in non-descending order. If no sequence of allowed operations can do it, return -1.

Constraints: 1 <= s.length <= 100000; s contains only lowercase English letters.

Problem Essence

The operation can only sort a proper substring, never the whole string. That single restriction is the source of the edge cases. Since sorting a substring only permutes characters inside that interval, the final sorted string is always the globally sorted multiset of the original characters.

The accepted solutions do not simulate operations. They classify the answer into one of 0, 1, 2, 3, or -1 using boundary characters and the global minimum/maximum characters.

Worked Example

s = "card"

  1. The string is not already sorted.
  2. It has length greater than 2, so it is not the special impossible unsorted two-character case.
  3. The global minimum is a; it appears before the last index. This makes a two-operation construction possible.
  4. One valid sequence is to sort "car" into "acr", producing "acrd", then sort "rd" into "dr", producing "acdr".

The answer is 2.

Decision Rule / Algorithm

  1. If s is already non-descending, return 0.
  2. If len(s) == 2, return -1. At this point it is an unsorted two-character string, and the only proper substrings have length one.
  3. Let mn be the minimum character and mx be the maximum character.
  4. If s[0] == mn or s[n - 1] == mx, return 1. A proper suffix or prefix can be sorted while the already-correct boundary character remains outside the operation.
  5. If mn appears anywhere in s[0:n-1] or mx appears anywhere in s[1:n], return 2.
  6. Otherwise return 3.

Equivalent accepted implementations sometimes detect the one-operation case by comparing s with sorted(s) and checking whether the mismatching interval is a proper substring. This is correct but costs O(n log n) unless counting sort is used. The boundary rule above is the direct O(n) form.

Implementation Skeleton

class Solution:
    def minOperations(self, s: str) -> int:
        n = len(s)

        if all(s[i - 1] <= s[i] for i in range(1, n)):
            return 0

        if n == 2:
            return -1

        mn = min(s)
        mx = max(s)

        if s[0] == mn or s[-1] == mx:
            return 1

        if mn in s[:-1] or mx in s[1:]:
            return 2

        return 3

For Java, JavaScript, Rust, C++, or Go, use one pass to test sortedness and collect mn/mx, then one more pass or built-in index search for the prefix/suffix membership checks.

Reimplementation Checklist

  • Check already sorted before any impossible-case logic; strings of length 1 and sorted length-2 strings return 0.
  • Return -1 only for unsorted strings of length 2.
  • Use character comparisons, not numeric distance between letters.
  • For answer 1, test the boundary positions: first character is global minimum or last character is global maximum.
  • For answer 2, test whether a global minimum is not confined to the final position or a global maximum is not confined to the first position.
  • Do not build or search all substrings; the answer is determined by global extremal characters.
  • Keep memory O(1) aside from the input in languages where strings are directly indexable.

Wrong But Tempting

  • Sorting the whole string as one operation: invalid because the chosen substring cannot be the entire string.
  • Returning -1 for every reversed-looking string: only unsorted length-2 strings are impossible. For example, length-3+ cases can still need 2 or 3 operations.
  • Counting inversions or adjacent swaps: operations sort arbitrary proper substrings, so inversion count is not the objective.
  • Assuming answer is at most 2: accepted solutions include a real 3 branch when the only global minimum is at the end and the only global maximum is at the start.
  • Checking only distinct min/max positions after sorting: duplicate minimum or maximum characters matter because any occurrence in the proper prefix/suffix can enable the two-operation branch.

Accepted Algorithm Families

Direct Linear Classifier

Used by Java and JavaScript accepted submissions. It checks sortedness, length-2 impossibility, global min/max, then prefix/suffix occurrence. Runtime is O(n), memory is O(1).

Sorted-Copy Mismatch Classifier

Used by several Python and Rust submissions. It creates sorted(s), checks whether the mismatch interval is proper for answer 1, then falls back to min/max occurrence logic. Runtime is usually O(n log n), memory O(n), but still passes at n = 100000.

Hybrid Hint Implementation

Some submissions mirror the official hints exactly: already sorted, boundary min/max for one operation, unsorted length-2 impossibility, then two or three operations based on extremal-character placement.
