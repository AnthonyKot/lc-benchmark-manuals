Problem Statement

Given an integer array nums, a non-empty subarray is called good if the bitwise OR of all elements in that subarray is equal to at least one element present in that same subarray. Return the number of good subarrays.

Constraints: 1 <= nums.length <= 10^5 and 0 <= nums[i] <= 10^9.

Problem Essence

A subarray's OR contains every bit that appears anywhere in the subarray. If that OR is equal to an element inside the subarray, that element must contain all bits used by every other element. Equivalently, a subarray is good if its bitwise OR equals its maximum-capability element under bit containment. The official hint phrases this as OR equals the subarray's maximum element, because any element missing a bit from the OR cannot be the OR value.

The core task is to count, for each possible owner element nums[i], how far left and right a subarray can extend while no element introduces a bit absent from nums[i]. Equal values must be de-duplicated so the same good subarray is counted once.

Decision Rule / Algorithm

Use the bit-containment rule: a subarray owned by index i is valid only if every included number has no bit outside nums[i].

  1. Sweep left to right. For each index i, compute left_bad[i], the nearest index to the left containing at least one bit that is not set in nums[i]. Maintain last_pos[bit] for the most recent set bit position.
  2. Sweep right to left. Compute right_bad[i], the nearest index to the right containing a bit absent from nums[i]. Maintain next_pos[bit].
  3. Track prev_same[i], the previous occurrence of nums[i]. Count each good subarray by its first occurrence of the OR value, so the effective left blocker is max(left_bad[i], prev_same[i]).
  4. Contribution of index i: (i - max(left_bad[i], prev_same[i])) * (right_bad[i] - i). Sum this in 64-bit arithmetic.

With values below 10^9, 30 bits are sufficient; many accepted submissions scan 31 bits to be conservative. Complexity is O(n * B), where B is 30 or 31, and memory is O(n + B).

Implementation Skeleton

def countGoodSubarrays(nums):
    n = len(nums)
    B = 31

    left_bad = [-1] * n
    last = [-1] * B
    for i, x in enumerate(nums):
        blocker = -1
        for b in range(B):
            if (x >> b) & 1 == 0:
                blocker = max(blocker, last[b])
        left_bad[i] = blocker
        for b in range(B):
            if (x >> b) & 1:
                last[b] = i

    right_bad = [n] * n
    nxt = [n] * B
    for i in range(n - 1, -1, -1):
        x = nums[i]
        blocker = n
        for b in range(B):
            if (x >> b) & 1 == 0:
                blocker = min(blocker, nxt[b])
        right_bad[i] = blocker
        for b in range(B):
            if (x >> b) & 1:
                nxt[b] = i

    ans = 0
    prev = {}
    for i, x in enumerate(nums):
        p = prev.get(x, -1)
        left_blocker = max(left_bad[i], p)
        ans += (i - left_blocker) * (right_bad[i] - i)
        prev[x] = i
    return ans

Reimplementation Checklist

  • Use a 64-bit return accumulator; the answer can be n * (n + 1) / 2.
  • Scan all relevant bits, normally 0 through 30 exclusive for < 10^9, or 0 through 31 exclusive for safety.
  • For an owner value x, blockers come from bits where x has 0, not bits where x has 1.
  • Left blockers use the maximum previous bad position; right blockers use the minimum next bad position.
  • Handle duplicates by requiring the owner index to be the first selected occurrence of that OR value: start must be after the previous same value.
  • Return the count, not the count modulo anything.

Wrong But Tempting

  • Counting only subarrays where OR equals the numerical maximum without checking duplicate ownership. This double-counts ranges containing repeated copies of the OR value.
  • Sliding window with a single OR value. Bitwise OR is monotonic when extending but not invertible when moving the left edge, so a naive two-pointer window loses information.
  • Enumerating all subarrays. O(n^2) is too slow for n = 100000.
  • Using 32-bit integer for the answer. The all-good case reaches 5,000,050,000 when n = 100000.
