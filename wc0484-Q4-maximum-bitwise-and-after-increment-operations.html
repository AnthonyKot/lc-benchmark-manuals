Problem Statement

You are given an integer array nums and integers k and m. You may perform at most k operations, where one operation increments any one array element by 1. After these increments, choose any subset of exactly m elements and maximize the bitwise AND of those chosen values.

Constraints: 1 <= nums.length <= 5 * 10^4, 1 <= nums[i] <= 10^9, 1 <= k <= 10^9, and 1 <= m <= nums.length.

Problem Essence

The selected m values must all contain every bit that appears in the final AND. For a candidate mask x, each array value has a minimum increment cost to reach some value y >= num with (y & x) == x. Candidate x is feasible if the sum of the smallest m such costs is at most k.

The key property is monotonicity by required bits: if a mask is feasible, you can greedily try to add higher bits first and keep them only when the feasibility check passes.

Worked Example

For nums = [3, 1, 2], k = 8, m = 2, the best answer is 6 (110b).

  1. Try to make two numbers contain bits 4 and 2.
  2. 3 can be increased to 6 at cost 3.
  3. 2 can be increased to 6 at cost 4.
  4. The two chosen values become [6, 6], total cost 7 <= 8, and their AND is 6.

Trying to force a larger answer fails because the two cheapest compatible values exceed the budget.

Decision Rule / Algorithm

Use greedy bit construction from bit 30 down to bit 0. Let ans be the mask already accepted. For each bit b, test candidate = ans | (1 << b).

  1. For every num, compute the minimum nonnegative increment needed to reach a value containing all bits of candidate.
  2. Sort the costs or otherwise select the smallest m.
  3. If their sum is at most k, accept the bit by setting ans = candidate.
  4. Return ans.
The cost formula used by accepted solutions: if (num & mask) == mask, cost is 0. Otherwise let missing = mask & ~num and let h be the highest set bit in missing. The minimal compatible value preserves bits above h, raises bit h, and sets required lower mask bits: value = (num & ~((1 << (h + 1)) - 1)) | (1 << h) | (mask & ((1 << h) - 1)). Cost is value - num.

Complexity is typically O(31 * n log n) from sorting costs for each tested bit, which fits n = 5 * 10^4. Partial selection can reduce constants but is not required by the accepted table.

Implementation Skeleton

def maximumAND(nums, k, m):
    ans = 0

    def cost_to_satisfy(num, mask):
        if (num & mask) == mask:
            return 0
        missing = mask & ~num
        h = missing.bit_length() - 1
        high = num & ~((1 << (h + 1)) - 1)
        value = high | (1 << h) | (mask & ((1 << h) - 1))
        return value - num

    for bit in range(30, -1, -1):
        candidate = ans | (1 << bit)
        costs = [cost_to_satisfy(x, candidate) for x in nums]
        costs.sort()
        if sum(costs[:m]) <= k:
            ans = candidate

    return ans

Reimplementation Checklist

  • Scan bits from 30 down to 0; nums[i] and k are at most 10^9, so answers fit below 2^31.
  • Use 64-bit arithmetic for shifts, masks, sums, and computed target values in Java, Go, C++, and TypeScript/JavaScript where appropriate.
  • Compute the highest missing required bit, not merely the lowest missing bit.
  • Only sum the cheapest m costs, because the subset can be chosen after increments.
  • Break cost summation early once it exceeds k to save time.
  • Do not mutate nums; each feasibility check is hypothetical.

Wrong But Tempting

  • Binary-searching the numeric answer as if feasibility were monotonic over integers. The Python file accepted__glm-5-cloud-t0.0__python3.py does this successfully with a specialized compatibility cost, but the safer general pattern is bit-greedy because masks, not numeric order alone, express the objective.
  • Forcing every array element to satisfy the candidate mask. Only m chosen elements matter.
  • Using target - num whenever num < target. A larger current value can still miss lower required bits, and a smaller value may need a carry past the highest missing bit.
  • Assuming incrementing to exactly the candidate mask is always possible or optimal. The real target is any value whose required bits are all set.
  • Trying to maximize individual values first. The AND depends on common bits across the selected subset.

Failure Patterns From Stats

The stats file records 4 Wrong Answer submissions and 1 Time Limit Exceeded submission. The likely failure modes, based on the accepted-code patterns, are:

  • Wrong Answer from incorrect cost computation when a carry is needed to set the highest missing required bit.
  • Wrong Answer from checking all elements or a fixed prefix instead of taking the cheapest m costs.
  • Wrong Answer from integer overflow or signed-shift behavior near bit 30.
  • Time Limit Exceeded from nested simulation of individual increment operations or from repeatedly doing heavier-than-sort work inside each bit check.
