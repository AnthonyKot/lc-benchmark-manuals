Problem Statement

You are given lists, a 2D array of non-empty integer arrays. Every inner array is already sorted in non-decreasing order.

Repeatedly choose two different lists a and b, merge them into one sorted list, remove the originals, and insert the merged list. The merge cost is:

len(a) + len(b) + abs(median(a) - median(b))

The median is the middle element of the sorted list; for even length, use the left middle element. Continue until one list remains and return the minimum possible total cost.

Constraints: 2 <= lists.length <= 12, 1 <= lists[i].length <= 500, values are between -10^9 and 10^9, each list is sorted, and the total number of elements is at most 2000.

Problem Essence

This is not a greedy merge problem. Because the median term depends on the exact set of original lists already merged into each side, the state is a subset of original list indices. With at most 12 lists, all subsets are feasible.

Let mask represent a merged group of original lists. Precompute len[mask] and median[mask]. Then solve the optimal binary merge tree with subset DP.

Worked Example

For lists = [[1,3,5],[2,4],[6,7,8]], the output is 18.

  1. Merge [1,3,5] and [2,4]. Length cost is 3 + 2; medians are 3 and 2; merge cost is 3 + 2 + abs(3 - 2) = 6. The merged list is [1,2,3,4,5].
  2. Merge [1,2,3,4,5] and [6,7,8]. Length cost is 5 + 3; medians are 3 and 7; merge cost is 5 + 3 + abs(3 - 7) = 12.
  3. Total: 6 + 12 = 18.

Decision Rule / Algorithm

Use dynamic programming over bitmasks. For any non-singleton mask, split it into two non-empty disjoint submasks sub and other = mask ^ sub. The final merge of those two groups costs:

len[mask] + abs(median[sub] - median[other])

Since len[mask] = len[sub] + len[other], this is exactly the statement's length term plus the median distance. The recurrence is:

dp[1 << i] = 0
dp[mask] = min over proper non-empty submasks:
           dp[sub] + dp[mask ^ sub]
           + len[mask]
           + abs(median[sub] - median[mask ^ sub])

To avoid evaluating both (sub, other) and (other, sub), either require sub < other or force one fixed bit of mask into sub.

Implementation Skeleton

def minMergeCost(lists):
    n = len(lists)
    N = 1 << n

    len_mask = [0] * N
    median = [0] * N

    # Precompute len_mask[mask].
    for mask in range(1, N):
        lsb = mask & -mask
        i = lsb.bit_length() - 1
        len_mask[mask] = len_mask[mask ^ lsb] + len(lists[i])

    # Precompute median[mask] by one accepted family:
    # 1. merge sorted arrays for each mask, or
    # 2. coordinate-compress values and binary-search the k-th element, or
    # 3. binary-search value range with upper_bound/countLE on each list.

    INF = 10**30
    dp = [INF] * N
    for i in range(n):
        dp[1 << i] = 0

    for mask in range(1, N):
        if mask & (mask - 1) == 0:
            continue
        sub = (mask - 1) & mask
        while sub:
            other = mask ^ sub
            if sub < other:
                dp[mask] = min(
                    dp[mask],
                    dp[sub] + dp[other] + len_mask[mask]
                    + abs(median[sub] - median[other])
                )
            sub = (sub - 1) & mask

    return dp[N - 1]

Reimplementation Checklist

  • Use 64-bit integers for the answer and DP values in Java, C++, Go, Rust, C#, and similar languages.
  • Represent each group by a bitmask over original list indices; do not mutate the input list collection during DP.
  • For median index, use left middle: zero-based index (total_length - 1) // 2, or one-based rank (total_length + 1) // 2.
  • Precompute every median[mask] before DP transitions.
  • Initialize singleton masks to cost 0; no merge is needed for one list.
  • When enumerating submasks, skip empty and full submasks and avoid double-counting symmetric splits.
  • Return dp[(1 << n) - 1].

Wrong But Tempting

  • Huffman-style greedy by shortest length: the median distance can dominate and invalidate a length-only priority queue.
  • Greedy by closest medians: the length term is paid repeatedly depending on tree shape, so local median closeness is not enough.
  • Using average for even lengths: the statement requires the left middle element, not the arithmetic average.
  • Using only current list medians without subset state: the median of a merged group depends on all values in that subset.
  • Simulating one arbitrary merge order: the answer asks for the minimum over all binary merge trees.

Failure Patterns From Stats

stats.json records two failed submissions, both with status Time Limit Exceeded. The likely failure modes for this problem are repeated median recomputation during every DP transition, physically merging lists inside the transition loop, or evaluating all symmetric submask splits without pruning in a slower language.

The DP has around 3^n split work before symmetry pruning. With n = 12, that is feasible, but only if median and length lookups are already precomputed.
