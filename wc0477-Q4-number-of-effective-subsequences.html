Problem Statement

Given an integer array nums, define the strength of an array as the bitwise OR of all its elements. A nonempty subsequence is effective if removing that subsequence strictly decreases the strength of the remaining elements. The OR of an empty array is 0. Return the number of effective subsequences modulo 1_000_000_007.

Constraints: 1 <= nums.length <= 100000, 1 <= nums[i] <= 1000000. Since 1000000 < 2^20, only 20 bit positions can matter.

Problem Essence

Removing a subsequence is the same as choosing the complementary subset that remains. Removal is effective exactly when the remaining subset has OR strictly smaller than the total OR of all numbers.

Answer = all choices of remaining elements minus choices whose OR is exactly the original total OR.

The empty removed subsequence is not counted as effective because leaving all elements keeps the same OR. The formula above naturally excludes it: the full remaining set is one of the subsets whose OR equals the total OR.

Worked Example

For nums = [1,2,3], the total OR is 3, using bits 01 and 10.

Remaining subsetRemaining ORRemoved subsequenceEffective?

[1,2]3[3]No

There are 8 remaining-subset choices, 5 of them keep OR 3, so the answer is 8 - 5 = 3.

Decision Rule / Algorithm

  1. Compute total_or across nums.
  2. Collect only the bit positions present in total_or. Let their count be k, where k <= 20.
  3. Compress every number into a k-bit mask and count frequencies freq[mask].
  4. Run SOS DP so cnt[mask] becomes the number of elements whose compressed mask is a submask of mask.
  5. For any allowed bit mask mask, the number of remaining subsets whose OR is contained inside mask is 2^cnt[mask].
  6. Use inclusion-exclusion to count remaining subsets whose OR is exactly the full mask (1 << k) - 1.
  7. Return 2^n - exact_full_or modulo 1_000_000_007.

Equivalent accepted formulations sum over missing-bit sets instead. If T is a nonempty set of total-OR bits that must disappear from the remaining subset, count remaining elements using only the complement bits and alternate signs by |T|.

Implementation Skeleton

MOD = 1_000_000_007
n = len(nums)
total_or = OR of every x in nums
bits = [b for b in 0..19 if total_or has bit b]
k = len(bits)
limit = 1 << k

freq = [0] * limit
for x in nums:
    mask = compressed mask of x using bits[]
    freq[mask] += 1

cnt = freq copy
for i in 0..k-1:
    for mask in 0..limit-1:
        if mask has bit i:
            cnt[mask] += cnt[mask ^ (1 << i)]

pow2[0] = 1
for i in 1..n:
    pow2[i] = 2 * pow2[i - 1] mod MOD

exact_full_or = 0
full = limit - 1
for mask in 0..full:
    term = pow2[cnt[mask]]
    missing = k - popcount(mask)
    if missing is even:
        exact_full_or += term
    else:
        exact_full_or -= term

return (pow2[n] - exact_full_or) mod MOD

Reimplementation Checklist

  • Use long, int64, or language-safe modular arithmetic for products and signed inclusion-exclusion terms.
  • Compress to the bits present in total_or; this keeps arrays at size at most 2^20.
  • Precompute pow2 up to n; each remaining subset choice is independent by index.
  • After subtraction, normalize with (value % MOD + MOD) % MOD or equivalent.
  • Remember that subsequences are index-distinct. Two equal values in different positions create different removal choices.
  • Do not separately remove the empty subsequence. It is already among the non-effective cases because the remaining OR is unchanged.

Wrong But Tempting

  • Counting value-distinct subsequences instead of index-distinct subsequences. Example [2,2,1] requires counting two different [2,1] removals.
  • Trying to greedily remove one number that owns a rare bit. A bit can occur in many elements, and all occurrences of a bit must be absent from the remaining subset before that bit disappears.
  • Checking every subsequence directly. 2^100000 is impossible.
  • Using only the count of total-OR bits per number. The identity of the bits matters for inclusion-exclusion.
  • Forgetting that the remaining array may be empty, whose OR is defined as 0.

Failure Patterns From Stats

The failed-submission summary contains Time Limit Exceeded: 2. That points to solutions that likely enumerated subsequences, repeatedly recomputed ORs, or used a state space larger than the 20-bit mask universe.

  • Any approach worse than roughly O(n*20 + 20*2^20) is risky under n = 100000.
  • Nested loops over all pairs or all subsets of indices will time out.
  • Memoizing by index and OR can still be too large if it degenerates toward n*2^20; accepted solutions aggregate counts first and run SOS once.
