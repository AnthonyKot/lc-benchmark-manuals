Problem Statement

You are given an integer array nums of length n. An integer k is called sortable if k divides n and the array can be sorted into non-decreasing order after this operation:

  • Partition nums into consecutive non-empty subarrays of length k.
  • Cyclically rotate each subarray independently any number of times left or right.

Return the sum of all sortable integers k.

Constraints: 1 <= n == nums.length <= 100000, 1 <= nums[i] <= 100000.

Problem Essence

The block boundaries are fixed for a chosen divisor k. Rotations cannot move an element from one block to another, so each original block must become exactly the corresponding block of the globally sorted array after some cyclic shift.

There are two equivalent ways to test this:

  • Official rotation-match view: sort a copy s. For every block [i, i+k), verify that s[i..i+k-1] occurs inside two concatenated copies of nums[i..i+k-1].
  • Accepted simplification: every block must be cyclically non-decreasing, meaning at most one descent when including the wrap edge. Also, after each block is rotated into non-decreasing order, the maximum of the previous block cannot exceed the minimum of the current block.

The second test avoids explicitly building the globally sorted array for each candidate and is enough because a cyclically sorted block contributes exactly its sorted multiset, while the block-to-block min/max condition guarantees the concatenation is globally non-decreasing.

Worked Example

For nums = [3,1,2], n = 3 and the divisors are 1 and 3.

  • k = 1: blocks are [3], [1], [2]. Singletons cannot change order, and 3 > 1, so this fails.
  • k = 3: the only block is [3,1,2]. It has one cyclic descent, from 3 to 1, and rotating after that descent gives [1,2,3]. This succeeds.

The sum of sortable divisors is 3.

Decision Rule / Algorithm

  1. Let n = nums.length.
  2. Enumerate all divisors k of n. A non-divisor can never be valid because the partition would not cover the array with equal blocks.
  3. For each block [start, start+k), count descents inside the circular block: adjacent pairs nums[j] > nums[j+1] plus the wrap pair nums[start+k-1] > nums[start].
  4. If any block has more than one circular descent, no rotation can make that block non-decreasing.
  5. Track each block's minimum and maximum. If previousBlockMax > currentBlockMin, the independently sorted blocks cannot concatenate into a globally non-decreasing array.
  6. If all blocks pass, add k to the answer.

Complexity: divisor enumeration gives at most a few hundred candidates for n <= 100000. Scanning all blocks for one divisor costs O(n), so the direct accepted method is O(n * d(n)), where d(n) is the number of divisors. This is comfortably small for the constraint.

Implementation Skeleton

function sortableIntegers(nums):
    n = length(nums)
    ans = 0

    for each divisor k of n:
        ok = true
        prevMax = -infinity

        for start in 0, k, 2k, ... n-k:
            descents = 0
            mn = +infinity
            mx = -infinity

            for offset from 0 to k-1:
                x = nums[start + offset]
                mn = min(mn, x)
                mx = max(mx, x)
                if offset + 1 < k and nums[start + offset] > nums[start + offset + 1]:
                    descents += 1

            if nums[start + k - 1] > nums[start]:
                descents += 1

            if descents > 1 or prevMax > mn:
                ok = false
                break

            prevMax = mx

        if ok:
            ans += k

    return ans

Reimplementation Checklist

  • Only test k values that divide n.
  • Count the wrap descent last > first; omitting this accepts blocks that cannot be rotated into sorted order.
  • Allow equal adjacent values. The comparison is strictly >, not >=.
  • Reset prevMax for every candidate k.
  • Use prevMax > currentMin, not >=, because equal boundary values are allowed in non-decreasing order.
  • Return an integer sum of divisors. With n <= 100000, the answer fits normal 32-bit integer ranges, but wider types are harmless.

Wrong But Tempting

  • Checking each block in isolation only: [2,3][1,4] has individually sorted blocks for k = 2, but the whole result cannot be non-decreasing because 3 > 1.
  • Counting only internal descents: [2,3,1] has one internal descent and is rotatable, while [3,2,1] has two internal descents and is not. The wrap edge still matters for cases such as already sorted blocks.
  • Sorting every block and comparing only multisets: rotations preserve cyclic order, not just values. A block such as [2,1,3] has the right multiset for [1,2,3] but cannot be rotated into it.
  • Treating duplicates as breaks: [2,2,1] rotates to [1,2,2]. Equal values are compatible with non-decreasing order.
