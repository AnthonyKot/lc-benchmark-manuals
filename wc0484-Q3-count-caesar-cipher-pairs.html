Problem Statement

You are given an array words of n lowercase strings. Every string has the same length m. One operation chooses one whole string and shifts every character to the next lowercase letter cyclically, so z becomes a.

Two strings are similar if, after applying this whole-string Caesar shift any number of times to either string, the two strings can become equal. Count pairs of indices (i, j) with i < j such that words[i] and words[j] are similar.

Constraints: 1 <= n == words.length <= 100000, 1 <= m == words[i].length <= 100000, 1 <= n * m <= 100000, and words contain only lowercase English letters.

Problem Essence

A Caesar shift adds the same value modulo 26 to every character in a word. That operation preserves relative structure. Two accepted key styles appeared in the submissions:

  • Normalize each word by shifting its first character to a. Example: layout becomes avqson.
  • Store the modulo-26 differences between adjacent characters. Example: layout has differences [11, 21, 22, 10, 25].

Both keys describe the same equivalence class. Equal keys mean the pair is similar.

Worked Example

For words = ["fusion","layout"], shifting fusion six times gives layout, so the answer is 1.

layoutavqson[15, 24, 16, 6, 25]
The simplest mental model is first-character normalization: subtract the first character from every character modulo 26. For fusion and layout, both normalize to avqson.

Other Official Examples

For words = ["ab","aa","za","aa"], the answer is 2. The similar pairs are ("ab","za") and the two equal "aa" entries.

Decision Rule / Algorithm

  1. For each word, build a hashable canonical key.
  2. For first-character normalization, let base = word[0] - 'a'. For each character c, append (c - 'a' - base + 26) % 26.
  3. Use a hash map from key to frequency.
  4. Either add seen[key] to the answer before incrementing, or count all frequencies and add cnt * (cnt - 1) / 2 for each group.

Time complexity is O(total characters). Extra space is O(total key size) in the worst case.

Implementation Skeleton

class Solution:
    def countPairs(self, words: List[str]) -> int:
        freq = {}
        ans = 0

        for word in words:
            base = ord(word[0]) - ord('a')
            key = tuple((ord(ch) - ord('a') - base) % 26 for ch in word)

            ans += freq.get(key, 0)
            freq[key] = freq.get(key, 0) + 1

        return ans

An equally valid skeleton is to key on adjacent differences:

key = tuple((ord(word[i]) - ord(word[i - 1])) % 26 for i in range(1, len(word)))

If using adjacent differences, every length-one word has the empty key and is therefore similar to every other length-one word.

Reimplementation Checklist

  • Return a 64-bit integer in fixed-width languages. The number of pairs can be about n * (n - 1) / 2.
  • Normalize modulo 26 with a non-negative result.
  • Do not compare every pair. O(n^2 * m) is unnecessary and will time out.
  • Use a compact key: string, byte array converted to string, tuple of small ints, or vector of bytes depending on language.
  • All words share one length by constraint, but the key logic should still handle length one.

Wrong But Tempting

  • Sorting letters: Caesar similarity depends on positions and cyclic offsets, not multiset equality.
  • Checking only first and last characters: all positions must share the same shift.
  • Using raw adjacent differences with the wrong direction in one place and first-character differences elsewhere. Pick one invariant and apply it consistently.
  • Building a key from absolute characters without subtracting a base. That treats ab and za as different, but they are similar.
  • Accumulating the answer in int in Java/C++/Go when n can be 100000.
