Problem Statement

You are given two binary strings s and t, each of length n. You may rearrange the characters of t in any order, but s must remain unchanged.

Return a binary string of length n representing the maximum integer value obtainable by taking the bitwise XOR of s and the rearranged t.

Constraints: 1 <= n == s.length == t.length <= 2 * 10^5, and every character in both strings is either '0' or '1'.

Problem Essence

The output is compared as a binary integer, so the leftmost position has the highest value. At each position, the best possible result bit is 1. Because s is fixed and only the multiset of bits in t matters, a result bit is 1 exactly when we can spend the opposite bit from t.

Greedy is valid because a 1 at an earlier bit is always more valuable than anything that can happen later. If an opposite bit is available now, use it now.

Worked Example

For s = "101", t = "011", the available bits in t are one zero and two ones.

Indexs[i]Preferred bit from tAvailable?Output bitRemaining counts
010yes1zeros 0, ones 2
101yes1zeros 0, ones 1
210no0zeros 0, ones 0

The maximum XOR string is "110".

Other Official Examples

  • s = "0110", t = "1110" gives "1101". One optimal rearrangement of t is "1011".
  • s = "0101", t = "1001" gives "1111". One optimal rearrangement of t is "1010".

Decision Rule / Algorithm

  1. Count zeros = number of '0' in t and ones = number of '1' in t.
  2. Scan s from left to right.
  3. If s[i] == '0', prefer spending a 1 from t. If one is available, output 1; otherwise spend a 0 and output 0.
  4. If s[i] == '1', prefer spending a 0 from t. If one is available, output 1; otherwise spend a 1 and output 0.
  5. Join the output bits.

Time complexity is O(n). Extra space is O(n) for the answer, or O(1) beyond the returned string/buffer.

Implementation Skeleton

class Solution:
    def maximumXor(self, s: str, t: str) -> str:
        zeros = t.count('0')
        ones = len(t) - zeros
        ans = []

        for ch in s:
            if ch == '0':
                if ones > 0:
                    ans.append('1')
                    ones -= 1
                else:
                    ans.append('0')
                    zeros -= 1
            else:
                if zeros > 0:
                    ans.append('1')
                    zeros -= 1
                else:
                    ans.append('0')
                    ones -= 1

        return ''.join(ans)

Reimplementation Checklist

  • Count bits in t, not in s.
  • Build the answer from left to right because the binary string is maximized lexicographically by earliest bits.
  • Append the XOR result bit, not the chosen rearranged bit from t.
  • Decrement exactly one available count for every position.
  • Use a mutable buffer such as a list, byte array, StringBuilder, or Vec<u8>; avoid repeated string concatenation for large n.
  • Return a string of length exactly n.

Wrong But Tempting

  • Sorting s or changing its order. Only t can be rearranged.
  • Trying to construct the lexicographically smallest or largest rearranged t. The objective is the XOR result, not t itself.
  • Using the original positions of t. They do not matter once rearrangement is allowed.
  • Saving opposite bits for later. Earlier result bits dominate later bits, so this loses value when a 1 could be produced now.
  • Returning the chosen bits of t rather than the computed XOR bits.

Accepted Algorithm Families

Direct Count Greedy

All inspected accepted submissions use the same core family: count zeroes and ones in t, then greedily append 1 when an opposite bit is available and 0 otherwise.

Buffer Variants

Languages differ only in storage: Python lists, Java StringBuilder, JavaScript arrays, Go byte slices, Rust String::with_capacity, and C++ strings all implement the same scan.

Equivalent Counting

Some submissions count both 0 and 1; others count only zeros and derive ones as n - zeros. Both are equivalent.
