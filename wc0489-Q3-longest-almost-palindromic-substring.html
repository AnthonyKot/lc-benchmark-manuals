Problem Statement

You are given a lowercase English string s. A nonempty substring is almost-palindromic if it becomes a palindrome after removing exactly one character from it. Return the length of the longest almost-palindromic substring.

Constraints: 2 <= s.length <= 2500, and s contains only lowercase English letters.

Problem Essence

The key observation is that an almost-palindromic substring has at most one "bad" character with respect to palindrome symmetry. Around any final palindrome center, expansion is normal until the first mismatch. At that single mismatch, the removed character must be either the left mismatching character or the right mismatching character. After choosing one of those skips, all remaining outer pairs must match.

A substring that is already a palindrome of length at least 2 also qualifies because deleting an appropriate middle character, or one of the two middle characters for even length, leaves a palindrome.

Worked Example

For s = "abca", choose the whole substring "abca". Comparing ends gives a == a, then the inner pair is b != c. Skip c, leaving "aba", which is a palindrome. The answer is therefore 4.

In center-expansion terms, the core palindrome is around b after the skip, and the one allowed deletion absorbs the adjacent c.

Decision Rule / Algorithm

Recommended rule: for each center, expand while matching. When the first mismatch or boundary is reached, evaluate the candidate that deletes one adjacent character, then continue expansion once for each possible skip direction.

  1. Enumerate all centers: odd centers (i, i) and even centers (i, i + 1).
  2. Expand l and r while s[l] == s[r]. This gives a palindromic core.
  3. The core length itself can update the answer if it is at least 2, because an already-palindromic substring can still lose exactly one middle character.
  4. If l is in bounds, try deleting s[l]: continue with l - 1 and r.
  5. If r is in bounds, try deleting s[r]: continue with l and r + 1.
  6. Update the maximum length from both skip attempts.

There are O(n) centers and each attempt can expand O(n), so the simple editorial solution is O(n^2) time and O(1) extra memory.

Implementation Skeleton

def almostPalindromic(s):
    n = len(s)
    ans = 2

    def expand(l, r):
        nonlocal ans
        core = 0
        while l >= 0 and r < n and s[l] == s[r]:
            core += 2 if l != r else 1
            l -= 1
            r += 1

        ans = max(ans, core)

        if l >= 0:
            a, b, length = l - 1, r, core + 1
            while a >= 0 and b < n and s[a] == s[b]:
                length += 2
                a -= 1
                b += 1
            ans = max(ans, length)

        if r < n:
            a, b, length = l, r + 1, core + 1
            while a >= 0 and b < n and s[a] == s[b]:
                length += 2
                a -= 1
                b += 1
            ans = max(ans, length)

    for i in range(n):
        expand(i, i)       # odd
        expand(i, i + 1)   # even
    return min(ans, n)

When translating this skeleton, be careful with the even-center core length. Some accepted submissions pass len explicitly instead of recomputing it from pointers.

Reimplementation Checklist

  • Handle both odd and even centers.
  • After the first mismatch, test both skip-left and skip-right.
  • Count the deleted character in the substring length.
  • Allow already-palindromic substrings to count because the deletion is performed after selecting the substring.
  • Do not use cubic enumeration of all substrings plus a two-pointer check; n = 2500 makes that too slow.
  • Use byte or character indexing directly; the input is lowercase English letters, so no Unicode grapheme logic is needed.

Wrong But Tempting

Only checking whether the whole string can become a palindrome. The answer is about any substring, not necessarily the full input.

Stopping at the first mismatch without trying both deletions. In cases like "abecbea", the better deletion direction is data-dependent.

Rejecting exact palindromes. "abba" is an official example with answer 4; deleting one middle b leaves "aba".

Counting the palindrome after deletion instead of the original substring. The required return value includes the removed character.
