Problem Statement

You are given two binary strings s and t, both of length n, and three positive integers flipCost, swapCost, and crossCost.

You may apply these operations any number of times:

  • Flip one bit in either string at cost flipCost.
  • Choose two distinct indices and swap two positions within the same string, either in s or in t, at cost swapCost.
  • At one index, swap s[i] with t[i] at cost crossCost.

Return the minimum total cost needed to make s and t equal. Constraints: 1 <= n <= 10^5, costs are between 1 and 10^9, and both strings contain only 0 and 1.

Problem Essence

Only mismatched positions matter. There are two mismatch types:

  • a: positions where s[i] = '0' and t[i] = '1'.
  • b: positions where s[i] = '1' and t[i] = '0'.

An opposite pair, one of each type, can be fixed by one same-string swap or by two flips. Two leftover mismatches of the same type can be handled by two flips or by using one cross swap to convert one mismatch type, then one same-string swap. If exactly one mismatch remains after pairing same-type leftovers, one flip is unavoidable.

Worked Example

For s = "01000", t = "10111", flipCost = 10, swapCost = 2, crossCost = 2:

  • Mismatches are a = 4 for 0/1 positions and b = 1 for 1/0 positions.
  • Pair one opposite mismatch: cost min(2, 20) = 2.
  • There are three same-type leftovers. One pair costs min(2 + 2, 20) = 4.
  • One leftover mismatch costs one flip: 10.
  • Total: 2 + 4 + 10 = 16.

Decision Rule / Algorithm

  1. Scan both strings once and count a and b.
  2. Let pairs = min(a, b). Fix these opposite mismatch pairs at cost min(swapCost, 2 * flipCost) each.
  3. Let leftover = abs(a - b).
  4. Fix each pair of same-type leftovers at cost min(crossCost + swapCost, 2 * flipCost).
  5. If leftover is odd, add one more flipCost.

Use 64-bit arithmetic. The maximum answer can be around 10^14 because n is up to 10^5 and each operation cost can be 10^9.

Implementation Skeleton

class Solution:
    def minimumCost(self, s: str, t: str, flipCost: int, swapCost: int, crossCost: int) -> int:
        a = b = 0
        for x, y in zip(s, t):
            if x == '0' and y == '1':
                a += 1
            elif x == '1' and y == '0':
                b += 1

        pairs = min(a, b)
        leftover = abs(a - b)

        cost_opposite = min(swapCost, 2 * flipCost)
        cost_same_pair = min(crossCost + swapCost, 2 * flipCost)

        return (
            pairs * cost_opposite
            + (leftover // 2) * cost_same_pair
            + (leftover % 2) * flipCost
        )

Reimplementation Checklist

  • Count only mismatched positions, separated into 0/1 and 1/0.
  • Do not simulate operations or mutate either string.
  • Use min(swapCost, 2 * flipCost) for opposite-type pairs.
  • Use min(crossCost + swapCost, 2 * flipCost) for same-type leftover pairs.
  • Add exactly one flipCost when the leftover count is odd.
  • Return a 64-bit integer in Java, C++, Go, Rust, C#, Scala, and similar languages.

Wrong But Tempting

  • Pairing every mismatch with every other mismatch at one uniform cost. Opposite-type and same-type leftovers have different cheapest operations.
  • Using crossCost alone to fix a mismatch. A cross swap at one mismatched index turns 0/1 into 1/0 or vice versa; it does not make that index equal by itself.
  • Forgetting the odd leftover case. One same-type mismatch cannot be paired and must be flipped.
  • Using 32-bit int for the answer. Counts times costs can overflow.
  • Sorting mismatch positions or trying adjacency-based swaps. The same-string swap operation can choose any two distinct indices, so positions and distance do not matter.

Accepted Algorithm Families

The 24 accepted local submissions fall into these families:

  • Direct greedy count formula: Most files count a/b, multiply opposite pairs by min(swapCost, 2 * flipCost), then handle leftovers with min(crossCost + swapCost, 2 * flipCost) and a possible final flip. Examples include accepted__kimi-k2.5-cloud-t0.0__python3.py, accepted__kimi-k2.5-cloud-t0.0-golang__golang.go, and several Java/Python variants.
  • Early all-flips branch: Some Java-style submissions first check whether swapping can ever beat two flips, returning (a + b) * flipCost when it cannot, then use the same remaining logic.
  • Candidate algebra/minimization: A few submissions model cross swaps as converting one mismatch type into the other and evaluate a small set of candidate conversion counts. This is more general-looking but collapses to the same cost choices for this problem.
  • Symmetry normalization: Some JavaScript solutions ensure the larger mismatch count is named A, then compare all-flip, opposite-pair, and cross-conversion expressions.
