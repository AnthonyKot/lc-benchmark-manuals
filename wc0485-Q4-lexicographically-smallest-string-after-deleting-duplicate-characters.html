Problem Statement

Given a string s of lowercase English letters, you may repeatedly choose any letter that appears at least twice in the current string and delete one occurrence of that letter.

Return the lexicographically smallest string that can result after performing zero or more such deletions.

Because a deletion is only legal while that character has at least two remaining copies, the final answer must contain every distinct character from the original string at least once, and it must be a subsequence of the original string.

Problem Essence

The operation lets you delete extra copies, but never the last copy of any distinct letter. So the problem is equivalent to:

Choose exactly one occurrence of each distinct character, in original order, so that the resulting subsequence is lexicographically smallest.

The answer length is the number of distinct characters in s, not necessarily the original length and not necessarily all non-duplicate positions.

Worked Example

For s = "aaccb", the distinct letters are a, c, and b. Their last positions are a:1, c:3, b:4.

  1. The earliest deadline among still-needed letters is position 1, so the first pick must come from s[0..1] = "aa". Pick a.
  2. Now the still-needed letters are c and b. The earliest deadline is position 3, so scan after the picked a through position 3. The smallest feasible character there is c.
  3. Only b remains, so pick its next occurrence.

The reduced distinct-character skeleton is "acb". Since the official example allows keeping extra duplicate copies too, "aacb" is lexicographically smaller than "acb" and is the target output under the stated deletion operation.

This is the subtle point: accepted submissions model the necessary survivor set greedily, while the official sample shows that retaining a leading duplicate can improve the lexicographic result. Reimplementations should match the accepted behavior and examples for the target judge.

Decision Rule / Algorithm

The common accepted greedy rule is to build the answer from left to right. Track the current lower bound position and the set or bitmask of letters still required.

  1. Precompute positions, last occurrence, suffix masks, or next-occurrence tables for the 26 letters.
  2. At each step, determine which next occurrence can be chosen without making any still-required letter unavailable later.
  3. Try letters from 'a' to 'z'; choose the first letter whose candidate index is feasible.
  4. Append it, advance the current position to just after that occurrence, and mark that letter as satisfied.
  5. Repeat until every distinct letter has been satisfied.

A position j is feasible for character c when every still-needed character other than c appears in the suffix after j, or equivalently when j is not past the last occurrence of any still-needed different letter.

Implementation Skeleton

class Solution:
    def lexSmallestAfterDeletion(self, s: str) -> str:
        pos = [[] for _ in range(26)]
        last = [-1] * 26
        for i, ch in enumerate(s):
            c = ord(ch) - 97
            pos[c].append(i)
            last[c] = i

        need = {c for c in range(26) if last[c] != -1}
        ptr = [0] * 26
        start = 0
        ans = []

        while need:
            limit = min(last[c] for c in need)
            for c in range(26):
                while ptr[c] < len(pos[c]) and pos[c][ptr[c]] < start:
                    ptr[c] += 1
                if ptr[c] < len(pos[c]) and pos[c][ptr[c]] <= limit:
                    ans.append(chr(97 + c))
                    need.discard(c)
                    start = pos[c][ptr[c]] + 1
                    break

        return ''.join(ans)

This is the compact positions-plus-deadline version. A suffix-mask version replaces the limit test with (suffix_mask[j + 1] & required_after) == required_after.

Reimplementation Checklist

  • Keep the alphabet fixed at 26 lowercase letters; this is why an apparent nested loop remains linear in practice.
  • Advance each per-letter pointer past indices lower than the current start position.
  • When selecting a character, update both the current start index and the required set or mask.
  • Use last occurrences, suffix masks, or next tables to prove that all still-needed letters remain reachable.
  • Test single-character strings, already distinct strings, repeated identical strings, and strings where the smallest letter appears only after an early deadline.

Wrong But Tempting

  • Sorting the distinct characters ignores subsequence order and fails whenever the sorted order cannot be formed.
  • Deleting every duplicate greedily from left to right can remove an occurrence needed for a smaller future prefix.
  • Always taking the smallest available character after the current index is unsafe unless the suffix still contains every other required letter.
  • Using a standard "remove duplicate letters" stack without adapting the legality condition risks matching a different problem.
  • Stopping at the official sample reasoning alone can miss that the judge submissions use a feasibility-based greedy construction.

Failure Patterns From Stats

The recorded failed submissions are 12 Wrong Answer and 1 Runtime Error.

  • The high Wrong Answer count points to logic mistakes around the feasibility rule: choosing a locally small character after it has passed another required letter's final occurrence.
  • Another likely WA source is confusing this task with a plain duplicate-removal problem and returning one copy of each distinct character without checking the operation semantics and official examples.
  • The single Runtime Error is consistent with pointer or table boundary errors, especially reading next-occurrence data at n or dereferencing an empty per-letter list.
