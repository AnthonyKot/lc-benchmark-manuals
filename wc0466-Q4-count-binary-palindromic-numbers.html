Problem Statement

You are given a non-negative integer n. A non-negative integer is binary-palindromic if its binary representation, written without leading zeros, reads the same forward and backward.

Return the number of integers k such that 0 <= k <= n and the binary representation of k is a palindrome.

The number 0 is considered binary-palindromic, with representation "0". Constraint: 0 <= n <= 10^15.

Problem Essence

Do not iterate over every integer up to n. The value 10^15 has only 50 binary bits, so the count can be computed by binary length.

For any positive binary palindrome of length L, the first bit must be 1, and the first ceil(L / 2) bits determine the entire number. Therefore, the number of positive palindromes of exact length L is:

2^(ceil(L / 2) - 1)

The only special case outside that formula is 0, which is counted once.

Worked Example

For n = 9, binary n is 1001, so L = 4.

  1. Start with 1 for 0.
  2. Lengths below 4 contribute: length 1 has 1 value (1), length 2 has 1 value (11), length 3 has 2 values (101, 111).
  3. Subtotal before length 4 is 1 + 1 + 1 + 2 = 5.
  4. For length 4, take the first ceil(4 / 2) = 2 bits of 1001: prefix 10. Mirroring it gives 1001, which is exactly 9, so include it.

Answer: 6. The values are 0, 1, 3, 5, 7, and 9.

Decision Rule / Algorithm

  1. If n == 0, return 1.
  2. Let s = binary(n) and L = len(s).
  3. Initialize answer = 1 for the number 0.
  4. For each positive length len from 1 through L - 1, add 2^((len - 1) / 2 floor). This is the same as 2^(ceil(len / 2) - 1).
  5. For length L, let half = ceil(L / 2), prefix = first half bits of n, and minPrefix = 1 << (half - 1).
  6. All prefixes from minPrefix up to prefix - 1 produce length-L palindromes smaller than n, so add prefix - minPrefix.
  7. Mirror prefix into a full length-L palindrome. If that value is <= n, add one more.

Equivalent accepted implementations binary-search the largest valid prefix whose constructed palindrome is <= n. That is also correct because palindrome values increase monotonically with the chosen prefix for a fixed length.

Implementation Skeleton

function countBinaryPalindromes(n):
    if n == 0:
        return 1

    s = binary representation of n without leading zeros
    L = length(s)
    ans = 1

    for len in 1 .. L - 1:
        ans += 1 << ((len - 1) // 2)

    half = (L + 1) // 2
    prefix = integer value of s[0:half]
    minPrefix = 1 << (half - 1)

    ans += prefix - minPrefix

    if L is even:
        palBits = prefixBits + reverse(prefixBits)
    else:
        palBits = prefixBits + reverse(prefixBits without last bit)

    if integer value of palBits <= n:
        ans += 1

    return ans

Reimplementation Checklist

  • Count 0 exactly once.
  • Do not allow leading-zero prefixes for positive numbers; minPrefix = 1 << (half - 1).
  • Use half = (L + 1) // 2, not L // 2, when extracting the controlling prefix.
  • For odd length, do not duplicate the middle bit when mirroring.
  • Use 64-bit integer arithmetic in fixed-width languages. n <= 10^15, but intermediate shifts still need more than 32 bits.
  • Return type can be int because the total count up to 10^15 is small, but internal arithmetic should be long, long long, or equivalent.

Wrong But Tempting

  • Brute-forcing every k from 0 to n. This is impossible at 10^15.
  • Using decimal palindromes or stringifying the decimal value. The palindrome property is about binary representation only.
  • Counting 2^ceil(L / 2) for a length. The leading bit is fixed to 1, so there is one fewer free bit.
  • Forgetting 0, or accidentally counting 0 again as a length-1 positive palindrome.
  • Mirroring the whole prefix for odd lengths, which duplicates the center bit and creates a number with too many bits.
  • Comparing only suffix strings without respecting exact construction. It can work, as in one accepted JavaScript file, but constructing and comparing the full palindrome is less fragile.

Accepted Algorithm Families

Prefix mirror and boundary check

Used by the JavaScript, Python, and several Java accepted submissions. These directly count shorter lengths, extract the top ceil(L / 2) bits of n, add the smaller prefixes, then mirror the boundary prefix once to decide whether to include it.

Representative files: accepted__set2-deepseek-v4-pro-cloud-t0.0-javascript__javascript.js, accepted__set2-qwen3.5-cloud-t0.0__python3.py, accepted__set2-kimi-k2.5-cloud-t0.8-java__java.java, accepted__set2-qwen3.5-cloud-t0.0-java__java.java.

Binary search over prefixes

Used by the Go and two Java submissions. For the current bit length, choose the range of valid leading prefixes and binary-search for the largest prefix whose constructed palindrome is no greater than n. This is slightly more code, but still constant time for this constraint because there are at most about 50 bits.

Representative files: accepted__set2-kimi-k2.5-cloud-t0.0-golang__golang.go, accepted__set2-kimi-k2.5-cloud-t0.0-java__java.java, accepted__set2-kimi-k2.5-cloud-t0.9-java__java.java.
