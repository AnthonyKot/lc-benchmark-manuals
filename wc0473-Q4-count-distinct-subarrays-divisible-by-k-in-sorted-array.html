Problem Statement

You are given an integer array nums sorted in non-descending order and a positive integer k.

A non-empty subarray is good if the sum of its elements is divisible by k. Return the number of distinct good subarrays, where two subarrays are distinct by their value sequence, not by their index positions.

For example, [1, 1, 1] has only three distinct subarrays by sequence: [1], [1, 1], and [1, 1, 1].

  • 1 <= nums.length <= 100000
  • 1 <= nums[i] <= 1000000000
  • nums is sorted in non-descending order.
  • 1 <= k <= 1000000000

Problem Essence

The hard part is not divisibility; that is a standard prefix-sum remainder condition. The hard part is distinctness under a sorted array with many equal values.

Because the array is sorted, equal values form contiguous runs. A subarray spanning at least two different values has a canonical value sequence: choose the left run, the right run, how many copies are taken from the left edge, and how many copies are taken from the right edge. That sequence cannot reappear elsewhere.

Duplicate value sequences happen only for subarrays fully inside one equal-value run. A run of value v and length c contributes one distinct all-v sequence for each length L such that L * v % k == 0.

Worked Example

For nums = [2, 2, 2, 2, 2, 2] and k = 6, there is one run: value 2, count 6.

A same-run sequence of length L is good when 2L % 6 == 0, so L must be a multiple of 3. The possible lengths are 3 and 6.

The distinct good subarrays are therefore [2, 2, 2] and [2, 2, 2, 2, 2, 2], so the answer is 2. Although length 3 appears at four index positions, all four positions have the same value sequence and count once.

Decision Rule / Algorithm

The accepted solutions use one of two equivalent viewpoints.

Run-boundary hash rule

  1. Compress nums into runs (value[i], count[i]).
  2. For each run, count single-run sequences. Let g = gcd(value, k) and period = k / g. Valid lengths are multiples of period, so this run contributes count / period.
  3. For subarrays spanning multiple runs, use prefix sums over whole runs. A sequence is described by taking a values from the left run, all middle runs, and b values from the right run.
  4. Store remainders for possible left boundaries in a hash map. Query matching right-boundary remainders before inserting the current run, so the counted subarray spans at least two runs.
  5. Return the sum of single-run and multi-run counts.

Prefix-pair correction rule

  1. Count all index-based subarrays with sum divisible by k using prefix remainder frequencies.
  2. For each equal-value run, subtract the overcount caused by duplicate same-run value sequences.
  3. For run length c and value v, valid lengths are multiples of s = k / gcd(v, k). If m = c / s, subtract sum(c - t*s) for t = 1..m.

Both rules exploit the same sorted-array invariant: any duplicate distinctness problem is contained inside one run of equal values.

Implementation Skeleton

long numGoodSubarrays(int[] nums, int k):
    runs = compress nums into (value, count)
    prefix[0] = 0
    for each run i:
        prefix[i + 1] = prefix[i] + value[i] * count[i]

    ans = 0

    for each run i:
        step = k / gcd(value[i], k)
        ans += count[i] / step

    freq = empty hash map from remainder to count
    for each run j from left to right:
        v = value[j]
        c = count[j]

        for b in 1..c:
            right = (prefix[j] + b * v) mod k
            ans += freq[right]

        for a in 1..c:
            left = (prefix[j + 1] - a * v) mod k
            freq[left] += 1

    return ans

Some accepted files use equivalent signs, storing -left and querying -right. The only requirement is that the two sides use complementary remainder formulas consistently.

Reimplementation Checklist

  • Use long, long long, or arbitrary-precision integers for sums and the answer.
  • Normalize all modulo results into [0, k - 1], especially when subtracting prefix sums.
  • Count same-run subarrays by distinct lengths, not by positions.
  • When using run-boundary hashing, query the current run before inserting it to avoid treating same-run subarrays as multi-run subarrays.
  • Total loop work over all run counts is O(n), because each a and b loop across all runs sums to n.
  • Return a 64-bit value. The answer can be quadratic in distinctness scale for large arrays.

Wrong But Tempting

Counting prefix pairs directly is not enough unless you also correct duplicate same-run subarrays. It counts index occurrences, not distinct value sequences.

  • Using a Set of serialized subarrays is too slow and too large for n = 100000.
  • Assuming each valid length in an equal run contributes all its positions overcounts. Length L inside one run contributes exactly one distinct sequence.
  • Forgetting the sorted property leads to harder duplicate handling than needed. The accepted approaches rely on equal values being contiguous.
  • Mixing index-based prefix sums with run-based distinctness without a correction gives plausible answers on arrays without duplicates but fails on long equal runs.

Failure Patterns From Stats
