Count Stable Subarrays

Problem id: wc0476-Q4-count-stable-subarrays. Function: countStableSubarrays(nums, queries). Difficulty: Hard.

The accepted set covers Java, Go, Python 3, and JavaScript implementations. Most accepted files use maximal non-decreasing segments directly; one Go file uses a segment tree over adjacent comparisons, and one Java file uses an offline Fenwick formulation.

Problem Statement

You are given an integer array nums and queries [l, r]. A non-empty subarray is stable when it has no inversion, meaning there are no indices i < j inside it with nums[i] > nums[j]. For each query, return the number of stable subarrays fully contained in nums[l..r].

  • 1 <= nums.length <= 100000
  • 1 <= nums[i] <= 100000
  • 1 <= queries.length <= 100000
  • 0 <= l <= r < nums.length
  • A single element subarray is stable.

Problem Essence

A subarray has no inversion exactly when it is non-decreasing. Therefore every stable subarray must lie completely inside one maximal non-decreasing run of nums. A run of length L contributes L * (L + 1) / 2 stable subarrays.

The task is not to test every candidate subarray. It is to split nums at every descent nums[i] > nums[i + 1], then answer each query by summing triangular counts from the touched run fragments.

Worked Example

For nums = [3, 1, 2], the descents split the array into runs [3] and [1, 2].

QuerySegmentStable subarraysAnswer
[0, 1][3, 1][3], [1]2
[1, 2][1, 2][1], [2], [1, 2]3
[0, 2][3, 1, 2][3], [1], [2], [1, 2]4

Output: [2, 3, 4].

Other Official Examples

For nums = [2, 2] and queries = [[0, 1], [0, 0]], the whole array is one non-decreasing run.

  • [0, 1] has length 2, so it has 2 * 3 / 2 = 3 stable subarrays: both singletons and [2, 2].
  • [0, 0] has length 1, so it has 1 stable subarray.

Output: [3, 1].

Decision Rule / Algorithm

Recommended run-prefix method

  1. Scan nums and start a new run whenever nums[i] > nums[i + 1].
  2. Store arrays start[k], end[k], and optionally belong[pos], the run index containing a position.
  3. Build pref[k + 1] = pref[k] + tri(length(run k)), where tri(x) = x * (x + 1) / 2.
  4. For a query [l, r], find a = belong[l] and b = belong[r]. If belong was not built, binary search the largest run start at or before each endpoint.
  5. If a == b, answer tri(r - l + 1).
  6. Otherwise answer tri(end[a] - l + 1) + (pref[b] - pref[a + 1]) + tri(r - start[b] + 1).

This gives O(n + q) with belong, or O(n + q log n) with binary searches over run starts. Both fit the constraints.

Implementation Skeleton

function countStableSubarrays(nums, queries):
    n = len(nums)
    starts = []
    ends = []
    belong = array length n

    start = 0
    run = 0
    for i in 0..n-1:
        if i == n-1 or nums[i] > nums[i+1]:
            starts.append(start)
            ends.append(i)
            for p in start..i:
                belong[p] = run
            run += 1
            start = i + 1

    pref = array length run+1, filled with 0
    for k in 0..run-1:
        length = ends[k] - starts[k] + 1
        pref[k+1] = pref[k] + length * (length + 1) / 2

    ans = []
    for [l, r] in queries:
        a = belong[l]
        b = belong[r]
        if a == b:
            length = r - l + 1
            ans.push(length * (length + 1) / 2)
        else:
            left = ends[a] - l + 1
            right = r - starts[b] + 1
            total = left * (left + 1) / 2
            total += pref[b] - pref[a + 1]
            total += right * (right + 1) / 2
            ans.push(total)
    return ans

Reimplementation Checklist

  • Use the split condition nums[i] > nums[i + 1]. Equal adjacent values stay in the same stable run.
  • Use 64-bit integer arithmetic for answers and prefix counts. The maximum count is about 100000 * 100001 / 2.
  • Handle queries entirely inside one run with one triangular number.
  • For cross-run queries, count only the suffix of the left run, full middle runs, and prefix of the right run.
  • Make prefix indices consistent: pref[k] should represent the sum of complete runs before run k.
  • If using binary search instead of belong, find the largest start[k] <= pos.

Wrong But Tempting

  • Counting all non-inversion pairs is not enough. A stable subarray requires every adjacent transition in the chosen interval to be non-decreasing.
  • Using nums[i] >= nums[i + 1] as the split condition is wrong because equal values do not create inversions.
  • Summing full run counts for every run touched by a query overcounts the left and right boundary runs when the query cuts through them.
  • Using 32-bit int for the returned counts can overflow in languages where int is fixed-width.
  • Building every stable subarray explicitly is too slow and can reach quadratic output size.

Maximal run decomposition with direct run lookup Java t0.8, Java t0.9 Precompute run starts, run ends, position-to-run, and prefix triangular counts. Each query is constant time. O(n + q) time, O(n) space
Maximal run decomposition with binary search Python 3, Qwen Java Store run starts and limits. Locate the containing runs for l and r by binary search. O(n + q log n) time, O(n) space
Right-bound array plus binary search JavaScript For each index, store the furthest non-decreasing run end. Query sums min(right[i], r) - i + 1 across starts in [l, r]. O(n + q log n) time, O(n) space
Segment tree over adjacent good edges Go Convert each adjacent pair to 1 if non-decreasing. A query over edges returns total all-ones subarrays, then adds singletons. O((n + q) log n) time, O(n) space
Offline Fenwick adjustment Java t0.0 Precompute each start index's run end, then answer sums capped by query right endpoint using sorted queries and Fenwick trees. O((n + q) log n) time, O(n) space
