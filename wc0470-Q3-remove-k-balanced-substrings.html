Problem Statement

You are given a string s containing only ( and ), and an integer k. A string is k-balanced when it is exactly k consecutive opening parentheses followed immediately by k consecutive closing parentheses: "(" * k + ")" * k.

Repeatedly remove all non-overlapping k-balanced substrings from s, join the remaining parts, and continue until no k-balanced substring remains. Return the final string.

Constraints: 2 <= s.length <= 100000, s consists only of parentheses, and 1 <= k <= s.length / 2.

Problem Essence

The repeated-removal wording is the trap: after one deletion, the left and right neighbors may become adjacent and form a new removable block. A correct solution must simulate this cascading behavior without rescanning the whole string after every deletion.

The key invariant is local. A removal can only occur at a boundary where a run of ( is immediately followed by a run of ), and both runs have at least k characters. Removing k from each side may expose another boundary, so the algorithm keeps a stack representation of the current reduced prefix.

Decision Rule / Algorithm

Use a stack of runs, where each entry stores a character and its current count. For every character in s, append it to the top run if the character matches, otherwise push a new run. After every push or count increment, repeatedly check the top two runs:

  1. If the second-to-top run is (, the top run is ), and both counts are at least k, subtract k from both counts.
  2. Remove any run whose count becomes zero.
  3. If deletion makes two adjacent runs with the same character, merge them.
  4. Repeat the check because the merge or shrink may create another removable boundary.

This is linear in practice and in the accepted implementations: each input character is pushed once into a compact stack state, and deletions reduce stored counts rather than rebuilding strings.

Implementation Skeleton

function removeSubstring(s, k):
    stack = empty list of (char, count)

    for c in s:
        if stack is not empty and stack.last.char == c:
            stack.last.count += 1
        else:
            push (c, 1)

        while stack has at least two runs:
            left = stack[-2]
            right = stack[-1]
            if left.char != '(' or right.char != ')' or left.count < k or right.count < k:
                break

            left.count -= k
            right.count -= k
            remove zero-count runs
            if top two runs now have the same char:
                merge them

    return concatenation of char repeated count for every run

An equivalent character-stack skeleton stores, for each stack position, the current consecutive open or close run length. When the last k characters are ) and the preceding stack position has at least k consecutive (, pop 2 * k characters. Two accepted Java submissions use this form.

Reimplementation Checklist

  • Represent the evolving string with a stack, not by repeatedly calling string replace or slicing in a loop.
  • Only remove k opens followed by k closes; balanced parentheses in the usual nesting sense are not enough.
  • After each deletion, continue checking the new top boundary before reading more input.
  • Delete zero-length runs and merge adjacent equal-character runs.
  • Build the answer at the end with a buffer or joined list, not repeated string concatenation inside a large loop.
  • Test k = 1, large single runs, no-removal cases, and cases where deletion exposes a new boundary.

Wrong But Tempting

  • Remove only the first visible batch. Example 1 needs a second removal after the first deletion creates ().
  • Search for ordinary balanced substrings. For k = 3, () is balanced but not k-balanced.
  • Use global replacement of the pattern once. New matches can cross the join created by a previous deletion.
  • Forget run merging. If a middle run disappears, two runs of the same character may become adjacent; treating them as separate can miss a future k-sized deletion.
  • Use repeated string splicing. With n = 100000, repeated rebuilds can become quadratic.
