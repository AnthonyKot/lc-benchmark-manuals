Problem Statement

Given positive integers n and k, return the nth smallest positive integer whose binary representation contains exactly k one bits. The answer is guaranteed to be strictly less than 2^50.

  • 1 <= n <= 2^50
  • 1 <= k <= 50
  • The returned value is strictly less than 2^50.

Problem Essence

The sorted numbers with exactly k set bits can be viewed as combinations of bit positions. A number is smaller when its highest set bit is lower; within the same highest bit, the remaining lower bits are ordered the same way recursively. Therefore the task is not to enumerate up to n, but to unrank a combination using binomial counts.

The key count is: among positions 0..pos-1, the number of ways to place r remaining ones is C(pos, r). This lets us skip an entire block of candidates when n is larger than that block.

Worked Example

For n = 4, k = 2, group numbers by highest set bit:

Highest bit positionCountNumbersAction
1C(1,1)=13 = 11bSkip; n becomes 3.
2C(2,1)=25 = 101b, 6 = 110bSkip; n becomes 1.
3C(3,1)=39, 10, 12Target is in this block, so set bit 3.

One one-bit remains to place below position 3. The first such lower choice is position 0, so the answer is 1001b = 9.

Decision Rule / Algorithm

  1. Precompute binomial coefficients C[i][j] for 0 <= i,j <= 50, or use a safe built-in such as Python's math.comb.
  2. Maintain answer, remaining rank n, remaining ones k, and an upper bit limit initially 50.
  3. For the next highest remaining one, try candidate bit positions pos from k - 1 upward, but below the current limit.
  4. The block with highest remaining bit exactly pos has C(pos, k - 1) numbers, because the other k - 1 ones must be chosen from lower positions.
  5. If n > C(pos, k - 1), subtract that count and try the next pos.
  6. Otherwise set bit pos, reduce k, set the upper limit to pos, and continue with lower bits.
  7. When k = 0, return answer.

This is O(50^2) for precomputation and at most another O(50^2) scan in the simplest form. Binary-search variants reduce the scan but are unnecessary under the constraints.

Implementation Skeleton

class Solution:
    def nthSmallest(self, n: int, k: int) -> int:
        # Build C[a][b] = number of ways to choose b positions from a.
        C = [[0] * 51 for _ in range(51)]
        for i in range(51):
            C[i][0] = 1
            for j in range(1, i + 1):
                C[i][j] = C[i - 1][j - 1] + C[i - 1][j]

        ans = 0
        limit = 50
        while k > 0:
            for pos in range(k - 1, limit):
                count = C[pos][k - 1]
                if n > count:
                    n -= count
                else:
                    ans |= 1 << pos
                    limit = pos
                    k -= 1
                    break
        return ans

Reimplementation Checklist

  • Use 64-bit integer storage for n, binomial counts, and the answer in C++, Java, Go, Rust, and similar languages.
  • Remember that bit positions are zero-indexed; 1 << 0 contributes value 1.
  • Only consider positions below the previously chosen position, so set limit = pos after placing a bit.
  • The minimum feasible next position is k - 1, because there must be enough lower positions to hold the remaining k - 1 ones.
  • Use C(pos, k - 1) for the size of a block with highest bit pos.
  • Return a numeric value, not a binary string.

Wrong But Tempting

  • Enumerating integers and counting bits is too slow because n can be as large as 2^50.
  • Using floating-point combinations can silently misrank near large counts; use integer binomial arithmetic.
  • Confusing C(pos, k) with C(pos, k - 1) shifts every block count after the first selected bit.
  • Searching all future bit positions after choosing a high bit can create invalid numbers with bits above the chosen prefix; lower the limit each time.
  • Using 32-bit int for counts or shifts overflows well before 2^50.
