Problem Statement

You are given an integer array nums and an integer k. In one operation, you may increase or decrease any element by exactly k.

For each query [l, r], compute the minimum number of operations required to make all elements in nums[l..r] equal. If it is impossible, return -1 for that query.

Constraints from the statement: 1 <= n, queries.length <= 4 * 10^4, 1 <= nums[i], k <= 10^9, and 0 <= l <= r < n.

Problem Essence

Adding or subtracting k never changes an element's remainder modulo k. Therefore a queried subarray can be equalized only when every element in the subarray has the same remainder modulo k.

Once the remainders match, write each value as nums[i] = remainder + k * q[i]. Equalizing the original values is exactly the same as making the integer quotients q[i] equal, with one operation changing a quotient by one. The minimum total number of unit moves to make several numbers equal is achieved at a median.

Worked Example

Example 1 from the statement:

nums = [1, 4, 7]
k = 3
queries = [[0, 1], [0, 2]]
output = [1, 2]

All three values have remainder 1 mod 3. Their quotients after removing the common remainder are [0, 1, 2].

Decision Rule / Algorithm

  1. Precompute a range test for whether all remainders nums[i] % k are equal in [l, r]. Accepted solutions use either a prefix count of adjacent remainder changes or a min/max sparse/segment tree over remainders.
  2. Transform values to an order-preserving domain. Either keep original nums[i] and divide the final absolute-difference sum by k, or use quotients q[i] = (nums[i] - nums[i] % k) / k and return the absolute-difference sum directly.
  3. Coordinate-compress the chosen values.
  4. Build a range order-statistics structure that can answer: kth smallest value in [l, r], count of values <= median, and sum of values <= median.
  5. For each query with matching remainders, find the lower median at rank (len + 1) / 2. Let cntLE and sumLE be the count and sum up to the median, and totalSum be the full range sum.
  6. Compute leftCost = median * cntLE - sumLE and rightCost = (totalSum - sumLE) - median * (len - cntLE). The answer is leftCost + rightCost when using quotients, or (leftCost + rightCost) / k when using original values.

Implementation Skeleton

minOperations(nums, k, queries):
    n = len(nums)

    rem[i] = nums[i] % k
    badPrefix[0] = 0
    for i in 1..n-1:
        badPrefix[i] = badPrefix[i-1] + (rem[i] != rem[i-1])

    values[i] = nums[i]                 # or quotient (nums[i] - rem[i]) / k
    compressed = sorted unique values
    roots[0] = empty persistent segment tree
    prefixSum[0] = 0
    for i in 0..n-1:
        roots[i+1] = add roots[i] with values[i]
        prefixSum[i+1] = prefixSum[i] + values[i]

    for each [l, r]:
        if badPrefix[r] - badPrefix[l] != 0:
            answer -1
            continue

        len = r - l + 1
        rank = (len + 1) // 2
        median = kth(roots[l], roots[r+1], rank)
        cntLE, sumLE = queryPrefixByValue(roots[l], roots[r+1], median)
        total = prefixSum[r+1] - prefixSum[l]
        cost = median * cntLE - sumLE + (total - sumLE) - median * (len - cntLE)
        answer cost / k if values are original nums, otherwise cost

Reimplementation Checklist

  • Use 64-bit integers for sums and answers. A range can contain 4 * 10^4 values up to 10^9.
  • Use lower median rank (len + 1) / 2; any median gives the same cost, but lower median is easiest for kth queries.
  • Make the range version difference correctly: query on roots[r + 1] minus roots[l].
  • Keep count and sum in every order-statistics node.
  • If using original nums[i] in the tree, divide the absolute-difference total by k. If using quotients, do not divide.
  • For Java and Go, preallocate persistent segment tree arrays generously: about n * (log2(uniqueValues) + 2) nodes.
  • For JavaScript, store numeric arrays compactly and avoid object-heavy tree nodes.

Wrong But Tempting

  • Checking only the first and last remainders. A range like remainders [1, 0, 1] would pass that check but is impossible.
  • Using the arithmetic mean instead of the median. The mean minimizes squared error, not sum of absolute moves.
  • Sorting each query independently. With up to 4 * 10^4 queries and length 4 * 10^4, that is too slow.
  • Forgetting that operation count is in units of k, not raw absolute difference.
  • Building a normal mutable segment tree and expecting it to answer arbitrary historical subarray ranges without persistence or merge-sort buckets.

Accepted Algorithm Families

Persistent segment tree over compressed values Python and most Java submissions Each prefix has a root. Subtract two roots to get the multiset for [l, r], then find kth and prefix sums by value. O(n log n) build, O(log n) per query
Merge-sort tree plus binary search Go submission Each segment tree node stores sorted quotient values and prefix sums. Binary-search the value domain to find the median by range counts. O(n log n) build, roughly O(log^2 n log n) median search plus sum queries
Wavelet tree One Java submission Stores rank navigation and prefix sums over compressed quotient values, giving order statistics and sums in one static structure. O(n log sigma) build, O(log sigma) per query
