Problem Statement

Given two integers low and high, return the number of balanced integers in the inclusive range [low, high].

An integer is balanced when it has at least two digits and the sum of digits in odd positions equals the sum of digits in even positions. Positions are counted from the left, starting at 1.

Constraint: 1 <= low <= high <= 10^15.

Problem Essence

The range is too large for enumeration. The useful reduction is to define f(x) as the number of balanced integers from 1 through x, then return f(high) - f(low - 1). Computing f(x) is a digit DP over the decimal representation of x.

The DP only needs to know where it is in the digit string, whether the prefix is still tight to the upper bound, whether a real number has started, and the current difference between odd-position and even-position digit sums. At the end, count the number only if at least two digits were placed and the difference is zero.

Worked Example

For low = 120 and high = 129, scan the candidates:

  • 120: odd positions are 1 + 0 = 1, even positions are 2, not balanced.
  • 121: odd positions are 1 + 1 = 2, even positions are 2, balanced.
  • 122 through 129: odd sums are greater than 2, so they are not balanced.

The answer is 1.

Decision Rule / Algorithm

  1. Implement countUpTo(x); return 0 for x <= 0.
  2. Convert x to a digit array.
  3. Run a digit DP from most significant digit to least significant digit.
  4. Skip leading zeros without changing the placed length or digit-sum difference.
  5. When placing the first nonzero digit, it becomes position 1, so add it to the odd-position side.
  6. For each later digit, alternate signs by the real placed length: add for odd positions, subtract for even positions.
  7. At the terminal state, return 1 only when real length is at least 2 and difference is 0.
  8. Return countUpTo(high) - countUpTo(low - 1).

With at most 16 digits and difference bounded by about [-144, 144], the state space is tiny.

Implementation Skeleton

def countBalanced(low, high):
    return count_up_to(high) - count_up_to(low - 1)

def count_up_to(x):
    if x <= 0:
        return 0
    digits = decimal_digits(x)

    memo = {}

    def dfs(index, length, diff, tight):
        if index == len(digits):
            return 1 if length >= 2 and diff == 0 else 0

        key = (index, length, diff) if not tight else None
        if key is not None and key in memo:
            return memo[key]

        limit = digits[index] if tight else 9
        total = 0
        for d in range(0, limit + 1):
            next_tight = tight and d == limit
            if length == 0 and d == 0:
                total += dfs(index + 1, 0, diff, next_tight)
            else:
                next_len = length + 1
                next_diff = diff + d if next_len % 2 == 1 else diff - d
                total += dfs(index + 1, next_len, next_diff, next_tight)

        if key is not None:
            memo[key] = total
        return total

    return dfs(0, 0, 0, True)

Reimplementation Checklist

  • Use a 64-bit return type in languages with fixed-width integers.
  • Subtract prefix counts: f(high) - f(low - 1).
  • Do not count one-digit numbers, even though their alternating difference may look valid in a flawed state model.
  • Leading zeros must not consume a position. The leftmost real digit is position 1.
  • Memoize only states that are no longer tight, or include tight in the memo key.
  • Keep the difference offset large enough for 16 digits; 9 * len or a constant near 160 is sufficient for this constraint.
  • Test the three official examples and boundary-style cases such as [1, 9], [10, 99], and single-point ranges.

Wrong But Tempting

  • Iterating every integer in [low, high]. The upper bound reaches 10^15.
  • Treating leading zeros as actual positions. That changes parity and corrupts numbers with fewer digits than the upper bound.
  • Using zero-based parity from the array index after leading zeros. Parity must be based on the real digit length, not the bound string index.
  • Counting length-1 numbers when diff == 0 or when no number has started.
  • Using number carelessly in JavaScript for totals beyond exact integer limits. The submitted JavaScript solutions passed here, but a conservative implementation should keep operations within known exact bounds or use BigInt if adapting the problem.

Accepted Algorithm Families

  • Recursive digit DP with leading-zero state: Python and C++ examples use DFS over pos, length or started, diff, and tight. This is the clearest family and appears throughout the accepted corpus.
  • Fixed-length DP plus bounded prefix: The fast Java solution counts all shorter lengths with free DP, then counts the exact upper-bound length with tight/free layers.
  • Iterative table DP: Several Java, Go, Rust, and JavaScript submissions convert the same recurrence into arrays indexed by position and shifted difference.
  • Alternative sign convention: Some solutions track odd - even; others track even - odd. Both are equivalent as long as the terminal check is zero and parity is consistent.
