Problem Statement

You are given integers n, l, and r. Count arrays of length n whose elements are all in [l, r], whose adjacent elements are never equal, and whose every three consecutive elements are not strictly increasing and not strictly decreasing. Return the count modulo 1_000_000_007.

Equivalently, for every adjacent pair the comparison must be either up or down, and comparisons must alternate. Equal adjacent values are forbidden.

Problem Essence

The actual values matter only through their order inside the interval. Let m = r - l + 1 and remap values to ranks 0..m-1 or 1..m. A valid array is exactly an alternating up/down sequence over these ranks.

The hard part is not deciding validity for one array, but counting all choices without an O(n*m*m) transition. Prefix and suffix sums collapse each layer to O(m).

For length 3, an up move must follow a previous down move, and a down move must follow a previous up move:

  • newUp[v] = sum(down[u]) for u < v, giving [0, 2, 3].
  • newDown[v] = sum(up[u]) for u > v, giving [3, 2, 0].

The total is 0+2+3+3+2+0 = 10, matching the official output.

Decision Rule / Algorithm

Use two DP arrays for the current length:

  • up[v]: count of sequences ending at value/rank v where the last comparison was up, so the next comparison must be down.
  • down[v]: count of sequences ending at value/rank v where the last comparison was down, so the next comparison must be up.

Initialize length 2:

  • up[v] = number of smaller ranks = v for 0-based ranks.
  • down[v] = number of larger ranks = m - 1 - v.

Transition for each new length from 3 to n:

  • nextUp[v] = sum(down[u]) over all u < v.
  • nextDown[v] = sum(up[u]) over all u > v.

Compute those sums with one left-to-right cumulative pass and one right-to-left cumulative pass. The final answer is sum(up) + sum(down) modulo 1_000_000_007.

Implementation Skeleton

class Solution {
    public int zigZagArrays(int n, int l, int r) {
        final int MOD = 1_000_000_007;
        int m = r - l + 1;

        long[] up = new long[m];
        long[] down = new long[m];
        for (int v = 0; v < m; v++) {
            up[v] = v;
            down[v] = m - 1 - v;
        }

        for (int len = 3; len <= n; len++) {
            long[] nextUp = new long[m];
            long[] nextDown = new long[m];

            long running = 0;
            for (int v = 0; v < m; v++) {
                nextUp[v] = running;
                running = (running + down[v]) % MOD;
            }

            running = 0;
            for (int v = m - 1; v >= 0; v--) {
                nextDown[v] = running;
                running = (running + up[v]) % MOD;
            }

            up = nextUp;
            down = nextDown;
        }

        long ans = 0;
        for (int v = 0; v < m; v++) {
            ans = (ans + up[v] + down[v]) % MOD;
        }
        return (int) ans;
    }
}

Reimplementation Checklist

  • Compute m = r - l + 1; do not allocate over the raw value range if rank indices are simpler.
  • Initialize from length 2, not length 1, unless using the one-pattern symmetry variant.
  • Use strict comparisons only: smaller for up and larger for down. Do not include equal values in prefix/suffix ranges.
  • Modulo every running cumulative sum and answer accumulation.
  • Use long, int64, or safe numeric handling for additions before modulo.
  • Return sum(up) + sum(down) after processing through length n.

Wrong But Tempting

  • Only checking adjacent inequality. This counts monotone triples such as [1,2,3], which are invalid.
  • Allowing equal endpoints in transitions. Prefix should stop before v; suffix should start after v.
  • Using O(n*m*m). With n,m up to 2000, a nested transition over all pairs is too slow in slower languages and unnecessary in all languages.
  • Mixing direction meanings. Decide whether up means last move was up or next move must be up, then keep the recurrence consistent.
  • Forgetting symmetry details. The single-pattern solution can multiply by 2 only because the two starting directions are symmetric; the two-array solution already counts both.
