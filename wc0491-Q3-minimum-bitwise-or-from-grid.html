Problem Statement

You are given a two-dimensional integer array grid of size m x n. You must select exactly one integer from each row. Return the minimum possible bitwise OR of the selected integers.

Constraints from the statement:

  • 1 <= m == grid.length <= 100000
  • 1 <= n == grid[i].length <= 100000
  • m * n <= 100000
  • 1 <= grid[i][j] <= 100000

Problem Essence

The selection is independent by row once a proposed OR mask is fixed. For a candidate answer mask target, a row is satisfiable if it contains at least one value whose set bits are all contained in target. That condition can be written as (value | target) == target, or equivalently (value & ~target) == 0.

To minimize the OR, decide bits from most significant to least significant. Keep higher bits fixed at their best known values, tentatively set the current bit to 0, allow all lower bits to be 1, and test whether every row has at least one compatible value. If the test fails, the current bit is forced to 1.

Worked Example

For grid = [[1,5],[2,4]], the answer is 3.

ChoiceORWhy
Pick 1 from row 1 and 2 from row 21 | 2 = 3Both rows are represented, and the OR has bits 0 and 1 set.
Pick 1 and 45Worse than 3.
Pick 5 and any row-2 valueAt least 5 or 7Worse than 3.

The bitwise greedy view reaches the same conclusion: bit 2 can be excluded because row 1 has 1 and row 2 has 2; bit 1 cannot be excluded after keeping bit 2 out because row 2 needs either 2 or 4; bit 0 cannot be excluded because row 1 needs 1 or 5. The result is binary 011, or 3.

Decision Rule / Algorithm

Feasibility rule: a proposed mask target is achievable if every row contains at least one x such that (x | target) == target.

  1. Use bits 16 down to 0, because grid[i][j] <= 100000 < 2^17. Some accepted submissions use a dynamic max_value.bit_length() or a wider fixed bound such as 20.
  2. Maintain ans, the forced prefix of the answer for higher bits.
  3. At bit b, build candidate = ans | ((1 << b) - 1). This means higher bits match ans, current bit is 0, and lower bits are unconstrained.
  4. If candidate is feasible, leave bit b as 0.
  5. If candidate is not feasible, set ans |= 1 << b.
  6. Return ans.

Time complexity is O(B * m * n), where B is at most 17 under the constraints. Space complexity is O(1) beyond the input for the mask-check version.

Implementation Skeleton

class Solution:
    def minimumOR(self, grid: List[List[int]]) -> int:
        def feasible(target: int) -> bool:
            for row in grid:
                ok = False
                for x in row:
                    if (x | target) == target:
                        ok = True
                        break
                if not ok:
                    return False
            return True

        ans = 0
        for b in range(16, -1, -1):
            candidate = ans | ((1 << b) - 1)
            if not feasible(candidate):
                ans |= 1 << b
        return ans

The equivalent inverse-mask style is also accepted: track bits that can be forced to zero, test whether each row has a value with (value & zero_mask) == 0, and return the complement inside the 17-bit universe.

Reimplementation Checklist

  • Confirm the bit limit. For this constraint, fixed bits 16..0 are enough.
  • For a target mask, scan each row and stop as soon as one compatible value is found.
  • Do not require the same column across rows; each row can choose any of its own values.
  • When testing bit b, keep lower bits permissive with ((1 << b) - 1).
  • Return only the forced bits accumulated in ans, not the last permissive candidate.
  • Use integer bitwise operations only; no sorting, priority queues, dynamic programming over rows, or recursion is needed.

Wrong But Tempting

  • Choosing the minimum value from each row. The minimum numeric value per row does not necessarily minimize the combined OR, because a slightly larger value can have bits that are already present elsewhere.
  • Binary search over numeric answers. The predicate feasible(mask) is monotone under bit inclusion, not ordinary integer order. For example, increasing from 3 to 4 drops low bits, so compatibility can disappear. One local JavaScript accepted file uses numeric binary search, but the robust intended approach is greedy bit fixing.
  • Testing only the current bit independently. A row value with the current bit clear may still contain a higher bit that was already excluded. The feasibility test must respect the whole candidate mask.
  • Trying all row choices. The product of row lengths can be enormous even though total cells are only 100000.

Failure Patterns From Stats

stats.json records 3 failed submissions: 1 Wrong Answer and 2 Time Limit Exceeded.

  • The Wrong Answer pattern is consistent with treating mask feasibility as a numeric monotone property, testing bits independently, or greedily picking row-local minima.
  • The Time Limit Exceeded pattern is consistent with enumerating combinations, using heavy dynamic programming over possible OR values without pruning, or rescanning with unnecessary copied state.
  • The accepted solutions avoid exponential search and keep the outer loop to at most 17 bit decisions.
