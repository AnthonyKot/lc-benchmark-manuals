Problem Statement

A no-zero integer is a positive integer that does not contain the digit 0 in its decimal representation.

Given an integer n, count the number of ordered pairs (a, b) such that both a and b are no-zero integers and a + b = n. Return that count as an integer.

Constraint: 2 <= n <= 10^15.

Problem Essence

We are not just finding one pair; we are counting every ordered split of n. A direct loop over a = 1..n-1 is impossible at 10^15. The useful observation is that the condition is digit-local if we process addition column by column and carry a small amount of state.

The accepted solutions all model decimal addition of two unknown positive no-zero integers. At each digit position, choose one digit for a and one digit for b, require their sum plus carry to match the current digit of n, and propagate the next carry. Because a and b may have fewer digits than n, the DP also needs to represent whether a number is still active or has ended and is now padded with leading zeroes.

Worked Example

For n = 11, the answer is 8.

The valid ordered pairs are:

(2, 9), (3, 8), (4, 7), (5, 6),
(6, 5), (7, 4), (8, 3), (9, 2)

The tempting pairs (1, 10) and (10, 1) are excluded because 10 contains digit 0.

Digit-DP view: at the ones digit, pick digits whose sum ends in 1, such as 2 + 9 = 11, and carry 1. At the tens digit, both one-digit numbers are already ended, so they contribute padding 0 + 0 + 1 = 1, matching the tens digit. That is how one-digit pairs can sum to a two-digit n without allowing zero inside the actual numbers.

Decision Rule / Algorithm

Use digit DP over n from least significant digit to most significant digit.

  1. Extract digits of n in least-significant-first order.
  2. Maintain dp[carry][activeA][activeB], where carry is 0 or 1, and each active flag says whether that number is still choosing real digits. If a number is inactive, all later positions must be padding zeroes.
  3. Initialize with both numbers active and no carry: dp[0][1][1] = 1.
  4. For each position, enumerate valid current digits. Active numbers choose digits 1..9 for the least significant digit, and can either continue or end for future positions; inactive numbers must choose 0.
  5. Accept a transition only when (digitA + digitB + carry) % 10 == currentDigitOfN. The next carry is integer division by 10.
  6. After the most significant digit, count states with final carry 0 and with both addends validly represented. The exact active/inactive terminal convention varies by implementation, but it must allow numbers shorter than n.

Equivalent accepted variants track whether a number has already ended, whether it has started, or whether it is still active. These are the same DP once the meaning of the two flags is kept consistent.

Implementation Skeleton

long countNoZeroPairs(long n) {
    digits = decimal digits of n, least significant first
    dp = 2 x 2 x 2 array of long
    dp[0][1][1] = 1  // carry 0, a active, b active

    for each target digit d in digits:
        next = zeroed 2 x 2 x 2 array
        for carry in {0, 1}:
            for activeA in {0, 1}:
                for activeB in {0, 1}:
                    ways = dp[carry][activeA][activeB]
                    if ways == 0: continue

                    for digitA in allowedDigits(activeA):
                        for digitB in allowedDigits(activeB):
                            sum = digitA + digitB + carry
                            if sum % 10 != d: continue
                            nextCarry = sum / 10

                            for nextActiveA in allowedNextFlags(activeA):
                                for nextActiveB in allowedNextFlags(activeB):
                                    next[nextCarry][nextActiveA][nextActiveB] += ways
        dp = next

    return count of terminal states with carry 0 and both positive numbers valid
}

For a simpler but slightly more verbose implementation, a recursive memoized DFS over (pos, carry, stateA, stateB) is also accepted. The state count is tiny: at most about 16 * 2 * 2 * 2 for the given constraint.

Reimplementation Checklist

  • Use long/long long/int64 for n and the answer.
  • Process digits from least significant to most significant so carry flows naturally.
  • Never allow a real digit of a or b to be 0.
  • Allow a number to end before the highest digit of n, then pad later positions with zeroes.
  • Require final carry 0 after all digits of n are processed.
  • Count ordered pairs: (2, 9) and (9, 2) are different.
  • Test single-digit values, powers of ten, values containing zeroes, and values like 11 where shorter addends are valid.

Wrong But Tempting

  • Looping over all a. It is easy to write and works for small examples, but it is too slow for n near 10^15.
  • Only checking each digit of n independently. Carries couple neighboring digits, so a per-digit multiplication formula without carry state is wrong.
  • Forgetting shorter addends. For n = 11, the valid answers are one-digit plus one-digit; a DP that forces both numbers to have the same length as n misses them.
  • Allowing internal zeroes after a number has started. A real digit 0 is forbidden; only padding positions beyond the length of the number may be zero.
  • Counting unordered pairs. The examples confirm ordered counting.

Failure Patterns From Stats

The stats record one failed submission status: Wrong Answer. The local accepted solutions suggest the likely failure modes are semantic rather than performance-related:

  • Terminal-state mistakes around numbers shorter than n.
  • Confusing real zero digits with leading padding zeroes.
  • Wrong carry direction in a top-down implementation that traverses most-significant-first.
  • Returning only states where both addends remain active at the end, or only states where both are inactive, without matching the chosen state convention.
