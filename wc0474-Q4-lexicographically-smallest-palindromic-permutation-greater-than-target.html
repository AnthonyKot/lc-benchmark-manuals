Problem Statement

Given lowercase strings s and target of equal length n, return the lexicographically smallest string that is both a palindromic permutation of s and strictly greater than target. If no such permutation exists, return the empty string.

Constraints: 1 <= n == s.length == target.length <= 300; both strings contain only lowercase English letters.

Problem Essence

A palindrome is completely determined by its left half and, for odd lengths, one middle character. So the search space is not all permutations of s; it is all permutations of the multiset count[c] / 2 for the left half, with the middle fixed by the one odd-count character if any.

The lexicographic comparison against target can usually be decided by the left half. If we can reuse target's left half, the mirrored full palindrome might already be greater because of the middle or right side. Otherwise, we need the next multiset permutation of the left half that is strictly greater than target's left half.

Worked Example

For s = "baba" and target = "abba":

  1. Counts are a:2, b:2, so a palindrome is possible.
  2. The left-half multiset is {a:1, b:1}.
  3. The target left half is "ab", which can be formed.
  4. Mirroring "ab" gives "abba", which is not strictly greater than the target.
  5. The next left-half multiset permutation after "ab" is "ba".
  6. Mirroring "ba" gives "baab", the smallest valid answer.

Decision Rule / Algorithm

  1. Count all letters in s. If more than one count is odd, return "". This single test works for both even and odd n: even lengths cannot have odd counts; odd lengths can have exactly one.
  2. Build halfCounts[c] = count[c] / 2. Record the odd-count character as middle when n is odd.
  3. Let m = n / 2 and bound = target[0:m].
  4. If bound can be formed from halfCounts, build bound + middle + reverse(bound). If that full palindrome is strictly greater than target, return it.
  5. Otherwise compute the smallest half-string that is greater than bound using the same multiset. The accepted greedy form keeps the longest feasible prefix equal to bound, bumps one position to the smallest larger available character, then fills the suffix in ascending order.
  6. If no such bumped half exists, return "". Otherwise mirror the bumped half around the middle and return the full palindrome.
Because n <= 300 and the alphabet size is 26, repeatedly scanning all letters is cheap. The important part is avoiding factorial enumeration of half permutations.

Implementation Skeleton

function lexPalindromicPermutation(s, target):
    n = len(s)
    count = frequency(s)

    oddCount = number of letters with odd count
    if oddCount > 1:
        return ""

    middle = odd-count letter, if any
    halfCounts[c] = count[c] // 2
    m = n // 2
    bound = target[0:m]

    if canForm(halfCounts, bound):
        p = buildPalindrome(bound, middle, n is odd)
        if p > target:
            return p

    half = nextHalfGreaterThan(halfCounts, bound)
    if half does not exist:
        return ""
    return buildPalindrome(half, middle, n is odd)

function nextHalfGreaterThan(counts, bound):
    for pivot from len(bound) - 1 down to 0:
        temp = counts after consuming bound[0:pivot]
        if prefix cannot be consumed:
            continue
        choose smallest c > bound[pivot] with temp[c] > 0
        if found:
            return bound[0:pivot] + c + all remaining chars sorted ascending
    return none

Reimplementation Checklist

  • Reject impossible palindromes before comparing against target.
  • Use half-counts, not full counts, when constructing the left half.
  • Always verify the full palindrome when the left half equals target's left half; the right half can decide strictness.
  • When bumping the left half, fill the rest with the smallest available letters to preserve minimality.
  • For odd n, place the odd-count character in the middle; do not treat it as another free half character.
  • Return an empty string, not null or a smallest non-greater palindrome, when no valid candidate exists.

Wrong But Tempting

  • Generating all palindromic permutations and sorting them. This is unnecessary and can explode combinatorially.
  • Only checking whether the left half is greater than target's left half. Equal left halves can still succeed or fail based on the middle and mirrored suffix.
  • Using the ordinary next permutation of target[0:m] without checking whether that prefix is available from s's half multiset.
  • Forgetting that a string equal to target is invalid; the answer must be strictly greater.
  • For odd lengths, picking the middle greedily from remaining characters after half construction. The middle is fixed by parity.

Accepted Algorithm Families

  • Half-multiset next-permutation greedy: The Java and Go submissions center on checking target's half, then finding the next feasible half by pivoting and filling the suffix in sorted order. This is the cleanest family for reimplementation.
  • DFS over palindrome positions with lexicographic pruning: The JavaScript submission recursively chooses paired characters from left to right, never choosing below the target unless already greater. With only 26 letters and n <= 300, pruning keeps it accepted.
  • Full-index pivot construction: The Python submission scans possible pivot positions in the full palindrome, handles symmetry constraints, and constructs the minimal suffix after the pivot. It is more intricate but captures the same lexicographic rule.
