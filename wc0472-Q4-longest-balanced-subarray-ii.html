Problem Statement

You are given an integer array nums. A non-empty subarray is balanced when the number of distinct even values in it equals the number of distinct odd values in it. Return the length of the longest balanced subarray.

Constraints: 1 <= nums.length <= 100000 and 1 <= nums[i] <= 100000.

Problem Essence

The hard part is that duplicates should count only once inside a subarray. A normal prefix sum over parity fails because adding a repeated value must not change the distinct-even or distinct-odd count for every possible start.

The key representation is: for a fixed sweep boundary, each distinct value contributes exactly one signed event at the occurrence that matters for that boundary. Use +1 for one parity and -1 for the other. Then a subarray is balanced exactly when the signed distinct count difference is zero.

A lazy segment tree stores the possible prefix or start values under range additions. Its min and max fields can prove whether a target value, usually zero or the current prefix value, exists in a queried range.

Worked Example

For nums = [2, 5, 4, 3], the full array has distinct evens {2, 4} and distinct odds {5, 3}. The counts are both two, so the longest balanced subarray is the full array and the answer is 4.

In the segment-tree view, each first occurrence contributes a signed parity value. The prefix difference returns to zero at the last index, so the queried zero position gives the full span.

Decision Rule / Algorithm

Use one of the two equivalent accepted segment-tree sweeps.

Left-boundary sweep

  1. Compute next[i], the next occurrence of nums[i], or n if absent.
  2. Build an initial signed event array from first occurrences only. Either sign convention works if updates are consistent.
  3. Build prefix values over those events in a segment tree storing min, max, and lazy range-add tags.
  4. For each left boundary l, query the rightmost index r >= l whose segment-tree value is zero. If found, update ans = max(ans, r - l + 1).
  5. Move l forward: remove this occurrence's contribution over its active prefix range, then activate the next occurrence of the same value if it exists.

Right-boundary sweep

  1. Sweep r from left to right and keep lastPos[value].
  2. When a value appears for the first time, add its signed contribution to all starts that include it.
  3. When a value repeats, move its contribution from the previous occurrence to the new occurrence using one or two range additions.
  4. Query the earliest valid start whose stored value matches the current target difference. Earlier start means longer subarray.

Both forms are O(n log n) time and O(n + V) memory, with V <= 100000 from the constraints.

Implementation Skeleton

function longestBalanced(nums):
    n = len(nums)
    build occurrence metadata: next[] for left sweep or lastPos[] for right sweep
    initialize lazy segment tree with arrays min[], max[], lazy[]
    ans = 0

    for each sweep boundary:
        update segment tree ranges so each distinct value has one active signed contribution
        query for a zero/current-difference match in the valid index range
        if found:
            ans = max(ans, computed length)

    return ans

segment tree node stores:
    min value in interval
    max value in interval
    lazy add tag

range_add(node, ql, qr, delta):
    add delta to node min/max/lazy when covered
    otherwise push, recurse, then pull min/max

query_match(node, range, target):
    skip node if target < min or target > max
    descend toward the side that optimizes length:
        leftmost start for right sweep
        rightmost end for left sweep

Reimplementation Checklist

  • Choose and document one sign convention; do not mix +1 for even in one update and +1 for odd in another.
  • Represent duplicate handling by moving a value's single active contribution, not by counting every occurrence.
  • Segment tree must support range add and must keep both min and max.
  • Query direction matters: find the earliest start in a right sweep, or the latest end in a left sweep.
  • Guard empty update ranges such as ql > qr.
  • Use arrays for lastPos when relying on nums[i] <= 100000; otherwise use a hash map.
  • For Python, raise recursion depth or write iterative helpers for deep segment-tree recursion.

Wrong But Tempting

  • Using a plain parity prefix sum over all elements. This solves equal number of even and odd positions, not equal number of distinct even and odd values.
  • Sliding window with two frequency maps and shrinking greedily. Balance is not monotonic, so local shrinking decisions can discard the optimal interval.
  • Checking all starts for every end with sets. It is conceptually simple but becomes O(n^2) and will time out at 100000 elements.
  • Only storing a segment-tree minimum. A target can exist between min and max; accepted solutions use both to prune correctly.
  • Returning as soon as any balanced interval is found. The task asks for the longest interval.

Accepted Algorithm Families

Lazy segment tree, left sweep

Seen in accepted__set2-codex-agent-gpt-5.5-codex-java__java.java. It precomputes next occurrences, maintains first-occurrence contributions for the current left boundary, and queries the rightmost zero.

Lazy segment tree, right sweep

Seen in the Go, Java, and Python accepted files. It tracks last occurrences while extending the right boundary and queries the earliest compatible start.

No accepted local file uses a pure hash-map prefix-sum solution; duplicates force range updates, which is why the accepted family centers on segment trees.

Failure Patterns From Stats

stats.json reports failed submission statuses: Wrong Answer: 2 and Time Limit Exceeded: 1.

  • The wrong answers likely correspond to duplicate-count mistakes, off-by-one query ranges, or inconsistent sign updates. These are the most fragile parts of this problem.
  • The time-limit failure matches the natural brute-force trap: rebuilding distinct sets or scanning many starts for every end is too slow for n = 100000.
  • Segment-tree queries must prune by min/max; descending without pruning can degenerate badly.
