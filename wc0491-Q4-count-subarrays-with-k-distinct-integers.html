Count Subarrays With K Distinct Integers

Problem Statement

You are given an integer array nums and two integers k and m.

Return the number of non-empty subarrays such that the subarray contains exactly k distinct integers and every distinct integer present in the subarray appears at least m times.

Constraints: 1 <= nums.length <= 100000, 1 <= nums[i] <= 100000, and 1 <= k, m <= nums.length.

Problem Essence

For each possible left boundary, valid right boundaries form a contiguous suffix inside the range where the window still has at most k distinct values. The first right boundary must make all k values reach frequency at least m; the last right boundary is just before a (k+1)th distinct value would enter.

The count for a fixed left is therefore:

number of valid rights = maxRightAtMostK - minRightAllMature + 1

when the minimal mature window exists; otherwise it contributes zero.

Worked Example

For nums = [1,2,1,2,2], k = 2, m = 2, the answer is 2.

SubarrayDistinct countFrequenciesValid?
[1,2,1,2]2{1:2, 2:2}yes
[1,2,1,2,2]2{1:2, 2:3}yes

For left index 0, the minimal right that makes both distinct values appear twice is index 3. The maximal right with at most two distinct values is index 4. That gives two valid endings: 3 and 4.

Other Official Examples

For nums = [3,1,2,4], k = 2, m = 1, the answer is 3.

SubarrayDistinct countFrequencies
[3,1]2{3:1, 1:1}
[1,2]2{1:1, 2:1}
[2,4]2{2:1, 4:1}

Because m = 1, every present value is already mature. The problem reduces to counting subarrays with exactly two distinct values.

Decision Rule / Algorithm

The clearest accepted linear algorithm uses two sliding windows anchored at the same left boundary.

  1. Maintain window A with counts, distinctA, and validA, where validA is the number of distinct values whose count is at least m. Expand its right pointer until either the window has exactly k distinct values and all k are mature, or adding a new value would exceed k distinct values.
  2. Maintain window B with counts and distinctB. Expand its right pointer as far as possible while keeping at most k distinct values.
  3. If window A is valid, add rightB - rightA + 1. Every end from the minimal mature end through the maximal at-most-k end is valid.
  4. Remove nums[left] from both windows and advance left.

Use long/long long/int64 for the answer, because the number of subarrays can be quadratic in n.

Implementation Skeleton

long countSubarrays(nums, k, m):
    n = nums.length
    freqNeed = zero array or map
    freqLimit = zero array or map
    rightNeed = 0
    rightLimit = 0
    distinctNeed = 0
    matureNeed = 0
    distinctLimit = 0
    ans = 0

    for left in 0 .. n-1:
        while rightNeed < n:
            if distinctNeed == k and matureNeed == k:
                break
            x = nums[rightNeed]
            if freqNeed[x] == 0 and distinctNeed == k:
                break
            if freqNeed[x] == 0:
                distinctNeed += 1
            freqNeed[x] += 1
            if freqNeed[x] == m:
                matureNeed += 1
            rightNeed += 1

        while rightLimit < n:
            x = nums[rightLimit]
            if freqLimit[x] == 0 and distinctLimit == k:
                break
            if freqLimit[x] == 0:
                distinctLimit += 1
            freqLimit[x] += 1
            rightLimit += 1

        if distinctNeed == k and matureNeed == k:
            ans += rightLimit - rightNeed + 1

        y = nums[left]
        if freqNeed[y] == m:
            matureNeed -= 1
        freqNeed[y] -= 1
        if freqNeed[y] == 0:
            distinctNeed -= 1

        if freqLimit[y] == 1:
            distinctLimit -= 1
        freqLimit[y] -= 1

    return ans

The skeleton uses exclusive right pointers, matching the fastest Java accepted file. If using inclusive right pointers, adjust the final addition accordingly.

Reimplementation Checklist

  • Return type is 64-bit.
  • Frequency storage handles values up to 100000; an array is faster than a hash map in Java, JavaScript, C++, and Python here.
  • When a count rises from m - 1 to m, increment the mature-value counter exactly once.
  • When removing the left value, decrement the mature counter before lowering the frequency if the old count is exactly m.
  • Do not let the minimal-mature window include more than k distinct values.
  • Do not count a left boundary unless distinct == k and mature == k.
  • Test m = 1, k = 1, all equal values, all distinct values, and cases where no answer exists.

Wrong But Tempting

  • Plain exactly-k distinct: Counting atMost(k) - atMost(k-1) without enforcing the frequency threshold accepts windows where some value appears fewer than m times.
  • Only checking total length: A window of length at least k * m is not enough; the counts can be uneven.
  • Shrinking the mature window greedily after it becomes valid: If the pointer is moved past the first valid right for a fixed left, the count of valid endings is off.
  • Using 32-bit answer storage: With n = 100000, the answer may exceed 2^31 - 1.
  • Forgetting the transition at exactly m: Incrementing mature count for every count above m inflates the validity test.

Failure Patterns From Stats

The stats show more Time Limit Exceeded submissions than Wrong Answer submissions: 6 TLE, 4 WA, and 1 Compile Error. That points to two main risks.

  • TLE risk: Checking every subarray or recomputing distinct/frequency maps per start is too slow for n = 100000. Even O(n sqrt n) style experiments are risky compared with the accepted O(n) windows.
  • WA risk: The validity condition combines exactly k distinct with all counts at least m. It is easy to count windows where only the distinct count is right, or where only k values are mature but an extra immature distinct value is also present.
  • Compile risk: Keep the function signature exactly as supplied by the platform; Java returns long, not int.
