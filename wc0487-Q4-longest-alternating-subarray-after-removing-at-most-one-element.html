Problem Statement

You are given an integer array nums. A subarray is alternating when its adjacent strict comparisons alternate, for example a0 < a1 > a2 < a3 or a0 > a1 < a2 > a3. Equal adjacent values break alternation because the comparisons must be strict.

You may remove at most one element from the original array, then choose one contiguous subarray from the remaining array. Return the maximum possible length of an alternating subarray. A length-1 subarray is always alternating.

Constraints: 2 <= nums.length <= 100000, 1 <= nums[i] <= 100000.

Problem Essence

The array can be understood through the signs of adjacent comparisons: + for increasing, - for decreasing, and 0 for equal. A valid alternating subarray is a contiguous run whose signs are nonzero and flip every step. Removing one element either does nothing useful, removes an endpoint, or removes a middle element so that nums[i-1] and nums[i+1] become adjacent and may bridge two alternating runs.

The core task is therefore to know how long an alternating run can extend into each side of a candidate deletion, with the comparison direction at the boundary preserved.

Worked Example

For nums = [3,2,1,2,3,2,1], the original signs are -,-,+,+,-,-, so the whole array is not alternating. Removing the middle 2 at index 3 gives [3,2,1,3,2,1]. The subarray [2,1,3,2] has signs -,+,-, so it is alternating and has length 4.

Using the bridge rule at deletion index 3, compare nums[2]=1 with nums[4]=3. The bridge sign is increasing. The left side ending at index 2 must end with a decreasing sign, and the right side starting at index 4 must continue with a decreasing sign. Those compatible pieces combine to length 4.

Decision Rule / Algorithm

The most direct accepted approach follows the official hints:

  1. Compute left[i][0] and left[i][1], the longest alternating subarray ending at i, where the last comparison is respectively < or >. Initialize every state to 1.
  2. Compute right[i][0] and right[i][1], the longest alternating subarray starting at i, where the first comparison is respectively < or >.
  3. Update the answer with all no-deletion states.
  4. For every removable middle index r from 1 to n-2, compare nums[r-1] and nums[r+1]. If they are equal, this deletion cannot bridge the two sides. If the bridge is <, combine the left state ending with < before the removed element and the right state that starts with > after the removed element. If the bridge is >, combine the symmetric states.

Equivalently, many accepted submissions store "up" and "down" states. The naming differs by language, but the invariant is the same: after adding a comparison of one direction, the previous comparison must have had the opposite direction.

Implementation Skeleton

def longestAlternating(nums):
    n = len(nums)
    left_up = [1] * n      # last comparison nums[i-1] < nums[i]
    left_down = [1] * n    # last comparison nums[i-1] > nums[i]

    for i in range(1, n):
        if nums[i - 1] < nums[i]:
            left_up[i] = left_down[i - 1] + 1
        elif nums[i - 1] > nums[i]:
            left_down[i] = left_up[i - 1] + 1

    right_up = [1] * n     # first comparison nums[i] < nums[i+1]
    right_down = [1] * n   # first comparison nums[i] > nums[i+1]

    for i in range(n - 2, -1, -1):
        if nums[i] < nums[i + 1]:
            right_up[i] = right_down[i + 1] + 1
        elif nums[i] > nums[i + 1]:
            right_down[i] = right_up[i + 1] + 1

    ans = max(max(left_up), max(left_down))
    for r in range(1, n - 1):
        if nums[r - 1] < nums[r + 1]:
            ans = max(ans, left_down[r - 1] + right_down[r + 1])
        elif nums[r - 1] > nums[r + 1]:
            ans = max(ans, left_up[r - 1] + right_up[r + 1])
    return ans

Note: Some accepted code uses the opposite names for up/down, depending on whether the direction is described from left to right or as a local peak/valley. The essential check is that adjacent comparison signs are strict and alternate.

Reimplementation Checklist

  • Return at least 1 for every valid input.
  • Treat equality as a hard reset; do not extend through nums[i] == nums[i+1].
  • Count elements, not comparisons. Combining two sides around a deletion adds the two element lengths because the removed element is absent.
  • Only try bridge deletions for indices 1..n-2. Deleting an endpoint is already covered by taking a subarray without that endpoint.
  • When bridging, compare nums[r-1] to nums[r+1], not either side to the removed value.
  • Keep the bridge direction compatible with both neighboring runs.
  • Use O(n) time. O(n) memory is straightforward; a rolling-state DP can reduce memory to O(1).

Wrong But Tempting

  • Deleting the first local violation greedily. A later deletion can produce a longer bridge, so each middle index must be considered or encoded in DP state.
  • Allowing equal values as either direction. Strict alternation means equality always breaks the chain and an equal bridge cannot connect two sides.
  • Taking left length plus right length plus one. The removed element is gone, so the combined length is just the kept left elements plus the kept right elements.
  • Using only one length per index. The boundary comparison direction matters. A long run ending with the wrong sign may not be bridgeable.
  • Forgetting no deletion. The best answer may be the original array or a subarray of it.

Accepted Algorithm Families

Prefix/suffix dynamic programming

This is the clearest family and appears in Python, JavaScript, Java, Rust, and other submissions. It precomputes alternating lengths ending at each index and starting at each index by direction, then tests each deletion as a bridge. It uses O(n) time and O(n) memory.

Rolling one-pass dynamic programming

Several accepted solutions keep four states: no deletion ending up/down and one deletion ending up/down. The one-deletion state can extend from a prior one-deletion state or delete i-1 and bridge i-2 to i. This reaches O(n) time and O(1) memory, but the state naming and initialization are easier to get wrong.

Direction-run arrays

Some JavaScript submissions store one length plus one boundary direction for the best run ending or starting at an index. This is equivalent to two directional DP states as long as the implementation checks compatibility before combining.
