Problem Statement

You are given an undirected tree with n nodes numbered from 0 to n - 1, represented by edges. You are also given group, where group[i] is the group label of node i.

For every unordered pair of distinct nodes (u, v) with group[u] == group[v], the interaction cost is the number of edges on the unique tree path from u to v. Return the sum of those interaction costs over all valid same-group pairs.

Constraints: 1 <= n <= 100000, edges.length == n - 1, group.length == n, 1 <= group[i] <= 20, and edges is a valid tree.

Problem Essence

Do not try to enumerate pairs. A pair contributes one unit of distance for every edge on the path between its two endpoints. Therefore, for each edge, count how many same-group pairs have endpoints on opposite sides of that edge. Summing those edge crossings over all edges is exactly the sum of all same-group distances.

If the tree is rooted at 0, every non-root node u represents the edge parent[u] - u. For a group g, let c be the number of group-g nodes inside u's subtree, and total[g] be the total number of group-g nodes in the whole tree. That edge contributes c * (total[g] - c).

Worked Example

Example 1: n = 3, edges = [[0,1],[1,2]], group = [1,1,1].

Root at 0. Total count for group 1 is 3.

EdgeSubtree side count cContribution c * (total - c)
1 - 211 * (3 - 1) = 2
0 - 122 * (3 - 2) = 2

Total: 2 + 2 = 4. This matches the pair distances dist(0,1)=1, dist(1,2)=1, and dist(0,2)=2.

Decision Rule / Algorithm

  1. Build an adjacency list for the tree.
  2. Count total[g] for group labels 1..20.
  3. Root the tree at node 0 and produce a parent array plus traversal order using an iterative DFS or BFS. Avoid recursive DFS in languages with shallow default stacks.
  4. Process nodes in reverse traversal order so children are handled before parents.
  5. Maintain subtree group counts. For each non-root node u and each group g, add subtreeCount[u][g] * (total[g] - subtreeCount[u][g]) to the answer.
  6. Merge u's group counts into parent[u].

The complexity is O(n * G) time and O(n * G) memory for G = 20, which is effectively linear. The per-group variant is also O(n * G) time and can use O(n) extra count memory for one group at a time.

Implementation Skeleton

function interactionCosts(n, edges, group):
    adj = adjacency list of size n
    for (u, v) in edges:
        adj[u].append(v)
        adj[v].append(u)

    total[1..20] = 0
    for g in group:
        total[g] += 1

    parent = array filled with -1
    order = []
    stack = [0]
    parent[0] = 0
    while stack is not empty:
        u = stack.pop()
        order.append(u)
        for v in adj[u]:
            if parent[v] == -1:
                parent[v] = u
                stack.push(v)

    cnt = n by 21 zero matrix
    ans = 0 as 64-bit integer

    for u in reversed(order):
        cnt[u][group[u]] += 1
        for v in adj[u]:
            if parent[v] == u:
                for g in 1..20:
                    c = cnt[v][g]
                    ans += c * (total[g] - c)
                    cnt[u][g] += c

    return ans

An equivalent layout initializes cnt[i][group[i]] = 1 before the reverse loop, then for each non-root u adds contributions from cnt[u] and merges into parent[u].

Reimplementation Checklist

  • Use a 64-bit answer type: Java long, Go int64, C++ long long, Python int, JavaScript number is still exact here because the maximum is below 2^53.
  • Remember group labels are one-based and bounded by 20; allocate length 21.
  • Each non-root node corresponds to exactly one cut edge, the edge to its parent.
  • Compute contributions before merging a child subtree into its parent.
  • Skip recursion unless the language/runtime stack is explicitly safe for 100000 nodes.
  • For n = 1, the reverse loop naturally returns 0; an early return is optional.

Wrong But Tempting

  • Enumerating all same-group pairs and computing distances with LCA. This can be quadratic when one group contains most nodes.
  • Adding only direct same-group edges. A pair contributes across every edge on its path, including edges whose endpoints may have unrelated labels.
  • Using c * c or combinations within the subtree. The edge needs pairs split across the cut, so the other side has total[g] - c nodes.
  • Counting both directions of an edge. Rooting the tree and only processing non-root nodes avoids double counting.
  • Using 32-bit integer arithmetic for the answer. A path tree with many equal labels has a distance sum on the order of n^3.

Accepted Algorithm Families

All groups in one postorder pass

Most accepted Java, Go, and Python submissions keep subtree_counts[node][group]. They build a parent/order array iteratively, process order backward, add c * (total[g] - c) for every child edge and group, then merge the child counts upward. This is the clearest and least error-prone family.

One group at a time

The JavaScript accepted submission and one Java submission loop over group labels and reuse a one-dimensional sub or cnt array. For each group, mark nodes in that group, accumulate subtree counts in postorder, and add the same cut contribution. This trades repeated scans for lower count-array memory.

Traversal variations

Both DFS stacks and BFS queues are accepted for creating a rooted traversal order. The only requirement is that reversing the order processes children before parents.
