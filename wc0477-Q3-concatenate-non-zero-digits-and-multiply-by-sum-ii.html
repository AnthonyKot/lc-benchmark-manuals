Problem Statement

You are given a digit string s of length m and queries [l, r]. For each query, take the substring s[l..r], remove every zero, concatenate the remaining digits in their original order into an integer x, compute the sum of those non-zero digits, and return x * sum modulo 1_000_000_007. If the substring has no non-zero digits, x = 0 and the answer is 0.

Constraints are 1 <= s.length <= 100000 and 1 <= queries.length <= 100000, so building the concatenated number per query is too slow.

Problem Essence

Zeros only affect which original positions are inside a query; they do not contribute to the compressed number or its digit sum. The problem becomes range extraction over the sequence of non-zero digits, while still mapping each original query boundary into that compressed sequence.

For compressed non-zero digits d[0..k-1], maintain prefix number P[i+1] = P[i] * 10 + d[i] modulo MOD. Then the concatenated number for compressed interval [a, b] is (P[b+1] - P[a] * 10^(b-a+1)) mod MOD.

Decision Rule / Algorithm

  1. Scan s. Store each non-zero digit's original position in pos and digit value in digits.
  2. Precompute pow10[i] = 10^i mod MOD up to the number of non-zero digits.
  3. Build prefNum, where prefNum[i+1] is the modulo value of concatenating digits[0..i].
  4. Build prefSum, where prefSum[i+1] is the sum of digits[0..i].
  5. For a query [l, r], find a = lower_bound(pos, l) and b = upper_bound(pos, r) - 1.
  6. If a > b, return 0.
  7. Let len = b - a + 1. Compute x = (prefNum[b+1] - prefNum[a] * pow10[len]) mod MOD.
  8. Compute sum = prefSum[b+1] - prefSum[a] and return x * (sum mod MOD) mod MOD.

This gives O(n + q log n) time with binary searches and O(n) memory. A variant using original-index prefix counts gives O(n + q) time.

Implementation Skeleton

MOD = 1_000_000_007

pos = []
digits = []
for i, ch in enumerate(s):
    if ch != '0':
        pos.append(i)
        digits.append(int(ch))

k = len(digits)
pow10 = [1] * (k + 1)
prefNum = [0] * (k + 1)
prefSum = [0] * (k + 1)

for i in range(k):
    pow10[i + 1] = pow10[i] * 10 % MOD
    prefNum[i + 1] = (prefNum[i] * 10 + digits[i]) % MOD
    prefSum[i + 1] = prefSum[i] + digits[i]

ans = []
for l, r in queries:
    a = lower_bound(pos, l)
    b = upper_bound(pos, r) - 1
    if a > b:
        ans.append(0)
    else:
        length = b - a + 1
        x = (prefNum[b + 1] - prefNum[a] * pow10[length]) % MOD
        total = prefSum[b + 1] - prefSum[a]
        ans.append(x * (total % MOD) % MOD)

Reimplementation Checklist

  • Use only non-zero digits in the concatenated-number prefix.
  • Map query boundaries from original positions to compressed positions with lower/upper bound, or with prefix counts over original indices.
  • Precompute powers of ten by compressed length, not original substring length.
  • Use 64-bit arithmetic for multiplication before taking modulo in Java, Go, C++, and similar languages.
  • Normalize subtraction with + MOD before the final modulo.
  • Return 0 for a query whose compressed interval is empty.
  • Keep digit sums exact or modulo MOD; both work because the final product is modulo MOD.

Wrong But Tempting

  • Using the original substring length in pow10. Zeros are removed, so only the count of non-zero digits in the query matters.
  • Summing all digits in the substring and then trying to separately adjust the number. The sum is harmless because zeros add nothing, but the number must be built from only non-zero digits.
  • Parsing x as an integer or string per query. With 100000 queries and long substrings, this becomes quadratic and can overflow.
  • Forgetting to handle all-zero ranges. Prefix subtraction may produce 0, but bounds like b = a - 1 must be detected before indexing.
  • Using floating-point powers. Modular powers of ten must be integer recurrence values.

Failure Patterns From Stats

The stats record one failed submission status: Wrong Answer. The available accepted files point to the most likely wrong-answer risks:

  • Using the wrong exponent when cutting a prefix number. The exponent must be the compressed interval length, not r - l + 1.
  • Getting inclusive/exclusive query bounds wrong when converting from original positions to compressed indices.
  • Missing modulo normalization after subtracting prefix contributions.
  • Returning a non-zero value for all-zero substrings because the empty compressed interval was not checked.
