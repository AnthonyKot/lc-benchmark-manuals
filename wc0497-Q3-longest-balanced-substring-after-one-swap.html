Longest Balanced Substring After One Swap

Provenance

Problem id: wc0497-Q3-longest-balanced-substring-after-one-swap

Source artifacts used: problem.md, stats.json, and 16 local accepted__* submissions.

Function: longestBalanced(s), arity 1. Difficulty: Medium. Constraint: 1 <= s.length <= 100000; s is binary.

Problem Statement

You are given a binary string s. A string is balanced if it has the same number of 0 and 1 characters. You may perform at most one swap between any two positions in the whole string, then choose a balanced substring. Return the maximum possible length of such a substring.

The empty substring is balanced, so the answer can be 0 when the string has only one character kind.

Problem Essence

The swap matters only through the selected substring's character counts. If the chosen substring is already balanced, no swap is needed. If it has two more 1s than 0s, it can become balanced by swapping one inside 1 with one outside 0. If it has two more 0s than 1s, it can become balanced by swapping one inside 0 with one outside 1.

Therefore a candidate substring needs prefix-balance difference 0, +2, or -2. The +2 case also needs at least one 0 outside the substring. The -2 case also needs at least one 1 outside the substring.

Worked Example

For s = "100001", the answer is 4.

  1. Total counts are four 0s and two 1s, so no answer can exceed 2 * min(4, 2) = 4.
  2. Swap the middle 0 at index 2 with the final 1. The string becomes "101000".
  3. The substring "1010" has two 0s and two 1s, so length 4 is reachable and optimal.

Other Official Examples

InputOutputReason
"100001"4One swap creates a balanced substring of length 4.
"111"0There are no 0s, so no non-empty balanced substring is possible.

Decision Rule / Algorithm

Use a prefix balance P with +1 for 1 and -1 for 0. For substring [l, r), its imbalance is P[r] - P[l].

  • P[r] - P[l] == 0: already balanced.
  • P[r] - P[l] == 2: two extra 1s; valid only if not all zeros of the whole string lie inside [l, r).
  • P[r] - P[l] == -2: two extra 0s; valid only if not all ones of the whole string lie inside [l, r).

The accepted implementations use two equivalent families:

  • Prefix-sum buckets with earliest and latest positions for each balance value.
  • Linear arrays over the balance range [-n, n], recording first occurrences and adjusted first occurrences after the first global 0 or 1.

A clean linear implementation scans prefix positions from left to right. For each right endpoint r, it asks for the earliest compatible l with balance P[r], P[r] - 2, and P[r] + 2. If the earliest one-swap candidate would cover every needed outside character, switch to the earliest occurrence that starts after the first such character.

Implementation Skeleton

def longestBalanced(s):
    n = len(s)
    P = [0] * (n + 1)
    count zeros, ones, first_zero, last_zero, first_one, last_one

    for i, ch in enumerate(s):
        P[i + 1] = P[i] + (1 if ch == '1' else -1)

    first[value] = earliest prefix index with this balance
    first_after_first_zero[value] = earliest prefix index > first_zero
    first_after_first_one[value] = earliest prefix index > first_one

    ans = 0
    for r in range(0, n + 1):
        v = P[r]

        record first[v] and the adjusted first arrays for this prefix index

        # no swap: P[r] - P[l] == 0
        ans = max(ans, r - first[v])

        # too many 1s: need an outside 0, so substring must not cover every 0
        l = first[v - 2]
        if l exists:
            if not (l <= first_zero and r > last_zero):
                ans = max(ans, r - l)
            else use first_after_first_zero[v - 2] if it exists

        # too many 0s: need an outside 1, so substring must not cover every 1
        l = first[v + 2]
        if l exists:
            if not (l <= first_one and r > last_one):
                ans = max(ans, r - l)
            else use first_after_first_one[v + 2] if it exists

    return ans

Use an offset such as n or n + 2 when storing balances in arrays, because balances range from -n to n.

Reimplementation Checklist

  • Return an even length; the prefix-difference rule naturally does this.
  • Handle all-zero and all-one strings; one of the one-swap branches must be disabled and the answer may be 0.
  • Include prefix index 0 and prefix index n.
  • For +2, check for an outside 0; for -2, check for an outside 1.
  • Do not simulate swaps. The selected window's imbalance and outside availability are sufficient.
  • Keep the algorithm O(n) or O(n log n); quadratic window enumeration will not fit n = 100000.

Wrong But Tempting

Only computing the longest balanced substring before any swap. This misses windows with imbalance exactly 2 or -2.

Allowing any imbalance of absolute value 2. A swap can fix it only when the opposite character exists outside the selected substring.

Capping by 2 * min(total0, total1) and returning the cap blindly. The cap is necessary but not sufficient because the balanced characters must form a substring after one swap.

Greedy local swap near a longest run. The best window may be determined by prefix-balance positions far apart, not by local run structure.

Linear prefix arrays Java, JavaScript, C++, Rust, TypeScript variants Store first balance positions in arrays indexed by shifted balance; use first/last global positions of each character to validate outside availability. O(n) time, O(n) memory
Prefix buckets plus binary search Python variants Group prefix indices by balance and use sorted lists plus bisect or earliest/latest endpoints to find the longest valid 0, +2, or -2 window. O(n log n) or near-linear depending on bucket scan, O(n) memory
Suffix/prefix availability arrays Go variant Track next needed character, prefix/suffix availability, and last compatible prefix positions by balance. O(n) time, O(n) memory

Failure Patterns From Stats

stats.json records 4 failed submissions, all with status Wrong Answer. No Time Limit Exceeded or Memory Limit Exceeded failures are listed, which points to edge-case logic rather than raw complexity as the main failure mode.

  • Most likely wrong-answer source: forgetting the outside-character requirement for imbalance +2 or -2.
  • Another likely source: mishandling windows that include every 0 or every 1, where the needed incoming character does not exist outside.
  • All-one or all-zero cases must return 0, not 2.
