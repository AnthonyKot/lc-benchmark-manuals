Problem Statement

You are given an integer array nums of length n. In one operation, choose any non-empty subarray nums[l..r] and increase every element in that subarray by a positive integer x. The cost of that operation is x.

Return the minimum possible total operation cost needed to make the array non-decreasing, meaning nums[i] <= nums[i + 1] for every adjacent pair.

Constraints from the statement: 1 <= nums.length <= 100000 and 1 <= nums[i] <= 1000000000.

Problem Essence

Only adjacent drops matter. If nums[i] > nums[i + 1], the right side is too low by nums[i] - nums[i + 1], and at least that much paid increase must begin somewhere after index i. Because operations can cover any suffix-like portion of the remaining low run, those required payments add independently over all drops.

The answer is therefore:

sum(max(0, nums[i] - nums[i + 1]) for i in 0..n-2)

This is why short accepted solutions can simply scan adjacent pairs without actually modifying the array.

Other Official Examples

Example 2: nums = [5, 1, 2, 3]

The only drop is from 5 to 1, with difference 4. The answer is 4. Add 4 to subarray [1..3] to get [5,5,6,7].

The official sample set in stats.json contains exactly these two examples: [3,3,2,1] -> 2 and [5,1,2,3] -> 4.

Decision Rule / Algorithm

  1. Initialize ans = 0 using a 64-bit integer type where the language distinguishes integer widths.
  2. For each adjacent index i from 0 to n - 2, compare nums[i] and nums[i + 1].
  3. If nums[i] > nums[i + 1], add nums[i] - nums[i + 1] to ans.
  4. Return ans.

Why it is minimal: every descending edge creates an unavoidable deficit that must be paid by starting/increasing coverage on the right side of that edge. Why it is sufficient: pay each drop as a subarray increment over the portion to the right that needs that level, which can always be arranged to remove all descending edges.

Implementation Skeleton

class Solution:
    def minOperations(self, nums: list[int]) -> int:
        ans = 0
        for i in range(len(nums) - 1):
            if nums[i] > nums[i + 1]:
                ans += nums[i] - nums[i + 1]
        return ans
class Solution {
    public long minOperations(int[] nums) {
        long ans = 0;
        for (int i = 0; i + 1 < nums.length; i++) {
            if (nums[i] > nums[i + 1]) {
                ans += (long) nums[i] - nums[i + 1];
            }
        }
        return ans;
    }
}

Reimplementation Checklist

  • Use adjacent original values; do not simulate actual operations.
  • Add only positive drops: max(0, nums[i] - nums[i + 1]).
  • Use 64-bit accumulation in C++, Java, Go, Rust, C#, Kotlin, Scala, and C.
  • Handle n = 1 by returning 0; the loop naturally does this.
  • Keep time O(n) and extra memory O(1).

Wrong But Tempting

  • Raising every low value to the prefix maximum and summing all increments. For [5,1,2,3], that would charge 4 + 3 + 2 = 9, but one operation over [1..3] costs only 4.
  • Counting the number of operations instead of the sum of x values. The objective is total added operation magnitudes, not operation count.
  • Mutating the array greedily and then comparing changed neighbors incorrectly. The accepted direct formula works on original adjacent drops.
  • Using 32-bit answer storage. With up to 100000 elements and values near 1000000000, the sum of drops can exceed signed 32-bit range.

Accepted Algorithm Families

Dominant family Adjacent-drop summation. Most accepted files implement exactly ans += max(0, nums[i] - nums[i + 1]). This is the clearest and shortest form.

Equivalent family Required increment profile. Several accepted files track how much each position would need to be raised relative to a running final value or carried addition, then add only positive increases in that required amount. Algebraically this collapses to the same adjacent-drop sum.

Overcomplicated but accepted Slack/current-sum accounting. One Java solution tracks positive and negative local differences plus slack. It still computes the same total and is not recommended for reimplementation because it is harder to audit.
