The accepted code reveals two equivalent families. One follows the official hints literally by counting subsequences whose elements are multiples of g, then subtracting multiples to get exact GCD counts. The other uses the identity gcd(S) = sum(phi(d)) over d | gcd(S), so it can add phi(d) times the number of increasing subsequences made only from multiples of d.

Problem Statement

You are given an integer array nums of length n. For every positive integer g, the beauty of g is g multiplied by the number of strictly increasing nonempty subsequences of nums whose GCD is exactly g.

Return the sum of beauty values for all positive integers g, modulo 1_000_000_007.

  • 1 <= nums.length <= 10^4
  • 1 <= nums[i] <= 7 * 10^4

Problem Essence

Every counted object is a subsequence, so original order matters. The values inside that subsequence must be strictly increasing by value, not merely by index. The GCD requirement is the number-theory layer on top of a classic increasing-subsequence DP.

For a fixed divisor d, keep only numbers divisible by d. If a subsequence chosen from those numbers is strictly increasing in original values, it contributes to the count for every d dividing its GCD. A Fenwick tree over values, or scaled values x / d, counts such subsequences in order:

ways_ending_at_x = 1 + sum(ways_ending_at_y for y < x)

The hard part is doing this for many divisors without enumerating subsequences.

Worked Example

Example 1

Input: nums = [1,2,3]

Output: 10

SubsequenceGCD
[1]1
[2]2
[3]3
[1,2]1
[1,3]1
[2,3]1
[1,2,3]1

Exact GCD counts are F[1] = 5, F[2] = 1, and F[3] = 1. The answer is 1*5 + 2*1 + 3*1 = 10.

Using the phi identity gives the same answer. For each subsequence, summing phi(d) over all divisors of its GCD gives the GCD itself; for example, a subsequence with GCD 3 contributes phi(1)+phi(3)=1+2=3.

Decision Rule / Algorithm

Recommended: use the phi-weighted divisor family when implementing from scratch in a performance-sensitive language. It avoids a final descending subtraction pass and directly accumulates the final answer.

  1. Let M = max(nums) and MOD = 1_000_000_007.
  2. Precompute Euler's totient phi[1..M] with a sieve.
  3. Precompute divisors for each value, or loop multiples for each divisor depending on the language and memory tradeoff.
  4. For each divisor d, count strictly increasing subsequences using only elements divisible by d. Process retained elements in original index order. Query the Fenwick prefix below the current value, add one for the singleton, then update at the current value.
  5. Add phi[d] * countDivisible[d] to the answer.

Why phi works: a subsequence with GCD G is counted once for every divisor d of G. Its total added weight is sum_{d|G} phi[d], which equals G. That is exactly the desired beauty contribution of that subsequence.

Official-hint variant: compute cnt[g], the number of increasing subsequences where every element is divisible by g. Then process g downward and compute exact[g] = cnt[g] - exact[2g] - exact[3g] - .... The answer is sum(g * exact[g]).

Implementation Skeleton

MOD = 1_000_000_007
M = max(nums)
phi = euler_totient_sieve(M)
divs = divisors_for_each_value(M)

ans = 0

# Phi-weighted form:
for d in 1..M:
    bit.clear_or_use_versioning()
    total = 0
    for x in nums, in original order, where x % d == 0:
        rank = x / d       # or x if the BIT domain supports values directly
        add = 1 + bit.sum(rank - 1)
        bit.add(rank, add)
        total += add
    ans += phi[d] * total

return ans % MOD

For a faster implementation, avoid scanning all nums for every d. Accepted solutions either prebuild lists[d] by iterating each number's divisors, or pregroup positions by value and gather multiples of d.

Reimplementation Checklist

  • Process array elements in original order for each divisor group.
  • Use a strict Fenwick prefix query: current rank minus one, not current rank.
  • Include singleton subsequences with +1.
  • Take modulo after additions and subtractions; normalize negative values in the exact-GCD version.
  • Use long, int64, or JavaScript safe modular multiplication where needed for phi[d] * total.
  • Clear Fenwick state efficiently. Version stamps or touched-index cleanup are safer than clearing O(M) blindly for every divisor.
  • Do not coordinate-compress globally unless the query semantics still mean "strictly less than current scaled value" inside the current divisor group.
  • Confirm the implementation handles duplicates: equal values must not extend each other because the subsequence must be strictly increasing.

Wrong But Tempting

  • Counting all increasing subsequences once and trying to assign GCD later: the GCD distribution is the problem, and it cannot be recovered from only the total LIS-style DP.
  • Using nondecreasing transitions: querying <= x incorrectly allows equal values to chain.
  • Sorting the values for every divisor: this destroys subsequence order unless you sort only collected indices back into original index order.
  • Forgetting that cnt[g] is an overcount: it includes subsequences with GCD g, 2g, 3g, and so on.
  • Reusing a dirty Fenwick tree: stale values from a previous divisor silently inflate later counts.
  • Assuming the JavaScript accepted style is universally safe: product sizes stay within safe integer range only because both factors are modulo-sized and the code reduces frequently; BigInt or careful modular arithmetic may be needed if the structure changes.

Failure Patterns From Stats

stats.json records two failed submissions, both with status Time Limit Exceeded. This points to performance risk rather than a broad mix of wrong-answer edge cases.

  • Likely TLE cause: scanning all n elements for every possible g, which is O(nM log M) at n = 10^4 and M = 70000.
  • Likely TLE cause: rebuilding and sorting large temporary arrays for many divisors without reuse.
  • Likely TLE cause: clearing Fenwick arrays of size M for every divisor instead of clearing only touched ranges or using version stamps.
  • Likely TLE cause: high-overhead inner loops in Python or JavaScript, especially function calls inside BIT query/update.
