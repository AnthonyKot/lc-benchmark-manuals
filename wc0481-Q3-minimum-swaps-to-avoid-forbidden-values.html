Problem Statement

You are given two integer arrays, nums and forbidden, each of length n. In one operation, choose two distinct indices i and j, and swap nums[i] with nums[j].

Return the minimum number of swaps required so that every index satisfies nums[i] != forbidden[i]. If no sequence of swaps can make all indices valid, return -1.

Constraints: 1 <= n == nums.length == forbidden.length <= 10^5, and 1 <= nums[i], forbidden[i] <= 10^9.

Problem Essence

Only positions where nums[i] == forbidden[i] are immediately bad. Swapping two bad positions with different bad values can fix both at once. If one bad value dominates, each occurrence of that value needs its own swap partner, so the dominant count becomes the answer floor.

There is also a global feasibility condition: for every value v, the number of copies of v in nums plus the number of positions forbidding v must be at most n. Otherwise there are not enough positions where all copies of v can legally land.

Worked Example

Input: nums = [4,6,6,5], forbidden = [4,6,5,5]

Bad positions: index 0 has value 4, index 1 has value 6, index 3 has value 5. Thus badPairsSum = 3 and each bad value appears once, so maxBadPairs = 1.

Decision: max(ceil(3/2), 1) = 2. One optimal sequence swaps index 0 with 2, then index 1 with 3, producing [6,5,4,6].

Decision Rule / Algorithm

  1. Let n = nums.length.
  2. Count each value in nums and in forbidden.
  3. If any value has countNums[v] + countForbidden[v] > n, return -1.
  4. Scan all indices where nums[i] == forbidden[i]. Let badPairsSum be their count, and count those bad positions by value.
  5. Let maxBadPairs be the largest bad-position count for one value.
  6. Return max((badPairsSum + 1) / 2, maxBadPairs) using integer division.

The first term is the number of swaps needed if each swap fixes two bad positions. The second term handles an overrepresented bad value that cannot be paired with itself.

Implementation Skeleton

int minSwaps(nums, forbidden):
    n = len(nums)
    countNums = frequency map of nums
    countForbidden = frequency map of forbidden

    for each value v seen in nums or forbidden:
        if countNums[v] + countForbidden[v] > n:
            return -1

    badPairsSum = 0
    badByValue = empty frequency map
    for i in 0..n-1:
        if nums[i] == forbidden[i]:
            badPairsSum += 1
            badByValue[nums[i]] += 1

    maxBadPairs = maximum value in badByValue, or 0
    return max((badPairsSum + 1) // 2, maxBadPairs)

Reimplementation Checklist

  • Use hash maps because values can be as large as 10^9.
  • Check feasibility before returning a swap count.
  • Count only initially bad positions for the answer formula, not every occurrence of every value.
  • Use ceiling division (badPairsSum + 1) / 2 with integer arithmetic.
  • Handle the already-valid case naturally: if badPairsSum == 0, the formula returns 0.

Wrong But Tempting

  • Returning only ceil(badPairsSum / 2): fails when one value dominates the bad positions, because two identical bad values cannot fix each other.
  • Ignoring global feasibility: misses cases where too many copies of one value exist relative to the number of positions that permit it.
  • Trying to simulate swaps greedily: unnecessary and easier to get wrong; the count formula is enough.
  • Using arrays indexed by value: invalid for values up to 10^9.

Accepted Algorithm Families

  • Global frequency feasibility plus bad-position formula: used by the Go, Python, and most Java accepted files. These count nums, count forbidden, reject countNums[v] + countForbidden[v] > n, then return max(ceil(k/2), M).
  • Dominant-conflict feasibility: one Java solution first finds the most common bad value, then checks whether there are enough indices where both nums[i] and forbidden[i] are not that value. It returns the same answer formula for accepted cases.
  • Equivalent answer branch: one Java implementation writes if (2 * M <= k) return ceil(k/2); else return M;, which is the same as max(ceil(k/2), M).

Failure Patterns From Stats

stats.json reports no failed submission status counts: failed_submission_status_counts is empty. The main risk patterns therefore come from the accepted-code structure and official hints rather than recorded failed attempts.

  • Missing the feasibility check can produce a positive swap count for impossible inputs.
  • Miscounting maxBadPairs over all values instead of only bad positions overestimates the answer.
  • Using floating-point ceiling division is unnecessary and can introduce avoidable mistakes.
