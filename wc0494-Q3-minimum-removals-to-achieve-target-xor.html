Problem Statement

You are given an integer array nums and an integer target. You may remove any number of elements from nums, possibly zero. Return the minimum number of removals required so that the bitwise XOR of the remaining elements equals target. If it is impossible, return -1. The XOR of an empty array is 0.

Constraints: 1 <= nums.length <= 40, 0 <= nums[i] <= 10000, 0 <= target <= 10000.

Problem Essence

Removing elements leaves a subsequence, but order does not matter for XOR. The task is really to choose a subset to keep whose XOR is target, while maximizing how many elements are kept. The answer is then n - maxKept. Equivalently, compute the XOR of all elements as total; the removed elements must XOR to total ^ target, and the answer is the minimum size of such a removed subset.

The value bound makes every possible XOR fit below 2^14 = 16384, so a small DP over XOR states is enough. The length bound also allows meet-in-the-middle over two halves of at most 20 elements each.

Worked Example

For nums = [1,2,3] and target = 2, the XOR of all numbers is 1 ^ 2 ^ 3 = 0. If using removed-subset DP, removed elements must XOR to 0 ^ 2 = 2. The smallest removed subset with XOR 2 is [2], so the answer is 1.

Using kept-subset DP gives the same result: the largest kept subset with XOR 2 is [1,3], of size 2. Since n = 3, removals are 3 - 2 = 1.

Decision Rule / Algorithm

Preferred DP: maximize kept elements

  1. Let MAX = 1 << 14, or compute the next power of two greater than the bitwise OR of all values and target.
  2. Maintain dp[x] as the maximum number of kept elements that can produce XOR x. Initialize dp[0] = 0 and all other states to -1.
  3. For each num, copy the current DP and try keeping this element: next[x ^ num] = max(next[x ^ num], dp[x] + 1).
  4. After all numbers, if dp[target] == -1, return -1. Otherwise return len(nums) - dp[target].

Equivalent DP: minimize removed elements

  1. Compute need = xor(nums) ^ target.
  2. Maintain dp[x] as the minimum number of removed elements producing XOR x.
  3. Return dp[need], or -1 if absent.

Both formulations are correct because XOR is associative and every element is either kept or removed. They differ only in which side of the partition is optimized.

Implementation Skeleton

class Solution:
    def minRemovals(self, nums: List[int], target: int) -> int:
        max_xor = 1 << 14
        dp = [-1] * max_xor
        dp[0] = 0

        for num in nums:
            ndp = dp[:]
            for x in range(max_xor):
                if dp[x] != -1:
                    nx = x ^ num
                    ndp[nx] = max(ndp[nx], dp[x] + 1)
            dp = ndp

        if dp[target] == -1:
            return -1
        return len(nums) - dp[target]

Time complexity is O(n * 2^14), at most about 655,360 state transitions for n = 40. Space complexity is O(2^14).

Reimplementation Checklist

  • Use a fresh copy of DP for each element so the same element is not used more than once.
  • Represent unreachable states explicitly, for example -1 for max-kept DP or inf for min-removed DP.
  • Return 0 when the full array already satisfies the target; the DP naturally handles this.
  • Handle target = 0; keeping no elements is valid because the XOR of an empty array is 0.
  • If using a dynamic state size, include all bits that appear in any num or in target. A fixed 1 << 14 is valid under the given constraints.

Wrong But Tempting

  • Greedy removal by value or bit: XOR has cancellation behavior, so locally removing a number that fixes one bit can break another bit later.
  • Checking only individual elements: A target may require a combination, such as 1 ^ 3 = 2.
  • Using current-row updates in-place without a copy: This can reuse one element multiple times in the same iteration and create invalid states.
  • Returning the minimum kept subset size: The problem asks for minimum removals, so with kept-subset DP you must maximize kept count.
  • Forgetting empty remainder: If the target is 0, removing every element is allowed.
