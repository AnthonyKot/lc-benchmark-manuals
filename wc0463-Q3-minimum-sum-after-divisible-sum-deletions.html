Problem Statement

You are given an integer array nums and an integer k. You may repeatedly choose any contiguous subarray whose sum is divisible by k and delete it. After each deletion, the remaining elements close the gap.

Return the minimum possible sum of the remaining array after any number of valid deletions.

Constraints: 1 <= nums.length <= 10^5, 1 <= nums[i] <= 10^6, and 1 <= k <= 10^5.

Problem Essence

Deleting a block whose sum is divisible by k is equivalent to jumping between two positions with equal prefix-sum remainder. Because deleted gaps close, a dynamic program over the original left-to-right scan can decide whether the current element remains or whether a suffix of the processed prefix can disappear.

The useful state is the best remaining sum seen for each prefix remainder. When the current prefix remainder is r, any previous boundary with remainder r allows the intervening subarray to be deleted, leaving that previous best cost.

Worked Example

For nums = [3,1,4,1,5] and k = 3, the minimum remaining sum is 5.

  1. Prefix remainder starts at 0, with best remaining sum 0.
  2. After reading 3, prefix remainder is still 0. Since the whole segment [3] is divisible by 3, the remaining sum can stay 0.
  3. Reading 1,4,1 creates a segment sum 6, also divisible by 3, so that middle segment can be deleted.
  4. After deleting [1,4,1] and then [3], only [5] remains.

Decision Rule / Algorithm

Maintain dp, the minimum possible remaining sum after processing the current prefix, and best[r], the minimum dp value seen at a boundary whose prefix sum has remainder r.

  1. Initialize best[0] = 0 and all other entries to infinity.
  2. Scan each value x, updating prefix += x and r = prefix % k.
  3. If keeping x, the new cost is dp + x.
  4. If deleting a just-formed divisible segment, the new cost can be best[r].
  5. Set dp = min(dp + x, best[r]), then update best[r] = min(best[r], dp).

This is O(n + k) time with an array of size k. A hash map version is also valid, though the accepted set shows arrays are simpler and faster when k <= 100000.

Implementation Skeleton

long minArraySum(int[] nums, int k) {
    long INF = very_large_value;
    long[] best = new long[k];
    fill(best, INF);
    best[0] = 0;

    long dp = 0;
    long prefix = 0;

    for (int x : nums) {
        prefix += x;
        int r = (int)(prefix % k);

        long keep = dp + x;
        long delete = best[r];
        dp = min(keep, delete);

        best[r] = min(best[r], dp);
    }

    return dp;
}
Equivalent accepted implementations maximize deleted sum instead: keep gain as the maximum removable total and return totalSum - gain. That version stores best values like gain - prefix or its algebraic equivalent.

Reimplementation Checklist

  • Use 64-bit integers for prefix sums and answers. The total can reach 10^11.
  • Initialize remainder 0 before the loop so a prefix with sum divisible by k can be fully deleted.
  • Update the prefix before computing the current remainder.
  • Compute the new dp before writing back into best[r].
  • Use best[r] as a value from an earlier boundary or the current boundary after the current transition, not an arbitrary prefix sum.
  • Return the minimum remaining sum, not the maximum deleted sum unless you subtract it from the total.

Wrong But Tempting

  • Greedily delete the first divisible subarray found. Local deletions can change which future elements become adjacent, so greedy order is not reliable.
  • Only consider subarrays in the original array after one pass. The closing-gap rule means separate surviving pieces can become adjacent after deletions.
  • Use a quadratic search over all equal-remainder prefix pairs. It is too slow for n = 100000.
  • Store only whether a remainder has been seen. The cost attached to that remainder is what determines the optimal remaining sum.
  • Use 32-bit int for totals in Java, Go, C++, or C. Prefix sums can overflow.
