Problem Statement

You are given a positive integer hp and two positive 1-indexed integer arrays damage and requirement. There are n trap rooms. Entering room i reduces health by damage[i]. After that reduction, if the remaining health is at least requirement[i], you earn 1 point for that room.

For a starting room j, score(j) is the number of points earned by starting with hp and entering rooms j, j + 1, ..., n in order. Return score(1) + score(2) + ... + score(n). Rooms cannot be skipped, and the run may continue even when health becomes non-positive.

Constraints: 1 <= hp <= 10^9, 1 <= n == damage.length == requirement.length <= 10^5, and 1 <= damage[i], requirement[i] <= 10^4.

Problem Essence

Each possible point is attached to a pair (start, room) with start <= room. For room k, count how many starting positions s make the health after taking damage from s through k still satisfy the requirement at k.

Let P[0] = 0 and P[t] = damage[0] + ... + damage[t - 1]. Starting at s and scoring at room k requires:

hp - (P[k + 1] - P[s]) >= requirement[k]
P[s] >= P[k + 1] + requirement[k] - hp

Because every damage value is positive, P is strictly increasing. For each room k, binary search the first prefix index s in [0, k] whose value reaches the threshold, then add k - s + 1.

Worked Example

Input: hp = 11, damage = [3,6,7], requirement = [4,2,5]. Output: 3.

Prefix sums are P = [0, 3, 9, 16].

Room kThreshold P[k+1] + requirement[k] - hpValid startsContribution
03 + 4 - 11 = -4P[0] = 01
19 + 2 - 11 = 0P[0] = 0, P[1] = 32
216 + 5 - 11 = 10none in P[0..2] = [0,3,9]0

Total contribution is 1 + 2 + 0 = 3. This matches score(1)=2, score(2)=1, and score(3)=0.

Other Official Examples

Example 2: hp = 2, damage = [10000,1], requirement = [1,1]. Output is 1.

Starting from room 1 earns no points because health immediately becomes -9998. Starting from room 2 earns one point because 2 - 1 = 1, which meets requirement 1.

Decision Rule / Algorithm

  1. Build long integer prefix sums P of length n + 1.
  2. Initialize answer = 0.
  3. For each room index k from 0 to n - 1, compute target = P[k + 1] + requirement[k] - hp.
  4. Binary search P[0..k] for the first index idx where P[idx] >= target.
  5. Every start in [idx, k] scores at room k, so add k - idx + 1. If idx == k + 1, add zero.

Time complexity is O(n log n). Space complexity is O(n). The answer can be as large as n * (n + 1) / 2, so return a 64-bit integer in languages with fixed-width integers.

Implementation Skeleton

long totalScore(int hp, int[] damage, int[] requirement) {
    int n = damage.length;
    long[] prefix = new long[n + 1];
    for (int i = 0; i < n; i++) {
        prefix[i + 1] = prefix[i] + damage[i];
    }

    long ans = 0;
    for (int k = 0; k < n; k++) {
        long target = prefix[k + 1] + requirement[k] - (long) hp;
        int idx = lowerBound(prefix, 0, k + 1, target); // search indices [0, k]
        ans += k - idx + 1L;
    }
    return ans;
}

int lowerBound(long[] a, int lo, int hi, long target) {
    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;
        if (a[mid] >= target) hi = mid;
        else lo = mid + 1;
    }
    return lo;
}

Reimplementation Checklist

  • Use zero-based arrays internally: room k uses damage[k], requirement[k], and prefix endpoint P[k + 1].
  • Search only among candidate starting prefixes P[0] through P[k], not through the whole prefix array.
  • Use lower bound for >= target, because equality is enough to satisfy the requirement.
  • Store prefix sums, thresholds, and the answer in 64-bit numeric types where needed.
  • Do not stop a simulated run when health becomes non-positive; the formula already handles later rooms.
  • Return zero contribution when the lower bound lands at k + 1.

Wrong But Tempting

  • Simulating every starting room directly is O(n^2) and will time out for n = 100000.
  • Checking whether the initial hp is at least each room requirement ignores damage from previous rooms in that run.
  • Binary searching the wrong side of the inequality counts failed starts instead of successful starts.
  • Using > instead of >= loses cases where remaining health exactly equals the requirement.
  • Using 32-bit int for the answer can overflow because the maximum total score is about 5,000,050,000.
