Count Good Integers on a Grid Path

Provenance

Problem id: wc0498-Q4-count-good-integers-on-a-grid-path

Source files used: problem.md, stats.json, and 17 accepted__* implementations.

Difficulty: Hard. Function: countGoodIntegersOnPath(l, r, directions). Topic: dynamic programming.

Problem Statement

Given integers l and r, and a six-character string directions containing exactly three D moves and three R moves, count how many integers x in [l, r] are good.

To test one integer, write it as a 16-digit string by left-padding with zeros, place those digits into a 4 by 4 grid in row-major order, start at cell (0,0), follow the six moves, and read the seven visited digits including the starting cell. The integer is good exactly when that seven-digit sequence is non-decreasing.

Constraints: 1 <= l <= r <= 9 * 10^15, directions.length == 6, with exactly three D and three R.

Problem Essence

The path only moves down and right, so every visited row-major index is strictly increasing. That means the condition is not about adjacent grid geometry after construction; it is simply a constraint on seven positions inside a fixed 16-digit number: whenever a position is on the path, its digit must be at least the previous path digit.

Since r can be as large as 9 * 10^15, direct enumeration of the range is infeasible. Count good values up to a bound with digit DP, then answer count(r) - count(l - 1).

Worked Example

For l = 8, r = 10, directions = "DDDRRR", the path visits row-major indices [0, 4, 8, 12, 13, 14, 15].

The answer is 2.

Decision Rule / Algorithm

  1. Convert the path into a boolean array isPath[16]. Start at index 0. A move R adds 1; a move D adds 4.
  2. Define count(N) as the number of good 16-digit padded values from 0 through N.
  3. Run digit DP over positions 0..15. State is usually (pos, tight, last), where last is the most recent digit chosen at a path index.
  4. At a path position, try only digits d >= last and update last = d. At a non-path position, try all legal digits and keep last unchanged.
  5. Return count(r) - count(l - 1).

Some accepted Python implementations use a two-sided DP directly over [l, r] with lower and upper tight flags. That is equivalent to the prefix-count method and has the same tiny state space.

Implementation Skeleton

function countGoodIntegersOnPath(l, r, directions):
    isPath = [false] * 16
    idx = 0
    isPath[0] = true
    for move in directions:
        if move == 'D': idx += 4
        else: idx += 1
        isPath[idx] = true

    function countUpTo(n):
        if n < 0: return 0
        digits = decimal digits of n, left padded to length 16
        memo = empty map

        function dfs(pos, tight, last):
            if pos == 16: return 1
            if not tight and memo has (pos, last): return memo[(pos, last)]

            limit = digits[pos] if tight else 9
            total = 0
            for d from 0 to limit:
                if isPath[pos] and d < last:
                    continue
                nextLast = d if isPath[pos] else last
                nextTight = tight and d == limit
                total += dfs(pos + 1, nextTight, nextLast)

            if not tight: memo[(pos, last)] = total
            return total

        return dfs(0, true, 0)

    return countUpTo(r) - countUpTo(l - 1)

Reimplementation Checklist

  • Pad every bound to exactly 16 digits, including small values such as 8.
  • Mark the starting cell index 0 as a path index before consuming directions.
  • Use row-major index arithmetic: D means +4, R means +1.
  • Initialize the previous path digit to 0 or use a sentinel such as -1. Because the first padded digit is never negative, either works when implemented consistently.
  • Use integer types that can hold the answer. The maximum range is below 10^16, so 64-bit signed integers are sufficient.
  • Memoize by the full state that affects the future. If caching tight states, include tight; if caching only loose states, (pos,last) is enough.

Wrong But Tempting

  • Brute force over [l,r]. This caused Time Limit Exceeded in the failed submissions and cannot survive ranges near 10^16.
  • Checking the whole 16-digit number for non-decreasing order. Only the seven path digits matter.
  • Forgetting leading zeros. The grid is always filled by a 16-digit padded string.
  • Using grid coordinates but accidentally translating with column-major indexing. The grid is row-major, so index is 4 * row + col.
  • Updating the previous digit on non-path cells. Non-path digits are unconstrained and should not affect the next path comparison.
