Problem Statement

You are given integer arrays nums1 and nums2 with lengths n and m, and an integer k. Choose exactly k index pairs (i, j) so that the chosen i indices are strictly increasing and the chosen j indices are strictly increasing.

Each chosen pair contributes nums1[i] * nums2[j]. Return the maximum possible total score.

  • 1 <= n, m <= 100
  • -10^6 <= nums1[i], nums2[j] <= 10^6
  • 1 <= k <= min(n, m)

Problem Essence

This is weighted sequence alignment with exactly k matches. The order constraints mean that after matching nums1[i] with nums2[j], all earlier pairs must come from prefixes ending before i and j.

The hard parts are the word exactly and negative values. A valid answer can be negative, so impossible states need a negative-infinity sentinel rather than zero.

Worked Example

For nums1 = [1,3,2], nums2 = [4,5,1], and k = 2, one optimal selection is:

  • Pair (1, 0): score 3 * 4 = 12
  • Pair (2, 1): score 2 * 5 = 10

The indices are increasing in both arrays, and the total is 12 + 10 = 22. A choice like (1, 1) followed by (2, 0) is illegal because the j index would move backward.

Decision Rule / Algorithm

Use dynamic programming over prefixes and number of selected pairs.

Let dp[i][j][c] be the best score using exactly c pairs from nums1[:i] and nums2[:j]. Then:

dp[i][j][c] = max(
    dp[i-1][j][c],                                      # skip nums1[i-1]
    dp[i][j-1][c],                                      # skip nums2[j-1]
    dp[i-1][j-1][c-1] + nums1[i-1] * nums2[j-1]         # match both
)

Base case: dp[*][*][0] = 0. Every state with c > 0 starts as negative infinity. The answer is dp[n][m][k].

Complexity is O(n*m*k) time. The straightforward table uses O(n*m*k) memory; rolling over i can reduce memory, but the accepted files mostly favor clarity with the full table or equivalent top-down memoization.

Implementation Skeleton

class Solution:
    def maxScore(self, nums1: List[int], nums2: List[int], k: int) -> int:
        n, m = len(nums1), len(nums2)
        NEG = -10**30

        dp = [[[NEG] * (k + 1) for _ in range(m + 1)] for _ in range(n + 1)]
        for i in range(n + 1):
            for j in range(m + 1):
                dp[i][j][0] = 0

        for i in range(1, n + 1):
            for j in range(1, m + 1):
                prod = nums1[i - 1] * nums2[j - 1]
                for c in range(1, min(i, j, k) + 1):
                    dp[i][j][c] = max(
                        dp[i - 1][j][c],
                        dp[i][j - 1][c],
                        dp[i - 1][j - 1][c - 1] + prod
                    )

        return dp[n][m][k]

Reimplementation Checklist

  • Use 64-bit integer arithmetic: products can be around 10^12, and sums can reach around 10^14.
  • Initialize impossible positive-pair states to a very small value, not 0.
  • Set all dp[i][j][0] states to 0.
  • Use 1-based DP dimensions so nums1[i-1] and nums2[j-1] are the current elements.
  • When matching current elements, transition only from dp[i-1][j-1][c-1].
  • Return exactly dp[n][m][k], not the maximum over all c <= k.

Wrong But Tempting

  • Greedy by largest product: ignores ordering and can consume indices that block better later combinations.
  • Longest-common-subsequence style with zero default: fails when all legal exactly-k scores are negative.
  • Choosing at most k pairs: returns 0 for negative-only cases, but the problem requires exactly k.
  • Using 32-bit integers: overflows on products near 10^12.
  • Taking from dp[i-1][j][c-1] or dp[i][j-1][c-1] when matching: would allow one current element to be matched without consuming both arrays consistently.

Accepted Algorithm Families

Bottom-up 3D DP

The dominant family in the accepted files. Java, Rust, Python, Go, JavaScript, TypeScript, and C++ submissions allocate (n+1)*(m+1)*(k+1) or a language-specific equivalent and apply the three-way transition.

Top-down memoized DP

Some Python-style implementations express the same recurrence recursively. This is still the same state graph: (i, j, c) with skip-left, skip-right, and take-both choices.

Space-conscious variants

A rolling-prefix implementation is possible, but it is easier to get wrong because dp[i][j-1][c] and dp[i-1][j-1][c-1] must refer to the correct row/prefix version.
