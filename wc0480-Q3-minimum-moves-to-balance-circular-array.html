Problem Statement

You are given a circular array balance of length n, where balance[i] is the net balance of person i.

In one move, a person can transfer exactly 1 unit of balance to either their left or right neighbor. Return the minimum number of moves required so that every person has a non-negative balance. If it is impossible, return -1.

Important guarantee: at most one index has a negative balance initially.

Constraints: 1 <= n == balance.length <= 10^5, -10^9 <= balance[i] <= 10^9, and at most one negative value exists initially.

Problem Essence

Because there is at most one negative entry, the task is not a general flow-balancing problem. If a negative index exists, all useful transferred units only need to move toward that one deficit. A unit taken from index i costs its shortest circular distance to the negative index.

The minimum cost is therefore obtained by filling the deficit from the closest available non-negative balances first. If the total sum is negative, there are not enough units in the entire circle, so the answer is -1. If no entry is negative, the array already satisfies the requirement and the answer is 0.

Decision Rule / Algorithm

  1. Scan once to compute the total sum and find the negative index, if any.
  2. If the total sum is negative, return -1.
  3. If there is no negative index, return 0.
  4. Let need = -balance[negIdx].
  5. Consume available units in increasing shortest circular distance from negIdx.
  6. For each distance d, transfer as many units as possible from the index or indexes at that distance, adding taken * d to the answer.
  7. Stop when need == 0. With a non-negative total sum this must be possible.

The core greedy rule is valid because every source unit has the same value, and only distance changes the cost. Choosing a farther unit while a closer unit is still available can only increase or preserve the total cost.

Implementation Skeleton

class Solution {
    public long minMoves(int[] balance) {
        int n = balance.length;
        long sum = 0;
        int negIdx = -1;

        for (int i = 0; i < n; i++) {
            sum += balance[i];
            if (balance[i] < 0) negIdx = i;
        }

        if (sum < 0) return -1;
        if (negIdx == -1) return 0;

        long need = -1L * balance[negIdx];
        long moves = 0;

        for (int d = 1; d <= n / 2 && need > 0; d++) {
            int left = (negIdx - d + n) % n;
            int right = (negIdx + d) % n;

            long take = Math.min((long) balance[left], need);
            moves += take * d;
            need -= take;

            if (left != right && need > 0) {
                take = Math.min((long) balance[right], need);
                moves += take * d;
                need -= take;
            }
        }

        return moves;
    }
}

A bucketed variant also works: compute dist = min(abs(i - negIdx), n - abs(i - negIdx)), accumulate balance[i] into buckets[dist], then walk buckets from distance 1 upward.

Reimplementation Checklist

  • Use 64-bit arithmetic for sum, need, and moves. Values can reach about 10^14.
  • Handle sum < 0 before assuming the deficit can be filled.
  • Return 0 when there is no negative value.
  • Use shortest circular distance, not absolute linear distance.
  • For even n, the opposite index appears as both left and right at d = n / 2; count it only once.
  • Do not mutate the array unless the chosen implementation explicitly needs it; all accepted patterns can compute the answer without mutation.

Wrong But Tempting

  • Using only the immediate left and right neighbors. Units may need to come from farther positions.
  • Sorting by raw index or absolute distance on the line. The array is circular, so index 0 may be adjacent to index n - 1.
  • Returning -1 after a greedy loop leaves no remaining source, without first checking total sum. A correct loop should not run out when sum >= 0 and distances are handled correctly.
  • Double-counting the opposite index when n is even.
  • Using 32-bit integers for the answer.
