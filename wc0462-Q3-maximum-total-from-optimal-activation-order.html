Problem Statement

You are given two integer arrays value and limit, both of length n. Initially every element is inactive. You may activate inactive elements in any order.

  • Index i may be activated only when the number of currently active elements is strictly less than limit[i].
  • Activating i adds value[i] to the total. The value is kept even if that element later becomes inactive.
  • After each activation, if the current active count becomes x, every element j with limit[j] <= x becomes permanently inactive.

Return the maximum total activation value.

Constraints: 1 <= n == value.length == limit.length <= 100000, 1 <= value[i] <= 100000, and 1 <= limit[i] <= n.

Problem Essence

The activation/deactivation story collapses to an independent top-k choice per limit value. For all elements with the same limit L, at most L of them can ever contribute before the active count reaches a threshold that permanently disables that group. Because all values are positive, the best contribution from that group is the sum of its largest min(L, groupSize) values.

Groups with different limits do not compete for a shared quota in the optimal formula. The total answer is the sum of each group's best local contribution.

Worked Example

Input: value = [3,5,8], limit = [2,1,3]

Group by limit:

  • limit = 1: values [5], take top 1 => 5
  • limit = 2: values [3], take top 1 of capacity 2 => 3
  • limit = 3: values [8], take top 1 of capacity 3 => 8

Total: 5 + 3 + 8 = 16

This matches the official activation order that activates indices 1, 0, then 2.

Other Official Examples

Input valueInput limitExpectedReason
[4,2,6] [1,1,1] 6 All items are in the limit = 1 group, so take only the largest value.
[4,1,5,2] [3,3,2,3] 12 For limit = 2, take 5. For limit = 3, take all three values 4,2,1. Total is 12.

Decision Rule / Algorithm

  1. Partition indices by their limit[i].
  2. For each group with limit L, keep only the largest L values from that group.
  3. Add those kept values to the answer.

A bounded min-heap is the most direct streaming implementation: push each value into the heap for its limit, and when the heap size exceeds that limit, remove the smallest. The remaining heap entries are exactly the values that group contributes.

Equivalent sorting version: store all values per limit, sort each group descending, and sum the first min(L, size) values.

Implementation Skeleton

class Solution {
    public long maxTotal(int[] value, int[] limit) {
        Map<Integer, PriorityQueue<Integer>> groups = new HashMap<>();
        long answer = 0L;

        for (int i = 0; i < value.length; i++) {
            int cap = limit[i];
            PriorityQueue<Integer> heap =
                groups.computeIfAbsent(cap, k -> new PriorityQueue<>());

            heap.offer(value[i]);
            answer += value[i];

            if (heap.size() > cap) {
                answer -= heap.poll();
            }
        }

        return answer;
    }
}

The maintained answer is a running sum of all values currently retained across the per-limit heaps, so there is no second pass over the heaps.

Reimplementation Checklist

  • Use a 64-bit integer for the total: maximum sum can reach 100000 * 100000 = 10000000000.
  • Key groups by the exact value of limit[i].
  • For a group with limit L, retain at most L values, not L - 1.
  • Use a min-heap when pruning top values; pop the smallest after the heap grows beyond capacity.
  • Do not simulate every activation unless the simulation is carefully proven equivalent; the grouped top-k rule is simpler and less error-prone.
  • Because values are positive under the constraints, always take as many values as the group capacity allows.

Wrong But Tempting

  • Global top values: Taking the largest values overall ignores that each limit value has its own independent capacity.
  • Sort by limit and greedily activate: A literal activation simulation is easy to get wrong because active elements can be deactivated immediately after a step.
  • Take only one item from low limits: This is true only for limit = 1. A group with limit = L can contribute up to L items.
  • Use int for the answer: The answer can exceed 32-bit signed range.
  • Make groups compete: The official hints and accepted submissions rely on independent per-limit group decisions.
