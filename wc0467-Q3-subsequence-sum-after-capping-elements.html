Problem Statement

Given an integer array nums of size n and a positive integer k, define the array capped by value x as replacing every element nums[i] with min(nums[i], x). For every integer x from 1 to n, decide whether some nonempty subsequence of the capped array has sum exactly k. Return a zero-indexed boolean array answer where answer[x - 1] stores that decision.

Problem Essence

For a fixed cap x, every original value less than or equal to x keeps its real value, while every original value greater than x becomes another copy of value x. Therefore the question is whether 

sum_from_original_values_<=_x + t * x == k

for some subset sum formed from values already exposed up to x, and some count t of capped larger elements. Since n and k are at most 4000, a one-dimensional subset-sum DP over sums up to k is enough.

Worked Example

Example 1: nums = [4,3,2,4], k = 5.

Cap xCapped arrayDecisionReason
1[1,1,1,1]falseSelectable sums are 1 through 4, not 5.
2[2,2,2,2]falseOnly even sums can be made.
3[3,3,2,3]trueChoose 2 + 3.
4[4,3,2,4]trueChoose 3 + 2.

Output: [false,false,true,true].

Other Official Examples

Example 2: nums = [1,2,3,4,5], k = 3. The expected output is [true,true,true,true,true], because every cap still leaves a way to make sum 3.

Decision Rule / Algorithm

  1. Count frequencies: freq[v] is the number of elements equal to v.
  2. Maintain dp[s]: whether a subset of the already processed uncapped values can make sum s.
  3. For each cap x = 1..n, add all copies of value x to dp with reverse subset-sum loops.
  4. Let largeCount be the number of original values strictly greater than x.
  5. Try t = 0..min(largeCount, floor(k / x)). If dp[k - t*x] is true, then answer[x - 1] = true.

Equivalent accepted variants check before adding freq[x] if their suffix count treats values greater than or equal to x as capped copies. The invariant must be consistent: do not count value x both inside dp and inside the capped-copy pool.

Implementation Skeleton

n = len(nums)
freq = counts of values 1..n
dp = boolean array of length k + 1
dp[0] = true
answer = [false] * n
largeCount = n

for x in 1..n:
    largeCount -= freq[x]

    repeat freq[x] times:
        for s from k down to x:
            dp[s] |= dp[s - x]

    maxCopies = min(largeCount, k // x)
    for t in 0..maxCopies:
        if dp[k - t * x]:
            answer[x - 1] = true
            break

return answer

Complexity for the simple boolean-DP version is O(n*k + n*(k/x averaged)), usually described as O(n*k + n*k) within the 4000 limits. Memory is O(k) plus frequency and answer arrays.

Reimplementation Checklist

  • Use freq; do not rebuild the capped array for every x.
  • Initialize dp[0] = true.
  • When adding real elements to subset-sum DP, iterate sums downward to avoid reusing the same element more than once.
  • Keep the boundary clear: either dp has values <= x and capped pool is > x, or dp has values < x and capped pool is >= x.
  • Only test sums up to k; larger sums cannot help.
  • Return exactly n booleans, where index x - 1 represents cap x.

Wrong But Tempting

  • Recomputing subset sums from scratch for each cap. This is easy to write but risks roughly O(n^2*k).
  • Forward DP updates for individual copies. Forward loops turn 0/1 knapsack into unbounded knapsack and can use the same element repeatedly.
  • Counting elements equal to x twice. If freq[x] is already added to dp, the capped-copy count must be only original values > x.
  • Forgetting the zero subset. dp[0] allows answers made only from capped large elements, such as t*x = k.
  • Assuming the chosen subsequence has to be contiguous. It is a subsequence, so any subset of positions is allowed.

Accepted Algorithm Families

FamilyObserved filesCore ideaNotes
Frequency plus 1D boolean subset DP Most Java files, JavaScript file, Go file Add values by increasing x, then combine dp[remaining] with some number of capped copies. Straightforward and portable. Java solutions ranged from 45 ms to 82 ms.
Bitset DP Python file Represent subset sums as bits in one integer and shift-or by bundled copies of the current value. Fast in Python because big-integer bit operations run in optimized native code.
Large-cap shortcut Go file For x > k, capped copies cannot be selected, so the answer depends only on whether ordinary subset DP can make k. Useful micro-optimization when n is much larger than k.
