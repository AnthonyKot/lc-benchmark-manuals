Problem Statement

There is an endless straight line with fixed robot positions and wall positions. Robot i stands at robots[i] and has one bullet that may be fired either left or right for at most distance[i] meters.

A bullet destroys every wall in its covered path. Robots are obstacles: if the bullet reaches another robot, it stops there and cannot continue beyond it. Robots themselves are not destroyed. A wall may share a robot position, and such a wall can be destroyed by that robot because either firing direction includes its own position.

Return the maximum number of unique walls that can be destroyed.

Constraints: robots.length == distance.length, each between 1 and 100000; walls.length between 1 and 100000; positions are positive up to 1e9; distances are up to 1e5; robot positions are unique; wall positions are unique.

Problem Essence

After sorting robots by position, only neighboring robots interact. A robot firing into a gap between two adjacent robots can destroy walls inside that gap up to its distance, but it cannot affect walls beyond the neighboring robot. Therefore every wall belongs to exactly one independent region: left of the first robot, right of the last robot, at a robot position, or inside one adjacent-robot gap.

The only coupling is directional: the number of walls destroyed in gap i depends on whether the left robot fires right, whether the right robot fires left, or both. That naturally gives a two-state dynamic program over sorted robots.

Worked Example

For robots = [10,2], distance = [5,1], walls = [5,2,7], sort robot-distance pairs into (2,1), (10,5) and sort walls into [2,5,7].

  • The wall at robot position 2 is always collectible by the robot at 2.
  • The gap between robots is (2, 10), containing walls 5 and 7.
  • The left robot firing right reaches only [3,3], so it gets no gap walls.
  • The right robot firing left reaches [5,9], so it gets walls 5 and 7.

Choose robot 2 to fire left and robot 10 to fire left. Total destroyed walls: 1 + 2 = 3.

Decision Rule / Algorithm

  1. Pair robots[i] with distance[i] and sort by robot position. Sort walls.
  2. Use binary search helpers lower_bound and upper_bound to count walls in any closed interval [L, R].
  3. Count walls at robot positions separately, or include each robot's own position consistently in both directional intervals and subtract only true overlaps. The gap-based accepted solutions usually count robot-position walls once as a base value.
  4. For each gap between sorted robots r[i] and r[i+1], compute:
    • A[i]: walls in [r[i]+1, min(r[i]+d[i], r[i+1]-1)], covered if robot i fires right.
    • B[i]: walls in [max(r[i]+1, r[i+1]-d[i+1]), r[i+1]-1], covered if robot i+1 fires left.
    • U[i]: union of those two sets, covered if both robots fire into the same gap.
  5. Run DP with two states after processing robot i: dpL means robot i fires left; dpR means robot i fires right.
  6. Initialize dpL with walls left of the first robot reachable by its left shot, and dpR = 0. Add the base robot-position wall count at the end, or add the current robot-position wall in every state exactly once.
  7. For each next robot, transition over the previous gap:
    • newL = max(dpL + B[i-1], dpR + U[i-1])
    • newR = max(dpL, dpR + A[i-1])
  8. The answer is base plus max(dpL, dpR + rightEnd), where rightEnd counts walls to the right of the last robot reachable by its right shot.

Implementation Skeleton

def maxWalls(robots, distance, walls):
    pairs = sorted(zip(robots, distance))
    r = [p for p, d in pairs]
    d = [d for p, d in pairs]
    walls.sort()

    def count(lo, hi):
        if lo > hi:
            return 0
        return upper_bound(walls, hi) - lower_bound(walls, lo)

    base = number_of_walls_exactly_at_robot_positions
    left_end = count(r[0] - d[0], r[0] - 1)
    right_end = count(r[-1] + 1, r[-1] + d[-1])

    dpL = left_end
    dpR = 0

    for i in range(1, len(r)):
        L, R = r[i - 1], r[i]
        dL, dR = d[i - 1], d[i]

        A = count(L + 1, min(R - 1, L + dL))
        B = count(max(L + 1, R - dR), R - 1)
        overlap = count(max(L + 1, R - dR),
                        min(R - 1, L + dL))
        U = A + B - overlap

        dpL, dpR = max(dpL + B, dpR + U), max(dpL, dpR + A)

    return base + max(dpL, dpR + right_end)

Reimplementation Checklist

  • Sort robot positions together with their original distances; do not sort robots and distance independently.
  • Sort walls once and use binary search for all interval counts.
  • Use open robot gaps (r[i], r[i+1]) for inter-robot walls so walls at robot positions are not double-counted.
  • Clamp every shot by the neighboring robot position before counting walls.
  • Count the union when both adjacent robots shoot into the same gap; do not add the two counts blindly.
  • Handle the single-robot case with the same initialization and final right-end transition.
  • Use long for interval endpoints in Java/C++ if adding or subtracting distances around positions, even though the answer fits in int.

Wrong But Tempting

  • Greedily choosing the better direction per robot fails because two adjacent choices can overlap in the same gap or leave a gap uncovered.
  • Counting all walls within distance[i] ignores blocking robots and overestimates cases like robots = [1,2], walls = [10].
  • Adding left-shot and right-shot coverage for adjacent robots without subtracting overlap double-counts unique walls.
  • Treating walls at robot positions as ordinary gap walls can miss or double-count them at boundaries.
  • Using a linear scan from scratch for every robot can degrade to O(nm).

Accepted Algorithm Families

The seven accepted files fall into two equivalent families:

  • Gap DP with base robot-position count: The Python and JavaScript solutions remove or separately count walls at robot coordinates, compute A, B, and union per adjacent gap, then run a two-state DP. This is the cleanest way to reason about uniqueness.
  • Directional interval DP with overlap subtraction: Several Java solutions precompute each robot's clamped left and right intervals, then transition between choosing left or right while subtracting overlap between the previous right interval and current left interval. This is algebraically the same gap DP, with robot-position walls included in the directional intervals.

Both families are O((n + m) log m + n log n + m log m), usually described as O((n + m) log(n + m)), and use O(n) auxiliary memory if interval counts are precomputed or O(1) beyond sorted arrays if counts are computed during DP.

Failure Patterns From Stats

stats.json records one failed submission status: Wrong Answer. With this problem shape and the accepted-code comparison, the likely failure modes are boundary and overlap mistakes rather than asymptotic performance.

  • Wrong answers often come from inclusive/exclusive interval errors around robot positions: gap walls should use r[i]+1 through r[i+1]-1 when robot-position walls are counted separately.
  • Another common source is forgetting that a robot blocks bullets, which makes the reachable interval end at the neighbor, not at the raw distance endpoint.
  • Overlap inside a gap must be counted once when both robots shoot toward each other.
