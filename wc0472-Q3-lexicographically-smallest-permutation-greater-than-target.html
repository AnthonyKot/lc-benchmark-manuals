Problem Statement

Given two lowercase strings s and target with equal length n, return the lexicographically smallest permutation of s that is strictly greater than target. If no such permutation exists, return the empty string.

A string is strictly greater than another same-length string when, at the first differing position, its character is later in the alphabet.

Problem Essence

The answer must use exactly the multiset of letters in s. To be as small as possible while still exceeding target, it should match target for as long as possible, then use the smallest available character that is greater than the corresponding target character, then fill the rest with the remaining letters in sorted order.

The main subtlety is that a prefix matching target is only legal if those prefix letters can actually be taken from s. The best divergence position is the rightmost position where the prefix before it is formable and some remaining letter is greater than target[i].

Worked Example

For s = "abc" and target = "bba", the sorted permutations are abc, acb, bac, bca, cab, and cba. The first one strictly greater than bba is bca.

Using the divergence rule:

  1. Try to match the longest possible prefix. Matching "bb" is impossible because s has only one b.
  2. At index 1, matching prefix "b" is possible, and the smallest remaining letter greater than 'b' is 'c'.
  3. Place 'c', then append remaining letters sorted: 'a'.
  4. The result is "bca".

Other Official Examples

stargetoutputReason

"baba" "bbaa" "" The largest usable permutation is bbaa, equal to target, so no strictly greater permutation exists.

Decision Rule / Algorithm

Pick the rightmost valid position where the answer can first become larger than target. A later first difference gives a lexicographically smaller result than an earlier first difference.
  1. Count letters in s as countS[26].
  2. Scan candidate divergence index i from n - 1 down to 0.
  3. Maintain or compute counts for target[0..i-1]. If any prefix count exceeds countS, this divergence index is impossible.
  4. Compute available letters after reserving that target prefix: avail[c] = countS[c] - prefixCount[c].
  5. Choose the smallest c > target[i] with avail[c] > 0.
  6. If found, return target[0..i-1] + c + sorted(remaining letters).
  7. If no index works, return "".

With alphabet size fixed at 26 and n <= 300, an O(26n) implementation is simple and comfortably fast.

Implementation Skeleton

class Solution {
    public String lexGreaterPermutation(String s, String target) {
        int n = s.length();
        int[] countS = new int[26];
        for (int i = 0; i < n; i++) {
            countS[s.charAt(i) - 'a']++;
        }

        int[] prefix = new int[26];
        for (int i = 0; i < n; i++) {
            prefix[target.charAt(i) - 'a']++;
        }

        for (int i = n - 1; i >= 0; i--) {
            prefix[target.charAt(i) - 'a']--;

            boolean okPrefix = true;
            for (int c = 0; c < 26; c++) {
                if (prefix[c] > countS[c]) {
                    okPrefix = false;
                    break;
                }
            }
            if (!okPrefix) continue;

            int[] avail = new int[26];
            for (int c = 0; c < 26; c++) {
                avail[c] = countS[c] - prefix[c];
            }

            int t = target.charAt(i) - 'a';
            for (int c = t + 1; c < 26; c++) {
                if (avail[c] == 0) continue;

                StringBuilder ans = new StringBuilder(n);
                ans.append(target, 0, i);
                ans.append((char) ('a' + c));
                avail[c]--;
                for (int k = 0; k < 26; k++) {
                    while (avail[k]-- > 0) {
                        ans.append((char) ('a' + k));
                    }
                }
                return ans.toString();
            }
        }
        return "";
    }
}

Reimplementation Checklist

  • Use frequency counts, not generated permutations.
  • Remember strictness: returning target itself is not allowed.
  • Prefer the rightmost divergence index that can work.
  • At the divergence index, choose the smallest available letter strictly greater than target[i].
  • After divergence, append all remaining characters in increasing order.
  • Check that the target prefix is constructible from s before using it.
  • Return "" if every divergence position fails.

Wrong But Tempting

  • Sorting s and returning it whenever it is greater than target. This misses cases where the sorted permutation is too small but a later permutation works.
  • Using a standard next-permutation operation on s. The input s is not necessarily related to target order; the answer is the next permutation of the multiset after target, not after s.
  • Greedily taking the smallest character that keeps the prefix at least target without checking suffix feasibility. This can choose an equal character and later get stuck, requiring backtracking or a feasibility check.
  • Choosing an earlier divergence than necessary. A string that becomes larger sooner is usually lexicographically larger than one that matches target longer.
  • Forgetting duplicate letters. Counts must be decremented and restored carefully; treating characters as unique breaks examples like "baba".

Left-to-right candidate enumeration Go submission Walk a matching prefix while also testing the smallest greater replacement at each position, keeping the best candidate. O(26n) to O(26n + candidates*n), still tiny for n <= 300.
Left-to-right greedy with suffix feasibility JavaScript submission When matching target[i], first verify the remaining multiset can still form a strictly greater suffix; otherwise bump now. O(26n^2) in a simple feasibility implementation, accepted because limits are small.
Backtracking from latest matched position Reflected by official hints and some Java variants Match target while possible; if stuck, backtrack to the most recent position that can be increased. O(26n) when implemented with counts and one pass.
