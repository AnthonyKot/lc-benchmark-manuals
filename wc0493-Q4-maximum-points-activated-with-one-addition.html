Maximum Points Activated with One Addition

Problem Statement

You are given distinct integer coordinate points [x_i, y_i]. If a point is activated, every existing point with the same x-coordinate or the same y-coordinate becomes activated, and this propagation continues until it reaches a fixed point.

You may add exactly one new point at an integer coordinate not already present. Activation starts from that newly added point. Return the maximum total number of activated points, including the new point.

Constraints: 1 <= points.length <= 100000, coordinates are between -10^9 and 10^9, and all original coordinates are distinct.

Problem Essence

Think of the original points as edges in a bipartite graph: every distinct x-coordinate is one kind of node, every distinct y-coordinate is the other kind, and each point (x, y) is an edge connecting x to y. Activating a point reaches exactly the connected component containing its x/y coordinate nodes.

Adding a new point (x0, y0) can connect at most two existing components: the component already containing x0, and the component already containing y0. If either coordinate is new, that side contributes no original points. Therefore the best move is to connect the two largest existing components, then add 1 for the inserted point.

Worked Example

For points = [[1,1],[1,2],[2,2]], all three original points belong to one connected component because (1,1) shares x with (1,2), and (1,2) shares y with (2,2).

Add (1,3). The new point activates the x=1 component, which then propagates through y=2 and reaches all three original points. The answer is 3 + 1 = 4.

Other Official Examples

InputOutputReason
[[2,2],[1,1],[3,3]] 3 Each original point is isolated. Add (1,2) to connect two singleton components, activating two original points plus the new one.
[[2,3],[2,2],[1,1],[4,5]] 4 The component containing (2,3) and (2,2) has size 2. Add (2,1) to also reach singleton (1,1), giving 2 + 1 + 1 = 4.

Decision Rule / Algorithm

  1. Build connected components among the original points using DSU.
  2. Two points are in the same component if they share an x-coordinate, share a y-coordinate, or are connected through a chain of such shares.
  3. Count how many original points are in each component.
  4. Let a and b be the two largest component sizes, using b = 0 if only one component exists.
  5. Return a + b + 1.

The added point never needs to be enumerated. Since coordinates are integers and the original set is finite, a coordinate pair can be chosen to connect the target components without duplicating an existing point. If there is only one original component, add a point sharing either an existing x or y, or any nearby unused coordinate paired with one existing coordinate, and activate all original points plus the new point.

Complexity is O(n alpha(n)) expected with hash maps and DSU, or O(n log n) if coordinate compression is done by sorting. Memory is O(n).

Implementation Skeleton

def maxActivated(points):
    n = len(points)
    parent = list(range(n))
    size = [1] * n
    first_x = {}
    first_y = {}

    def find(a):
        while parent[a] != a:
            parent[a] = parent[parent[a]]
            a = parent[a]
        return a

    def union(a, b):
        ra, rb = find(a), find(b)
        if ra == rb:
            return
        if size[ra] < size[rb]:
            ra, rb = rb, ra
        parent[rb] = ra
        size[ra] += size[rb]

    for i, (x, y) in enumerate(points):
        if x in first_x:
            union(i, first_x[x])
        else:
            first_x[x] = i
        if y in first_y:
            union(i, first_y[y])
        else:
            first_y[y] = i

    best1 = best2 = 0
    for i in range(n):
        if find(i) == i:
            s = size[i]
            if s > best1:
                best1, best2 = s, best1
            elif s > best2:
                best2 = s
    return best1 + best2 + 1

Reimplementation Checklist

  • Use DSU with path compression and union by size/rank.
  • Hash x-coordinate to one representative point index, and y-coordinate to one representative point index; union against that representative.
  • When computing final component sizes, call find(i) or rely only on roots whose sizes were maintained by union.
  • Track the two largest root sizes in one pass; sorting all component sizes is fine but unnecessary.
  • Return largest + second_largest + 1; this also handles the one-component case because second_largest stays 0.
  • Use 32-bit integers for counts, but keep coordinates in a type that can hold [-10^9, 10^9].

Wrong But Tempting

  • Choosing the most frequent x and most frequent y independently. Frequency does not capture transitive activation through alternating x/y chains.
  • Running BFS from every possible coordinate or every pair of components. The added point only connects at most two components, so exhaustive search is avoidable.
  • Counting coordinate-node component sizes instead of original-point counts. The answer counts activated points, not distinct x/y values.
  • Forgetting the inserted point. The answer is original activated count plus 1.
  • Returning only the largest component when all points are already connected. You can still add a valid new point and count it, so the answer is n + 1.

Accepted Algorithm Families

Point-index DSU

Most Java and JavaScript submissions use one DSU node per original point. For each point index i, maps x -> first index and y -> first index union i with previous representatives. Component size is maintained directly as number of original points.

Coordinate-node DSU

Several Python and Rust-style implementations create DSU nodes for compressed x-values and y-values. Each point unions its x-node and y-node. After all unions, the solution counts original points per component root. This is close to the official graph model and avoids point-to-point unions.

Coordinate compression variant

The Rust accepted file sorts and deduplicates x and y arrays, then uses binary search to map coordinates to DSU ids. This trades hash lookups during construction for sorting and predictable compact ids.
