Problem Statement

You are given a strictly increasing integer array nums. For each index x, closest(x) is the adjacent index whose value has minimum absolute difference from nums[x]. If both adjacent indices exist and tie, choose the smaller index.

From any index x, you may move to any index y with cost abs(nums[x] - nums[y]), or move to closest(x) with cost 1. For every query [l, r], return the minimum total cost to move from index l to index r.

Constraints: 2 <= nums.length <= 100000, -10^9 <= nums[i] <= 10^9, nums is strictly increasing, 1 <= queries.length <= 100000, and all query indices are valid.

Problem Essence

The complete graph of direct jumps is a distraction. Because nums is sorted, the direct cost from l to r equals the sum of adjacent gaps on the interval. A useful discounted move can only replace one adjacent step by cost 1, and only in the direction chosen by closest(index).

Therefore each adjacent directed step has a fixed best local cost:

  • Going right from i to i + 1 costs 1 if closest(i) == i + 1, otherwise nums[i + 1] - nums[i].
  • Going left from i to i - 1 costs 1 if closest(i) == i - 1, otherwise nums[i] - nums[i - 1].

Once those costs are known, each query is just a range-sum lookup in the direction of travel.

Worked Example

For nums = [0, 2, 3, 9], the gaps are [2, 1, 6]. The closest indices are [1, 2, 1, 2]: index 1 prefers the right gap of 1, index 2 prefers the left gap of 1, and endpoints have only one neighbor.

Rightward adjacent costs:

0 -> 1: 1  (closest from 0)
1 -> 2: 1  (closest from 1)
2 -> 3: 6  (closest from 2 points left, so pay gap)

Leftward adjacent costs:

1 -> 0: 2  (closest from 1 points right, so pay gap)
2 -> 1: 1  (closest from 2)
3 -> 2: 1  (closest from 3)

Thus query [3, 0] costs 1 + 1 + 2 = 4, query [1, 2] costs 1, and query [2, 0] costs 1 + 2 = 3.

Decision Rule / Algorithm

  1. Compute adjacent gaps gap[i] = nums[i + 1] - nums[i].
  2. For every index, determine whether its closest neighbor is left or right. Endpoints are forced. For an interior index i, choose left if gap[i - 1] <= gap[i]; otherwise choose right. The <= is important because ties choose the smaller index.
  3. Build forwardPrefix, where forwardPrefix[k] is the cost to walk from index 0 to k using the best rightward adjacent step at each position.
  4. Build backwardPrefix, where backwardPrefix[k] is the cost to walk from index 0 to k if each stored edge cost represents moving left from i to i - 1. Then the cost from l down to r is backwardPrefix[l] - backwardPrefix[r].
  5. For a query, return 0 if l == r, forwardPrefix[r] - forwardPrefix[l] if l < r, otherwise backwardPrefix[l] - backwardPrefix[r].
Time complexity is O(n + q). Space complexity is O(n) beyond the answer.

Implementation Skeleton

def minCost(nums, queries):
    n = len(nums)
    closest = [0] * n

    for i in range(n):
        if i == 0:
            closest[i] = 1
        elif i == n - 1:
            closest[i] = n - 2
        else:
            left_gap = nums[i] - nums[i - 1]
            right_gap = nums[i + 1] - nums[i]
            closest[i] = i - 1 if left_gap <= right_gap else i + 1

    forward = [0] * n
    backward = [0] * n
    for i in range(n - 1):
        gap = nums[i + 1] - nums[i]
        forward[i + 1] = forward[i] + (1 if closest[i] == i + 1 else gap)
        backward[i + 1] = backward[i] + (1 if closest[i + 1] == i else gap)

    ans = []
    for l, r in queries:
        if l < r:
            ans.append(forward[r] - forward[l])
        else:
            ans.append(backward[l] - backward[r])
    return ans

Reimplementation Checklist

  • Use adjacent gaps only; never run shortest path over all indices.
  • Handle endpoints: index 0 points right, index n - 1 points left.
  • For interior ties, choose left with left_gap <= right_gap.
  • Keep separate prefix arrays for rightward and leftward travel.
  • Use backward[l] - backward[r] for queries where l > r.
  • Return zero for same-index queries. The prefix formulas also yield zero, but the explicit case documents intent.
  • Use a numeric type large enough for sums. The maximum direct span is up to 2 * 10^9, so 32-bit signed integers are barely within range for values, but 64-bit is safer in languages where intermediate overflow is possible.

Wrong But Tempting

  • Running Dijkstra from each query source. The graph has too many possible direct edges and queries can be 100000.
  • Only following closest links until stuck. Sometimes a non-closest adjacent gap must be paid to continue toward the target.
  • Using one undirected discounted edge for every closest pair. The discount is directional: x -> closest(x) costs 1, but the reverse may still cost the full gap.
  • Breaking ties to the right. The statement says choose the smaller index, so interior equal gaps point left.
  • Comparing the prefix-walk cost with a single direct jump for every query and taking the minimum. The accepted solutions do not need this because direct movement across an interval is already represented by paying full adjacent gaps where no discount applies.

Accepted Algorithm Families

All accepted files in this workspace use the same family: compute closest-direction decisions, convert those decisions into per-adjacent-edge directional costs, build two prefix sums, and answer each query in constant time.
