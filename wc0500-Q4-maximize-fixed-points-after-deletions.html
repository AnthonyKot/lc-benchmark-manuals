Problem Statement

You are given an integer array nums. A position i is a fixed point if nums[i] == i. You may delete any number of elements, including zero. After deletions, the remaining elements shift left and are reindexed from 0. Return the maximum possible number of fixed points.

Constraints: 1 <= nums.length <= 100000, 0 <= nums[i] <= 100000.

Problem Essence

Deleting elements means choosing a subsequence of original indices to keep as fixed points. If original index i with value v = nums[i] becomes fixed, it must land at final index v. Therefore:

  • i >= v is mandatory; otherwise the item would need to move right, but deletions only shift left.
  • For two kept fixed points with values v1 < v2, their original indices must have enough room: i2 - i1 >= v2 - v1.
  • Rearranging gives i1 - v1 <= i2 - v2. The shift deficit d = i - nums[i] must be nondecreasing as the fixed values increase.

The task is a two-dimensional subsequence problem over points (value, deficit) = (nums[i], i - nums[i]), keeping only points with nonnegative deficit. Find the longest sequence with strictly increasing value and nondecreasing deficit.

Worked Example

For nums = [1,0,1,2], eligible points are:

Original index inums[i]deficit i - nums[i]Eligible?
01-1No
101Yes: (0,1)
211Yes: (1,1)
321Yes: (2,1)

The values 0, 1, 2 are strictly increasing and the deficits 1, 1, 1 are nondecreasing, so all three can be kept. Delete the first element and the array becomes [0,1,2], producing answer 3.

Other Official Examples

InputOutputReason

Decision Rule / Algorithm

  1. Build candidate points for each index i: if nums[i] <= i, record (x, y) = (nums[i], i - nums[i]).
  2. Require selected candidates to have strictly increasing x because two fixed points cannot occupy the same final index.
  3. Require selected candidates to have nondecreasing y because later selected elements must have at least as many deletable elements before them.
  4. Compute the longest such sequence in O(n log n).

The most direct LIS version sorts candidates by x ascending and, for equal x, by y descending. Then run longest nondecreasing subsequence on y using upper bound. The descending tie-break prevents two candidates with the same final value from both being counted.

An equivalent accepted variant sorts or groups by x and uses a Fenwick tree over compressed y to query the best length for all y' <= y. Updates for the same x must be batched so equal values cannot extend each other.

Implementation Skeleton

from bisect import bisect_right

class Solution:
    def maxFixedPoints(self, nums: list[int]) -> int:
        points = []
        for i, v in enumerate(nums):
            if v <= i:
                points.append((v, i - v))

        points.sort(key=lambda p: (p[0], -p[1]))

        tails = []
        for _, deficit in points:
            pos = bisect_right(tails, deficit)
            if pos == len(tails):
                tails.append(deficit)
            else:
                tails[pos] = deficit

        return len(tails)

Complexity: O(n log n) time from sorting and binary searches, and O(n) extra space. This matches the accepted submissions and is necessary for n = 100000.

Reimplementation Checklist

  • Filter out every index with nums[i] > i.
  • Use deficit = i - nums[i], not nums[i] - i.
  • For the patience-sorting solution, sort by (value asc, deficit desc).
  • Use upper bound / bisect_right for nondecreasing deficits.
  • If using Fenwick DP, batch all updates for the same value.
  • Return the sequence length, not the number of already-fixed positions in the original array.

Wrong But Tempting

  • Count only current fixed points: misses cases like [1,0,1,2], where deletion creates three fixed points.
  • Keep all indices with nums[i] <= i: not every eligible element is mutually compatible.
  • Use strict LIS on deficit: equal deficits are allowed, as shown by [1,0,1,2].
  • Sort equal values by deficit ascending in the direct LIS approach: this can count two points with the same final index value.
  • Update Fenwick immediately inside a same-value group: this also lets equal values extend each other incorrectly.
  • Try quadratic DP: n can be 100000, so O(n^2) will time out.
