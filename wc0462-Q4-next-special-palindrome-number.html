Problem Statement

You are given an integer n. A number is called special if it is a palindrome and every digit k appearing in the number appears exactly k times. Return the smallest special number strictly greater than n.

Constraint: 0 <= n <= 10^15.

Problem Essence

The key observation is that a valid number is determined by a subset of digits from 1..9. If digit k is selected, it contributes exactly k total positions. Digit 0 cannot appear because it would have to appear exactly zero times.

  • The total length is the sum of the selected digits.
  • A palindrome can contain at most one digit with an odd total count, so the selected subset may contain at most one odd digit.
  • For a selected subset, the left half contains floor(k / 2) copies of each selected digit k, plus the single odd digit as the center if one exists.
  • There are only 2^9 - 1 = 511 non-empty digit subsets, so it is practical to generate all candidate palindromes and search them.

Worked Example

For n = 33, one valid digit subset is {1, 2}. Its total length is 1 + 2 = 3, and it has one odd-count digit, 1, which can sit in the center.

  1. The half multiset gets floor(1 / 2) = 0 copies of 1 and floor(2 / 2) = 1 copy of 2.
  2. The center digit is 1.
  3. Mirroring half 2 around center 1 gives 212.
  4. 212 > 33, and no smaller special number is greater than 33, so the answer is 212.

Decision Rule / Algorithm

The simplest accepted decision rule is: precompute every special palindrome within the needed numeric range, sort the list, then binary search for the first value greater than n.

  1. Enumerate every non-empty mask over digits 1..9.
  2. Reject masks whose selected digit sum is too large for the target type, or whose odd selected digit count is greater than one.
  3. Build half counts: for every selected digit d, put d / 2 copies into the left-half multiset.
  4. Generate all unique permutations of that half multiset.
  5. Mirror each half, inserting the odd digit as the center when present.
  6. Convert to integer, discard overflow, sort, deduplicate, and binary search for the first candidate strictly greater than n.

A target-aware variant avoids storing every candidate: for each possible length, enumerate valid digit subsets and construct the smallest palindrome of that subset that is greater than the target. The precompute-and-binary-search version is easier to reimplement reliably.

Implementation Skeleton

buildCandidates():
    values = []
    for mask in 1 .. (1 << 9) - 1:
        length = 0
        oddCount = 0
        middle = none
        for digit in 1..9:
            if mask selects digit:
                length += digit
                if digit is odd:
                    oddCount += 1
                    middle = digit

        if oddCount > 1 or length is outside supported bound:
            continue

        counts[1..9] = 0
        halfLength = 0
        for selected digit:
            counts[digit] = digit // 2
            halfLength += counts[digit]

        backtrack all unique half permutations:
            value = append half digits
            if middle exists: append middle
            append reversed half digits
            add value if no overflow

    sort values
    remove duplicates
    return values

specialPalindrome(n):
    candidates = buildCandidates once
    return first candidate with candidate > n

Reimplementation Checklist

  • Use digits 1..9 only. Never include 0.
  • Filter digit subsets with more than one odd selected digit.
  • Use the sum of selected digits as the candidate length.
  • Generate the half multiset with floor(d / 2) copies of selected digit d.
  • Handle duplicate half digits with either count-based backtracking or sorted next-permutation.
  • Compare using strict greater-than: answer must be > n, not >= n.
  • Use 64-bit integer arithmetic in Java/C++/Go/Rust, and guard overflow if generating beyond the exact problem bound.
  • Sort and deduplicate candidates before binary search.

Wrong But Tempting

  • Incrementing from n + 1 and checking every number is far too slow near 10^15.
  • Generating arbitrary palindromes and then counting digits wastes most of the search space.
  • Forgetting the "at most one odd digit" palindrome condition creates impossible subsets.
  • Letting selected digit 0 appear misreads the rule: zero appears exactly zero times, so it is absent.
  • Returning n when n is already special violates the strict greater-than requirement.
  • Using ordinary permutation generation without duplicate control can cause unnecessary work on halves with repeated digits.

Accepted Algorithm Families

Precompute All + Binary Search

Used by both Java submissions. Enumerates masks, backtracks or next-permutes the half, forms numbers, sorts candidates, then answers each call with lower-bound search for > n.

Best for clarity and robustness on LeetCode because the candidate space is tiny.

Length-by-Length Candidate Search

Used by the Python submission. Tries candidate lengths from len(n) upward, generates valid subsets for that length, and returns the minimum candidate greater than n.

Works because there are only 511 digit masks and the half length is small.

Target-Aware Half DFS

Used by the JavaScript submission. Groups subsets by length and recursively builds the smallest feasible half that can beat the target string.

Avoids enumerating every half permutation for some equal-length cases, but the logic is more delicate.
