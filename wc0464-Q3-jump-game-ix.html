Problem Statement

You are given an integer array nums. From index i, a jump to index j is valid under exactly one of these rules:

  • Jump right to j > i only when nums[j] < nums[i].
  • Jump left to j < i only when nums[j] > nums[i].

For every starting index i, return the maximum value in nums reachable by any sequence of valid jumps from i.

Constraints: 1 <= nums.length <= 100000, 1 <= nums[i] <= 1000000000.

Problem Essence

The jump rules connect indices into contiguous components. If a left segment contains a value greater than a right segment value, movement can cross the boundary through that inversion pattern. A boundary is a true separator only when every value on the left is less than or equal to every value on the right.

The answer for every index in one component is simply the maximum value inside that component.

Worked Example

For nums = [2,3,1], compute prefix maximums and suffix minimums:

inums[i]prefixMax[i]suffixMin[i]
0221
1331
2131

Check cuts:

  • After index 0: prefixMax[0] = 2 and suffixMin[1] = 1, so 2 <= 1 is false.
  • After index 1: prefixMax[1] = 3 and suffixMin[2] = 1, so 3 <= 1 is false.

No separator exists, so the whole array is one component. The component maximum is 3, giving [3,3,3].

Other Official Examples

InputOutputReason
[2,1,3] [2,2,3] A cut exists after index 1 because max left is 2 and min right is 3. Components are [2,1] and [3].
[2,3,1] [3,3,3] No cut exists, so all indices share maximum reachable value 3.

Decision Rule / Algorithm

  1. Build suffixMin, where suffixMin[i] is the minimum of nums[i..n-1].
  2. Scan left to right while maintaining currentMax, the maximum in the active block.
  3. At index i, close the current block when currentMax <= suffixMin[i + 1]. This means no right-side value is smaller than any left-side maximum, so the jump graph cannot merge across that boundary.
  4. Fill all positions in the closed block with currentMax.

Equivalent accepted implementations precompute both prefixMax and suffixMin, collect split positions, then fill each segment.

Implementation Skeleton

function maxValue(nums):
    n = length(nums)
    suffixMin[n] = +infinity
    for i from n - 1 downto 0:
        suffixMin[i] = min(nums[i], suffixMin[i + 1])

    ans = array of length n
    start = 0
    currentMax = -infinity

    for i from 0 to n - 1:
        currentMax = max(currentMax, nums[i])
        if currentMax <= suffixMin[i + 1]:
            for j from start to i:
                ans[j] = currentMax
            start = i + 1
            currentMax = -infinity

    return ans

Time complexity is O(n). Extra space is O(n) for suffixMin plus the output. The nested fill loop is still linear overall because each index is assigned once.

Reimplementation Checklist

  • Use the strict jump inequalities from the statement, but use a non-strict cut test: max(left) <= min(right).
  • Include the sentinel suffixMin[n] = +infinity if using the one-pass block-closing version.
  • Reset the block start and current maximum after closing a block.
  • Fill every index exactly once with its component maximum.
  • Use integer types that can hold values up to 1000000000; standard 32-bit signed integers are enough.
  • Do not build explicit graph edges, which can be quadratic.

Wrong But Tempting

  • Treating each direct jump independently and taking only immediate neighbors. Jumps may require multiple moves.
  • Using prefixMax[i] < suffixMin[i+1] as the cut rule. Equal values on both sides cannot jump across by value, but equality still permits a separator; the accepted condition is <=.
  • Assuming a decreasing suffix or increasing prefix by itself is enough. The separator depends on both sides together.
  • Running DFS/BFS over all possible jumps. With n = 100000, enumerating all valid jump pairs is too large.
  • Returning each component's rightmost or leftmost value instead of its maximum.

Failure Patterns From Stats

The local stats record two failed submissions, both with status Wrong Answer. No time-limit failures are recorded, which points to logic mistakes rather than asymptotic performance as the observed failure mode.

  • The most likely wrong-answer source is an incorrect component separator, especially using strict comparison or missing equal-value boundaries.
  • Another likely source is assigning only the local running maximum at each index instead of filling the entire component after its true boundary is known.
  • Reachability should be reasoned as components induced by valid cross-boundary inversions, not as independent one-step improvements.
