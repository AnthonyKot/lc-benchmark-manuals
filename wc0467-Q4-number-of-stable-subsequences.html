Problem Statement

You are given an integer array nums. A nonempty subsequence is stable if, when read in subsequence order, it never contains three consecutive elements with the same parity.

Return the number of stable subsequences modulo 1_000_000_007.

Constraints from the statement:

  • 1 <= nums.length <= 100000
  • 1 <= nums[i] <= 100000

Problem Essence

Only parity matters. The actual values of nums[i] do not affect validity after converting each value to even or odd.

A stable subsequence can end in four meaningful states:

  • even1: ends with an even number and has a current run of one even.
  • even2: ends with two consecutive evens.
  • odd1: ends with an odd number and has a current run of one odd.
  • odd2: ends with two consecutive odds.

When processing a new number, every new stable subsequence that uses it is created by appending it to an older compatible subsequence, or by starting the single-element subsequence containing only this number.

Worked Example

For nums = [1, 3, 5], all numbers are odd. Every nonempty subsequence of length one or two is stable, but the length-three subsequence is not stable because it has three consecutive odd values.

SubsequenceStable?Reason
[1]YesLength one cannot contain three consecutive same-parity elements.
[3]YesSame.
[5]YesSame.
[1, 3]YesTwo consecutive odds are allowed.
[1, 5]YesTwo consecutive odds are allowed.
[3, 5]YesTwo consecutive odds are allowed.
[1, 3, 5]NoThree consecutive odds.

The answer is 6.

Other Official Examples

Example 2

Input: nums = [2, 3, 4, 2]

Output: 14

There are 2^4 - 1 = 15 nonempty subsequences. The only invalid one is [2, 4, 2], because those are three consecutive even values inside the chosen subsequence.

Decision Rule / Algorithm

Maintain counts for stable subsequences already seen. For each incoming value, update only the states ending in that value's parity.

Even value

  • New even1 subsequences: the single new element plus all old subsequences ending in odd, so 1 + odd1 + odd2.
  • New even2 subsequences: old even1 subsequences extended by this even value.
  • Old even2 subsequences cannot be extended by even; that would create three consecutive evens.

Odd value

  • New odd1 subsequences: 1 + even1 + even2.
  • New odd2 subsequences: old odd1 subsequences extended by this odd value.
  • Old odd2 subsequences cannot be extended by odd.

Always take modulo 1_000_000_007. The final answer is even1 + even2 + odd1 + odd2 modulo MOD.

Implementation Skeleton

MOD = 1_000_000_007
even1 = even2 = odd1 = odd2 = 0

for x in nums:
    if x is even:
        add_even1 = 1 + odd1 + odd2
        add_even2 = even1
        even1 = (even1 + add_even1) % MOD
        even2 = (even2 + add_even2) % MOD
    else:
        add_odd1 = 1 + even1 + even2
        add_odd2 = odd1
        odd1 = (odd1 + add_odd1) % MOD
        odd2 = (odd2 + add_odd2) % MOD

return (even1 + even2 + odd1 + odd2) % MOD

Important implementation detail: store add_even2 from the old even1, and add_odd2 from the old odd1. Do not let a state updated for the current element feed another transition for the same element.

Reimplementation Checklist

  • Convert each number to parity with x & 1 or x % 2.
  • Initialize all four DP counters to zero because the empty subsequence is not counted as an answer state.
  • Add 1 when starting a new single-element subsequence at the current number.
  • Append same parity only from run length one to run length two.
  • Append different parity from either run length one or two, resetting the run length to one.
  • Use old values for same-iteration transitions.
  • Take the modulus during updates and on the final sum.
  • Return a normal integer type accepted by the platform signature.

Wrong But Tempting

  • Counting contiguous subarrays instead of subsequences. The invalid triple is consecutive in the selected subsequence, not necessarily adjacent in the original array.
  • Subtracting only length-three same-parity subsequences from 2^n - 1. Longer subsequences may also become invalid when any run reaches length three.
  • Tracking only the last parity. You also need to know whether the current same-parity run length is one or two.
  • Updating even1 before saving the old value needed for even2, or similarly for odd states.
  • Including the empty subsequence in the final answer.
  • Using 32-bit intermediate arithmetic in languages where additions may overflow before modulo.

Accepted Algorithm Families

Four-State Run-Length DP

This is the dominant accepted family. Java, JavaScript, Go, and Python accepted submissions maintain four counters: parity even or odd crossed with run length one or two. It is O(n) time and O(1) memory.

Equivalent Length/Pair DP

One Java accepted file separates single-element states from two-or-more states, but the transitions are algebraically equivalent: a new value either starts a sequence, switches parity, or extends a one-length same-parity run.
