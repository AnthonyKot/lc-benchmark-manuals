Problem Statement

You are given a non-negative integer array nums and an integer k. Select a non-empty contiguous subarray whose maximum element minus minimum element is at most k. The value of a selected subarray is the XOR of all its elements. Return the maximum possible value.

Constraints: 1 <= nums.length <= 4 * 10^4, 0 <= nums[i] < 2^15, and 0 <= k < 2^15.

Problem Essence

The range condition is about ordinary values inside a contiguous window, while the objective is an XOR over a subarray. For a fixed right endpoint r, once the smallest valid left boundary L is known, every start l in [L, r] produces a valid subarray ending at r. Its XOR is pref[r + 1] ^ pref[l]. Therefore, the task becomes: maintain all currently valid prefix XORs pref[l] and answer maximum XOR queries against pref[r + 1].

Worked Example

For nums = [5,4,5,6] and k = 2, the best subarray is [4,5,6]. Its maximum is 6, minimum is 4, and 6 - 4 = 2, so it is valid. Its value is 4 ^ 5 ^ 6 = 7, so the answer is 7.

Prefix XORs are [0,5,1,4,2]. At right endpoint r = 3, the valid start indices include 1,2,3. Querying a trie containing pref[1], pref[2], and pref[3] with pref[4] = 2 can produce 2 ^ pref[1] = 2 ^ 5 = 7.

Decision Rule / Algorithm

  1. Compute prefix XORs, where pref[0] = 0 and pref[i + 1] = pref[i] ^ nums[i].
  2. Scan right endpoint r from left to right.
  3. Maintain two monotonic deques of indices: a decreasing deque for the current maximum and an increasing deque for the current minimum.
  4. While nums[maxDeque.front] - nums[minDeque.front] > k, remove pref[L] from the trie, evict index L from deque fronts if present, and increment L.
  5. Ensure the trie contains exactly prefix indices for valid starts l in [L, r], then query it with pref[r + 1].
  6. Update the answer with the query result.

The accepted submissions use two equivalent orderings: insert pref[r] before querying pref[r + 1], or carry pref[r] from the previous iteration after querying. The invariant is what matters: at query time, the trie must contain all and only valid start prefixes for subarrays ending at r.

Implementation Skeleton

def maxXor(nums, k):
    n = len(nums)
    pref = [0] * (n + 1)
    for i, x in enumerate(nums):
        pref[i + 1] = pref[i] ^ x

    trie = CountedBinaryTrie(bit_high=14)  # 15-bit values are enough for this problem
    max_dq = deque()  # indices, values decreasing
    min_dq = deque()  # indices, values increasing
    left = 0
    ans = 0

    for r, x in enumerate(nums):
        while max_dq and nums[max_dq[-1]] <= x:
            max_dq.pop()
        max_dq.append(r)

        while min_dq and nums[min_dq[-1]] >= x:
            min_dq.pop()
        min_dq.append(r)

        trie.insert(pref[r])

        while nums[max_dq[0]] - nums[min_dq[0]] > k:
            trie.remove(pref[left])
            if max_dq[0] == left:
                max_dq.popleft()
            if min_dq[0] == left:
                min_dq.popleft()
            left += 1

        ans = max(ans, trie.query_max_xor(pref[r + 1]))

    return ans

Reimplementation Checklist

  • Use prefix XORs; do not recompute subarray XORs directly.
  • Use counts in trie nodes so deleting stale prefixes does not break duplicate prefix values.
  • Use 15 bits for values under 2^15; using 16 bits is also safe and appears in some accepted solutions.
  • When moving L, delete pref[L], not nums[L].
  • Keep deques as indices, not values, so expired boundaries can be removed correctly.
  • At every query, the trie must be non-empty because a single-element subarray ending at r is always a possible start after inserting pref[r].

Wrong But Tempting

  • Sorting the array or using value buckets loses contiguity, so it cannot solve the subarray problem.
  • Maintaining only the best prefix XOR is insufficient; maximum XOR requires bitwise branching over all eligible prefixes.
  • Checking only the longest valid window misses shorter subarrays inside the window that may have a larger XOR.
  • Using a trie without per-node counts fails when the left boundary moves or duplicate prefixes exist.
  • Calling JavaScript Array.shift() heavily for queues can add overhead; accepted JavaScript still passed, but head pointers are usually safer for larger inputs.

Accepted Algorithm Families

All accepted files follow the same asymptotic family: sliding window plus monotonic min/max queues plus counted binary trie over prefix XORs. The main implementation variants are:

  • Object-node trie: common in Python, Java, and JavaScript; each node stores two children and a count.
  • Array-index trie: used in faster systems-language submissions and some JavaScript; stores child indices and counts in arrays or vectors for less allocation overhead.
  • Deque implementation choice: Python uses collections.deque, Java often uses ArrayDeque or raw arrays, Rust uses VecDeque, and Go uses slices with head indexes.

Time complexity is O(n * B), where B is 15 or 16 trie levels. Space complexity is O(n * B) in the worst case for trie nodes plus O(n) for prefix XORs and deques.
