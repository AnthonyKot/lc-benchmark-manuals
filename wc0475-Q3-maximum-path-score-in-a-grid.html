Problem Statement

You are given an m x n grid where each cell contains 0, 1, or 2, plus an integer budget k. Start at the top-left cell (0, 0) and reach the bottom-right cell (m - 1, n - 1) by moving only right or down.

Cell valueScore gainedCost paid
000
111
221

Return the maximum score among all valid paths whose total cost is at most k. Return -1 if every path to the destination exceeds the budget.

Constraints from the statement: 1 <= m, n <= 200, 0 <= k <= 1000, grid[0][0] == 0, and each grid value is between 0 and 2.

Problem Essence

The path shape is monotone, so the only predecessors of cell (i, j) are (i - 1, j) and (i, j - 1). The hard part is the budget: the best score at a cell is not a single number because a lower-score state with lower cost may still dominate later. Keep states indexed by exact cost, then maximize score.

Core state: dp[i][j][c] is the best score when reaching (i, j) with exact total cost c. Unreachable states are -1 or a negative sentinel.

Decision Rule / Algorithm

  1. Let cost = 0 for value 0, otherwise 1. Let score = grid[i][j].
  2. Initialize the start cell as reachable at cost 0 with score 0. The constraint guarantees grid[0][0] == 0.
  3. Process cells row by row, left to right. For each cell and each total cost c, pull the best predecessor from above and left at cost c - cost.
  4. If a predecessor is reachable, set the current state to max(current, predecessor + score).
  5. The answer is the maximum value at the destination over all costs from 0 through k. If no destination state is reachable, return -1.

Time complexity is O(m * n * k). A full three-dimensional table costs O(m * n * k) memory, but accepted solutions commonly reduce this to O(n * k) by keeping only the previous row and current row.

Implementation Skeleton

function maxPathScore(grid, k):
    m = grid.length
    n = grid[0].length
    limit = min(k, m + n - 1)  // optional, because each path has m+n-1 cells

    prev = n arrays of length limit + 1, filled with -1

    for i in 0..m-1:
        curr = n arrays of length limit + 1, filled with -1

        for j in 0..n-1:
            val = grid[i][j]
            addCost = 0 if val == 0 else 1
            addScore = val

            if i == 0 and j == 0:
                curr[j][0] = 0
                continue

            for c in addCost..limit:
                best = -1
                if i > 0:
                    best = max(best, prev[j][c - addCost])
                if j > 0:
                    best = max(best, curr[j - 1][c - addCost])
                if best != -1:
                    curr[j][c] = best + addScore

        prev = curr

    return max(prev[n - 1]) or -1 if all entries are unreachable

Reimplementation Checklist

  • Use exact-cost states, not just one best score per cell.
  • Include the destination cell's score and cost in the transition.
  • Initialize the start cell once. Since grid[0][0] == 0, it starts at cost 0 and score 0.
  • Read from prev[j] for the top predecessor and curr[j - 1] for the left predecessor when using row compression.
  • Use a clear unreachable marker such as -1 when scores are nonnegative, or a large negative sentinel.
  • Return the maximum over all allowed costs at the destination, not only cost exactly k.
  • Optionally cap the cost dimension to min(k, m + n - 1) because every path visits exactly m + n - 1 cells and each cell costs at most 1.

Wrong But Tempting

  • Greedy by value 2: A path that grabs more 2 cells early can spend the budget before it reaches the destination.
  • One best score per cell: This loses cheaper states that may be necessary to finish within k.
  • Shortest path framing: All monotone paths have the same number of moves, but they do not have the same score or cost.
  • Checking budget only at the end: The DP can store exact costs and discard transitions that exceed the budget immediately.
  • Returning dp[end][k] only: Valid paths may use less than the full budget.

Accepted Algorithm Families

Dense exact-cost DP

Most accepted files use arrays indexed by cost. Java, Go, and JavaScript submissions keep n * (k + 1) or n * (limit + 1) states for previous and current rows. This is the most direct reimplementation of the official hints.

Cost cap optimization

Several accepted submissions cap the cost dimension with min(k, m + n - 1) or an equivalent bound. This keeps the same recurrence but avoids scanning impossible costs when k is larger than any path cost.

Compressed frontier DP

The Python accepted solution stores only nondominated (cost, score) pairs per cell. It merges top and left frontiers and discards states that do not improve score as cost increases. This can reduce memory and work on many grids, but it is easier to get wrong than dense DP.
