Problem Statement

You are given a binary-character string s of length n, containing only 'A' and 'B', and a list of q queries.

  • [1, j]: flip s[j]. An 'A' becomes 'B', and a 'B' becomes 'A'. This mutation affects later queries.
  • [2, l, r]: compute the minimum number of character deletions needed so that the current substring s[l..r] becomes alternating. This query does not mutate s.

An alternating substring has no equal adjacent characters. A length-1 substring is already alternating. Return one answer for each type-2 query.

Constraints: 1 <= n == s.length <= 10^5, 1 <= q == queries.length <= 10^5, and all query indices are valid zero-based indices.

Problem Essence

The minimum deletions are not about choosing a target pattern like ABAB... by position parity. Deletions preserve order, so a substring can be reduced to one representative from each maximal run of equal characters.

For any substring, the maximum possible alternating subsequence length is the number of runs inside it. Therefore:

minimum deletions
= substring length - number of runs
= number of equal adjacent pairs inside the substring

So the whole problem reduces to maintaining whether each adjacent pair is equal under point flips, and answering range sums on those adjacent-pair markers.

Decision Rule / Algorithm

Maintain an auxiliary boundary array. Two equivalent conventions appear in accepted submissions:

  • Equal-marker convention: eq[i] = 1 when i >= 1 and s[i] == s[i-1]. A type-2 answer for [l,r] is sum(eq[l+1..r]).
  • Different-marker convention: diff[i] = 1 when s[i] != s[i-1]. Then answer = (r-l) - sum(diff[l+1..r]).

Use a Fenwick tree for point updates and range sums. On a flip at index j, only the boundaries j and j+1 in the right-indexed convention can change, corresponding to pairs (j-1,j) and (j,j+1).

build:
  for i in 1..n-1:
    eq[i] = (s[i] == s[i-1])
    bit.add(i, eq[i])

flip(j):
  s[j] = opposite(s[j])
  recompute boundary i = j     if j > 0
  recompute boundary i = j + 1 if j + 1 < n

query(l, r):
  return bit.sum(r) - bit.sum(l)

This is O((n + q) log n) time and O(n) memory.

Implementation Skeleton

class Solution:
    def minDeletions(self, s, queries):
        a = list(s)
        n = len(a)
        bit = Fenwick(n)
        eq = [0] * n

        def value(i):
            return 1 if i > 0 and a[i] == a[i - 1] else 0

        for i in range(1, n):
            eq[i] = value(i)
            if eq[i]:
                bit.add(i, 1)       # one-based Fenwick can also use i + 1

        ans = []
        for q in queries:
            if q[0] == 1:
                j = q[1]
                a[j] = 'B' if a[j] == 'A' else 'A'
                for i in (j, j + 1):
                    if 0 < i < n:
                        nv = value(i)
                        bit.add(i, nv - eq[i])
                        eq[i] = nv
            else:
                l, r = q[1], q[2]
                ans.append(bit.sum(r) - bit.sum(l))
        return ans

If your Fenwick implementation is strictly one-based and cannot update index 0, store boundary i at Fenwick position i for i in [1,n-1], exactly as the Java accepted submissions do.

Reimplementation Checklist

  • Convert s to a mutable representation: character array, byte slice, or list.
  • Pick exactly one boundary convention: equal markers or different markers.
  • Use right-indexed boundaries: boundary i represents pair (i-1, i).
  • For query [2,l,r], inspect only boundaries from l+1 through r.
  • For flip [1,j], recompute only boundary j when j > 0 and boundary j+1 when j+1 < n.
  • Do not append anything for type-1 queries.
  • Preallocate the result array if the language benefits from it; count type-2 queries first.

Wrong But Tempting

  • Comparing to fixed parity patterns: Counting mismatches against ABAB... or BABA... answers a replacement-style problem, not this deletion problem.
  • Scanning each substring: A direct scan per type-2 query is O(nq) in the worst case and cannot handle 10^5 queries.
  • Updating every affected substring after a flip: A point flip changes many possible substrings, but it changes only two adjacent boundaries.
  • Off-by-one range sums: Including boundary l accidentally uses pair (l-1,l), which is outside the queried substring.
  • Mixing marker conventions: If the tree stores different-adjacent markers, the answer is (r-l) - sum; if it stores equal-adjacent markers, the answer is just sum.
