Longest Balanced Substring II

Problem id: wc0471-Q3-longest-balanced-substring-ii. Function: longestBalanced(s).

Provenance

This manual was assembled from the local files problem.md, stats.json, and the five accepted__* submissions in this directory. The source problem is LeetCode "Longest Balanced Substring II", difficulty Medium, with tags hash-table, string, and prefix-sum.

The accepted corpus contains JavaScript, Go, Java, and Python 3 implementations. All accepted solutions use linear scans with prefix count states, either split by case or combined into several maps.

Problem Statement

You are given a string s containing only 'a', 'b', and 'c'. A non-empty substring is balanced if every distinct character that appears in that substring appears the same number of times. Return the length of the longest balanced substring.

  • 1 <= s.length <= 100000
  • s contains only 'a', 'b', and 'c'.

Problem Essence

"Balanced" does not mean all three letters must appear. The valid substrings fall into exactly three families:

  • One distinct character: every run like aaaa is balanced.
  • Two distinct characters: for a fixed pair, such as a/b, the substring must contain no c and must have equal counts of a and b.
  • Three distinct characters: counts of a, b, and c must all be equal.
Because the alphabet has only three characters, the clean solution is to solve those families directly and take the maximum.

Worked Example

For s = "abbac", the answer is 4.

The substring "abba" uses only a and b. It has two as and two bs, so it is balanced. No longer substring is valid: "abbac" has counts a=2, b=2, c=1, which are not all equal.

Decision Rule / Algorithm

Case 1: one distinct character

Scan consecutive runs and keep the maximum run length. Any run of one repeated character is balanced.

Case 2: exactly two distinct characters

For each pair (x, y) and excluded character z, scan maximal segments that do not contain z. Maintain a prefix difference count(x) - count(y). If the same difference appears at two positions, the substring between them has equal counts of x and y. Store only the earliest position for each difference.

Equivalent accepted variants avoid explicitly splitting segments by including the excluded character's prefix count in the hash key, for example (countC, countA - countB) for the a/b family. Equal excluded count guarantees no excluded character was added between the two prefixes.

Case 3: all three characters

Maintain prefix counts ca, cb, and cc. If two prefixes have the same pair of differences, such as (ca - cb, cb - cc), then the substring between them adds equal amounts of all three characters. Store the first index of each state to maximize length.

Time complexity is O(n) because the number of cases is constant. Space complexity is O(n) for the prefix-state hash maps.

Implementation Skeleton

def longestBalanced(s):
    ans = longest_run_of_same_character(s)

    for x, y, blocked in [('a','b','c'), ('a','c','b'), ('b','c','a')]:
        first = {0: -1}
        diff = 0
        for i, ch in enumerate(s):
            if ch == blocked:
                first = {0: i}
                diff = 0
                continue
            if ch == x:
                diff += 1
            elif ch == y:
                diff -= 1
            if diff in first:
                ans = max(ans, i - first[diff])
            else:
                first[diff] = i

    ca = cb = cc = 0
    first = {(0, 0): -1}
    for i, ch in enumerate(s):
        if ch == 'a': ca += 1
        elif ch == 'b': cb += 1
        else: cc += 1
        state = (ca - cb, cb - cc)
        if state in first:
            ans = max(ans, i - first[state])
        else:
            first[state] = i

    return ans

Reimplementation Checklist

  • Initialize the answer to at least the longest one-character run; for non-empty input, the answer is at least 1.
  • For pair cases, reset the map and difference when the excluded character appears, or include the excluded prefix count in the state key.
  • Store the earliest index for each prefix state. Replacing it with a later index shortens future candidates.
  • Use prefix positions consistently. Either store -1 for the virtual prefix before index 0, or store prefix lengths 0..n.
  • For three-letter substrings, key by two independent differences, not by one total or by raw counts.
  • Return the maximum across all three families, not just the all-three-character case.

Wrong But Tempting

  • Checking only substrings with all three letters. This misses answers like "abba".
  • Using a sliding window that shrinks on unequal counts. Balance is not monotonic, so a standard two-pointer window does not apply.
  • For pair cases, ignoring the third character without splitting or encoding its count. That can incorrectly accept substrings containing all three letters.
  • Keeping the latest prefix-state index. Longest-substring prefix methods need the earliest index.
  • Testing only if the substring length is divisible by two or three. Divisibility is necessary for some families but not sufficient.

Language and Performance Notes

The concrete performance data below comes from stats.json.performance_by_language. The runtimes are accepted-submission measurements, so compare them cautiously, but they are useful for implementation choices.

  • Java had two accepted submissions: fastest 334 ms and slowest 824 ms. The faster Java solution used packed long keys for the three-character map and segment-based pair scans; memory ranged from 152.9 MB to 282.6 MB.
  • JavaScript had one accepted submission at 421 ms and 85.5 MB, using string keys like "d1,d2" in Map.
  • Go had one accepted submission at 628 ms and 38.2 MB, using map[[2]int]int. It had the lowest memory in this corpus.
  • Python 3 had one accepted submission at 737 ms and 56.6 MB, using tuple keys and separate case scans. This is still linear and acceptable for n = 100000.

For Java, avoid excessive string key creation if possible; packed numeric keys can materially reduce both runtime and memory. In Python, tuple keys are clear and fast enough here. In Go, fixed-size array keys are a good fit for hash maps.

Failure Patterns From Stats

The stats report three failed submissions: 2 Time Limit Exceeded and 1 Wrong Answer.

  • Time Limit Exceeded usually points to enumerating substrings or repeatedly recounting characters. With n = 100000, any O(n^2) approach is too slow.
  • The Wrong Answer risk is highest around the definition of "distinct characters": one-letter and two-letter balanced substrings are valid, not only substrings containing all three characters.
  • Another likely wrong-answer source is accepting an a/b substring that crosses a c. Reset on excluded characters or encode the excluded prefix count.
