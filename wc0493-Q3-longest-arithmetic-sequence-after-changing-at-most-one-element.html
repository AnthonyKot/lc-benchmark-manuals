Problem Statement

You are given an integer array nums. A subarray is arithmetic if the difference between consecutive elements in the subarray is constant.

You may replace at most one element in nums with any integer. After that, choose an arithmetic subarray. Return the maximum possible length of such a subarray.

  • 4 <= nums.length <= 10^5
  • 1 <= nums[i] <= 10^5

Problem Essence

The chosen subarray must be contiguous. Changing one element can do three useful things: extend an existing arithmetic run by one at either end, replace an interior element to bridge equal-difference runs on both sides, or leave the best already-arithmetic run unchanged.

The key observation is local: if index i is replaced and both neighbors are included, the only possible common difference is d = (nums[i+1] - nums[i-1]) / 2. That bridge is valid only when the numerator is even, because the replacement must be an integer.

Worked Example

For nums = [9,7,5,10,1], the answer is 5.

  1. The intended full-array arithmetic difference is -2.
  2. The values around index 3 are 5 and 1, so the needed middle value is 3.
  3. Replace 10 with 3, giving [9,7,5,3,1].
  4. The whole array is now arithmetic, so the maximum selected subarray length is 5.

Decision Rule / Algorithm

Use a linear scan with precomputed run lengths. There are two equivalent representations in the accepted files: store runs over the value array, or store runs over the difference array. The difference-array version is compact.

  1. Build diff[i] = nums[i+1] - nums[i] for 0 <= i < n-1.
  2. Compute leftRun[i]: number of consecutive equal differences ending at i.
  3. Compute rightRun[i]: number of consecutive equal differences starting at i.
  4. Initialize the answer from the best existing arithmetic subarray, plus one possible changed boundary element, capped by n.
  5. For every interior changed index k, inspect the two adjacent gaps diff[k-1] and diff[k]. If their sum is even, the bridge difference is d = (diff[k-1] + diff[k]) / 2.
  6. Extend left through a run of d ending at k-2, extend right through a run of d starting at k+1, and count left + 3 + right for the two neighbors plus the replaced element.
  7. Also consider one-sided extension cases: changing an element just before or just after an existing run can add one element, but never more than n.

Time complexity is O(n). Space complexity is O(n), matching all accepted families here. With careful rolling state some one-sided checks can be compressed, but the two arrays are simpler and safer.

Implementation Skeleton

function longestArithmetic(nums):
    n = len(nums)
    if n <= 2:
        return n

    diff = [nums[i + 1] - nums[i] for i in 0..n-2]
    m = n - 1

    leftRun = array(m, 1)
    for i in 1..m-1:
        if diff[i] == diff[i - 1]:
            leftRun[i] = leftRun[i - 1] + 1

    rightRun = array(m, 1)
    for i in m-2 down to 0:
        if diff[i] == diff[i + 1]:
            rightRun[i] = rightRun[i + 1] + 1

    bestDiffRun = max(leftRun)
    ans = min(n, bestDiffRun + 2)  // run has bestDiffRun + 1 elements; change can add one

    for k in 1..n-2:
        gap = nums[k + 1] - nums[k - 1]
        if gap is even:
            d = gap / 2
            left = 0
            if k >= 2 and diff[k - 2] == d:
                left = leftRun[k - 2]
            right = 0
            if k + 1 <= n - 2 and diff[k + 1] == d:
                right = rightRun[k + 1]
            ans = max(ans, left + 3 + right)

        ans = max(ans, min(n, 2 + (k >= 1 ? leftRun[k - 1] : 0)))
        ans = max(ans, min(n, 2 + (k + 1 <= n - 2 ? rightRun[k + 1] : 0)))

    return min(ans, n)

Reimplementation Checklist

  • Use contiguous subarrays, not subsequences.
  • Track arithmetic lengths as element counts when returning, and as difference counts only inside diff-run helpers.
  • Cap every boundary-extension answer at n.
  • Require (nums[k+1] - nums[k-1]) to be even before bridging through changed index k.
  • For a bridge, inspect diff[k-2] on the left and diff[k+1] on the right, not the broken gaps adjacent to k.
  • Return at least 2; constraints have n >= 4, but defensive implementations often keep the small-n branch.

Wrong But Tempting

  • Solving longest arithmetic subsequence with hash maps. This problem is about subarrays, so that is too broad and too slow for the intended structure.
  • Trying every possible replacement value. Values are arbitrary integers, and the valid value is forced by adjacent elements whenever both sides are used.
  • Joining left and right runs whenever their differences match, without checking that the middle replacement can have the same integer difference.
  • Forgetting one-sided changes. Example 2 needs an endpoint-style extension to reach length 3.
  • Using floating-point halves for the bridge. Parity should be checked with integer arithmetic.

Accepted Algorithm Families

  • Difference-run bridge family: Python, Rust, C++, TypeScript, and several Java files compute equal runs on the adjacent difference array, then evaluate bridges with left + 3 + right. This is the clearest formulation.
  • Element-run prefix/suffix family: JavaScript and Java variants compute arithmetic subarray lengths ending at each index and starting at each index, plus their associated differences, then combine around the changed index.
  • Expanded case-check family: Some Java/Python solutions separately check full bridge, left-only extension, and right-only extension. The logic is equivalent to the compact difference-run method but more verbose.

Failure Patterns From Stats

The stats file records 7 failed submissions, all with status Wrong Answer. There are no recorded time-limit or memory-limit failures, which points to correctness details rather than asymptotic performance as the main risk.

  • Most likely wrong-answer source: joining across the changed element without the even-parity check for an integer replacement.
  • Second likely source: off-by-one errors from mixing difference-run lengths and element-run lengths.
  • Boundary changes are easy to miss: replacing the first or last value near a run can improve the answer by one.
  • The answer must never exceed n, especially when using formulas like bestRun + 2 over difference runs.
